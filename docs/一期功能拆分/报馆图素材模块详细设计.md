### 1.2 已确定边界

1. 标准方案读取灵通预先制作入库的三视图；结构不变时直接取对应资料。
2. 报馆图是施工/报馆参考素材，必须注明用途和适用范围，具体项目资料按实际要求确认。
3. 与图生图 mask、客户平面设计用墙面底图分开存储和展示，不能互相充当报馆图。
4. 客户支持预览、按原文件名逐张下载和下载全部；无资料显示“暂无素材”并隐藏下载按钮。
5. 主题调整不改模型和结构图纸；平台不从 AI 效果图自动推导施工图，不增加网页 CAD 编辑或自动报馆审批。

### 1.3 建议与待冻结口径

| 事项 | 本稿建议 |
|---|---|
| 三视图完整性 | 按已确认导出规范的视向覆盖检查，不以“文件数等于三”代替；允许一个文件多视向或同视向多张明细 |
| 文件格式 | 首版建议 PNG/JPEG/PDF；这是待样例验证的白名单，不将平面素材模块的“高清 PNG”直接套用到报馆图 |
| 整套下载 | 同一图纸修订的原始文件组成 ZIP，保留合法原文件名；不压缩重采样原图 |
| 变更生效 | 当前图纸的上传、替换、删除、元数据/排序变更使整套核验失效并同步下架；重新审核发布后恢复 |
| 后台接口缺口 | 复用通用资产上传/修改，补充 API-096 删除、API-097 后台预览/下载；不另建报馆图上传接口 |
| 资料权限 | 查看、原图下载、整包下载分别校验 Q07 授权；登录并不等于拥有全部资料 |

## 2. 客户端详细功能

### 2.1 C4-01 查看三视图

入口为方案详情“报馆图素材”弹窗，携带唯一 `schemeCode`。页头展示方案编号、用途、适用范围、复核日期及“下载全部”。内容使用文件卡片，展示名称、原文件名、视向标签、页数/像素信息及预览。

- API-011 返回当前已复核资料，前端不通过文件名猜方案或视向。
- 图片支持缩放、适应窗口；PDF 按页预览并标明页码。预览可以缩小，但必须与原件绑定，下载始终取原件。
- “三视图”不是固定三个卡片：卡片按后台 `sortOrder` 排序，同序用 assetId 稳定排序；每个文件的 `viewCodes` 可覆盖多个视向。
- 明示“施工/报馆参考；具体项目资料需按实际要求确认”，并展示维护人员填写的限制，如适用结构、尺寸和使用范围。
- 品牌/主题结果页仍指向原结构方案，提示“结构图纸沿用原方案，不代表已包含本次品牌画面”；不把新主题效果图混入图纸集合。
- 切换方案、关闭弹窗或退出登录后清除旧上下文；忽略已过时请求结果，避免串图。

| 状态 | 客户端行为 |
|---|---|
| 加载中 | 显示骨架屏，禁止下载 |
| 有权且有可用图纸 | 展示文件卡片及授权允许的下载操作 |
| 有权但无资料 | API-011 返回空集合，显示“暂无素材”，隐藏全部下载按钮 |
| 无查看权限 | 显示登录/授权提示，不显示文件名或缩略图，不伪装成无素材 |
| 方案已下架或资料复核失效 | 提示资料暂不可用；不继续展示旧缓存 |
| 预览失败 | 显示失败及重试；原文件确实可用且有下载权限时保留下载，不把缩略图失败等同原文件丢失 |
| 修订过期 | 刷新整套列表，提示资料已更新，不静默下载另一修订 |

### 2.2 C4-02 下载单张

每卡片提供下载按钮，调用 API-012，携带列表返回的 `revision`。服务端检查方案、图纸类型、当前集合成员及原文件就绪状态后返回附件流。

原文件名包含中文、空格时仍应正确下载。方案编号如 `TW66_BK_044_F&B` 保持原值，客户端仅对路径分段编码。下载鉴权失败时保留方案和弹窗回跳位置；重新登录后重新读取授权及修订，不重用过期文件地址。

### 2.3 C4-03 下载全部

调用 API-013，携带相同 `revision`，下载 `{方案编号}@报馆图素材.zip`（此 ZIP 名称为建议，不是原文既定命名）。包内只包含当前整套已复核图纸原件，不混入模型、清单、mask、平面素材或历史替换件。

- 打包期间按钮显示处理中，失败后允许重试；重复下载不产生新业务记录或扣费。
- 整套必须完整成功，缺一件或校验失败则整个请求失败，不生成“成功但缺图”的包。
- 文件名冲突在入库阶段阻断；ZIP 内文件名与客户单张下载名相同，不临时改名掩盖冲突。
- 超出已配置同步打包限制时给出明确错误和人工交接提示，不假装已排队生成；如样例证明需异步大包，应另行评审任务接口。

## 3. 管理后台详细功能

### 3.1 M4-01 图纸维护

在独立路由 `/assets/venue-materials` 完成，支持跨方案列表（API-098）、方案筛选及选择已有方案上传。方案详情只汇总并跳转；允许先创建/导入草稿，再分批补图纸。页头显示模型绑定、图纸修订、复核状态、视向缺失项及发布状态；文件表显示名称、原文件名、视向、大小、页数/分辨率、排序、来源、更新时间及操作。公共列表/上传归 W15，视向及模型绑定核验归 W09，详见[方案资产管理详细设计](方案资产管理详细设计.md)。

1. **上传**：API-040 使用 `type=drawing`；选择已确认导出规范、视向、用途、适用范围和当前模型。文件校验成功后才挂接，失败不修改当前集合。
2. **替换**：API-041 同一逻辑 assetId 上传新文件版本；先保存新对象，事务提交后切换引用，旧对象不覆盖。即使文件名一样也必须有新的版本及哈希。
3. **编辑/排序**：API-041 修改展示信息及 `sortOrder`。拖拽一次移动可只修改该项排序值，前端串行保存并使用最新修订，失败时刷新；不承诺多个独立 PATCH 原子批量成功。
4. **删除**：API-096 移除当前集合成员，明确显示会使资料重新待核验并下架。保留审计与历史项目引用，不以物理删除 S3 文件实现业务删除。
5. **预览/下载**：API-097 取指定不可变文件版本；未发布/待核验也可由有权后台人员检查，不复用客户端公开发布条件。
6. **完整性检查**：API-042 返回缺失视向、失效/不可读文件、重名、缺少用途、模型不匹配及未复核等阻断项。
7. **复核/发布**：API-043 的图纸复核阶段固定本次集合和模型；API-044 重新检查全部方案资料后发布。

后台删除、排序、预览、下载来自原始后台第五章，补入 M4-01；不能仅完成上传即宣称该功能完成。

### 3.2 图纸复核

机器校验“能否读取、是否齐全”，技术人员确认“是否与结构相符”。建议人工确认四项：

- 图纸与指定模型结构、编号一致；
- 规范要求的各视向覆盖完整，图中文字/尺寸可读；
- 用途、适用范围、尺寸和方向标注无明显矛盾；
- 来源和交付授权明确，符合本次交付范围。

API-043 建议增加 `stage=drawings`，携带 `expectedDrawingRevision`、`modelAssetVersionId`、`requestKey`、`decision`、四项确认及备注；通过时四项均须为 true，拒绝时填写原因。复核不等于场馆批准，也不自动发布方案。

## 4. 服务端一致性与文件交付

### 4.1 技术修订与状态

每方案维护图纸集合 `revision`，初始 0；这是防覆盖和固定引用的技术修订，不提供完整用户版本树。

| 状态 | 含义及变化 |
|---|---|
| absent | 当前集合为空；删除最后一个文件后进入此状态 |
| pending_review | 有文件但尚未复核，或文件/元数据/顺序/规范/模型绑定发生变化 |
| rejected | 当前集合被人工拒绝；编辑后返回 pending_review |
| verified | 针对固定集合、导出规范及模型版本的复核通过 |

所有成功变更和复核决定递增图纸 revision；失败/幂等重放不递增。客户端只有在方案可取用且集合 verified 时获取文件；有权方案的 absent 返回空集合，pending_review/rejected 返回资料暂不可用。若整体已下架，先按方案取用规则处理，而不是借空集合暴露草稿状态。

上传、替换、删除、编辑或绑定模型变化时，在同一数据库事务内锁定方案及图纸集合，校验预期修订、写快照、使图纸复核失效并下架。模型变化同时使清单核验失效，遵守清单模块规则。图纸自身修改不自动改变清单数量。仅改变主题选定效果不影响图纸核验。

API-043/044 与编辑共用同一锁定和最终校验顺序，避免“审核旧图、发布新图”；API-044 必须确认审核记录绑定的当前修订/模型仍有效。数据库事务中不执行文件上传、转码、ZIP 打包或外部 API。

### 4.2 并发和重复提交

- 图纸写入携带 `expectedDrawingRevision`；不匹配返回 409。多文件上传按文件串行确认修订，未全部成功前不允许通过完整性检查。
- API-040/041/096 图纸操作及 API-043 审核均携带 `requestKey`。唯一范围为操作者、操作和方案；同键同内容返回原结果，同键不同内容 409。
- 在完成身份/操作权限检查后，先查幂等记录，再比较修订。文件内容按服务端计算的哈希纳入请求摘要；不能仅以文件名判同一请求。
- 非当前成员、跨方案 assetId 或跨类型的文件版本一律拒绝，不接受客户端提交任意 storageKey。

### 4.3 文件校验与存储

- 先在临时对象区接收，再检测类型、扩展名与实际内容一致性、可解码性、大小、页数/像素总量及 SHA-256；通过后才能入库挂接。不得仅凭扩展名认定有效。
- 建议白名单 PNG/JPEG/PDF；格式、最小分辨率、图纸比例/单位及纸张规则须以设计部和 SU 样例冻结，不能通过自动放大宣称“高清”。
- PDF 预览生成受控栅格图，不在平台执行 PDF 附件、脚本或外链；原件需按约定的安全文件规则校验后才允许交付。预览失败与原件不可读分别记录。
- 原文件名要求为单一合法文件名，拒绝路径分隔符、路径穿越、控制字符及常见桌面系统不支持的名称。按规范化后不区分大小写检查整套重名；不静默改名，提示上传者修正源名。
- 以服务端生成的对象键保存；原文件名只用于展示和下载头，不拼接磁盘路径或对象键。预览衍生物与原件分别保存并固定关联。
- 原件不可变；业务删除只移除集合引用。无项目/审核引用的临时对象按保留策略回收，有历史引用的原件不得当孤儿清除。
- 建议初始限额：单文件 30 MiB、单套 200 MiB/30 个文件、PDF 100 页、单页图片 4000 万像素；全部为待样例压测确认的参数，不是业务已定上限；限制应同时覆盖请求、解码及打包资源。

### 4.4 预览和下载权限

API-011 不返回内部对象键；预览使用 API-012 的 `disposition=preview`，由服务端鉴权取受控衍生图，避免新增不受保护的缩略图入口。预览授权与原件下载授权分开；客户端 `capabilities` 仅用于 UI，服务端每次重验。后台 API-097 同理。

API-012/013/097 返回文件流，而非假定 JSON `{url}`。使用正确 Content-Type、中文文件名的 Content-Disposition、`Cache-Control: private, no-store`；原件 `attachment`，安全预览图 `inline`。不暴露容器内部 hostname，不直接提供长期公开 S3 URL。

单张在响应前固定不可变对象并复核当前授权/修订；整包先固定集合、检查所有原件、生成完整临时 ZIP，成功后再检查当前权限与修订，才开始发送。期间发生变更则丢弃结果并返回冲突。文件传输开始后无法撤回已发送内容，已开始的传输保持同一固定快照，不中途混入新文件。

缓存 ZIP 可按方案、图纸修订、文件哈希清单及打包规则版本复用，但每次响应仍重新授权；不能把缓存地址当作访问凭据。历史项目使用其固定资料快照和项目权限，不借当前方案下载接口绕过发布限制。

## 5. 逻辑数据模型

以下为建议实体及字段，不代表现有数据库表；复用方案和通用资产能力，避免复制一套文件系统。

| 实体 | 关键字段/约束 |
|---|---|
| scheme_drawing_sets | schemeId、revision、status、modelAssetVersionId、exportSpecVersion、reviewId；每方案一条当前集合 |
| drawing_set_snapshots | schemeId + revision 唯一；不可变成员版本、名称、视向、顺序、用途、范围、模型与规范快照 |
| scheme_assets / asset_versions | 逻辑 assetId、type=drawing、schemeId；不可变 versionId、objectKey、sha256、originalFilename、mediaType、byteSize、pixelSize/pageCount、previewState |
| drawing 元数据 | assetId、name、viewCodes、sortOrder、purpose、applicability；跟随集合快照保留 |
| scheme_reviews | 阶段、集合修订、模型版本、四项确认、决定、adminId、时间、requestKey |
| project_drawing_snapshot | projectId、schemeCode、drawingRevision、固定文件版本/哈希/元数据或 missing；不随当前图纸更新 |

`viewCodes` 来自冻结的 `exportSpecVersion`，例如平面/正立面/侧立面仅为待确认示例。必需视向、组合文件规则和可读性规则属于导出规范；当前规范定义可由 API-039 返回，不在一期增加通用规范编辑平台。客户端操作者引用 users，后台审核引用 admins。

## 6. 客户端接口契约

公共约定：路径 code 分段 URL 编码；修订为非负整数。业务 JSON 示例使用 `data` 包装作为建议，实际应与全局响应规范统一。401 未认证、403 无权限、404 不存在/不可见、409 修订或状态冲突、422 内容不合规、413 文件/包超限、503 存储暂不可用。细分原因建议使用 `error.reason`，这是待实现的扩展，不假定当前错误处理器已支持。

### 6.1 API-011 查看图纸集合

`GET /api/v1/client/schemes/{code}/drawings`

权限：方案可取用且拥有资料查看权。成功示例（文件信息仅作契约说明）：

```json
{
  "data": {
    "schemeCode": "TW66_BK_044_F&B",
    "revision": 7,
    "status": "verified",
    "reviewedAt": "2026-09-24T08:00:00Z",
    "capabilities": { "preview": true, "download": true },
    "items": [{
      "assetId": "drawing-1",
      "name": "平面图",
      "originalFilename": "平面图.pdf",
      "viewCodes": ["plan"],
      "sortOrder": 10,
      "mediaType": "application/pdf",
      "byteSize": 240000,
      "pageCount": 1,
      "previewState": "ready",
      "purpose": "施工/报馆参考",
      "applicability": "适用于本方案对应结构，具体项目按实际要求确认"
    }]
  }
}
```

示例仅展示一个文件，不表示完整规范只需要平面图。图片返回 pixelWidth/pixelHeight，PDF 返回 pageCount；无资料返回 `status=absent, items=[]`，仍有 revision。缺失内部复核细节不向无权客户端泄露。

### 6.2 API-012 预览或单张下载

`GET /api/v1/client/schemes/{code}/drawings/{assetId}/download`

| 参数 | 规则 |
|---|---|
| revision | 必填；等于 API-011 的当前图纸集合修订 |
| disposition | `attachment`（默认原件）或 `preview`（受控预览图） |
| page | preview 时 PDF 页码，默认 1；图片只允许 1；attachment 不接受 page |

返回原件附件流或指定页预览图。按 disposition 检查对应权限，均校验当前已复核集合和 assetId 归属；预览不存在返回 `PREVIEW_UNAVAILABLE`，修订过期返回 `DRAWING_REVISION_CONFLICT`。不因持有 assetId 允许读取已替换的旧版。

### 6.3 API-013 下载全部

`GET /api/v1/client/schemes/{code}/drawings/download?revision=7`

必填 revision；成功返回 `application/zip` 附件流。空集合返回 404 `DRAWINGS_NOT_FOUND`，复核失效返回 409 `DRAWINGS_NOT_READY`，打包中底层读取失败返回 503，超限返回 413；均不得返回空成功 ZIP。此固定路径应与 `{assetId}/download` 路由明确注册、验证无冲突。

## 7. 后台接口契约

以下扩展通用资产接口的 drawing 分支；其他类型保留各模块契约。所有写操作都检查方案数据范围和对应资产操作权限。

| API | 方法和完整路由 | 图纸输入与输出 |
|---|---|---|
| API-039 | GET `/api/v1/admin/schemes/{code}/assets` | `type=drawing` → drawingRevision、状态、模型版本、导出规范、当前文件版本及元数据、操作能力；不返回对象密钥 |
| API-040 | POST `/api/v1/admin/schemes/{code}/assets` | multipart：file、type=drawing、name、viewCodes、sortOrder、purpose、applicability、exportSpecVersion、modelAssetVersionId、expectedDrawingRevision、requestKey → assetId、assetVersionId、新 drawingRevision；规范和模型必须匹配当前集合，首次建立时固定 |
| API-041 | PATCH `/api/v1/admin/schemes/{code}/assets/{assetId}` | JSON 元数据，或 multipart 元数据与替换 file；均必填 expectedDrawingRevision、requestKey、changeReason → 当前文件版本及新修订。禁止改变 schemeId/type；修改集合导出规范时可带 exportSpecVersion，但必须校验全部成员元数据符合新规范 |
| API-096 | DELETE `/api/v1/admin/schemes/{code}/assets/{assetId}` | JSON：expectedDrawingRevision、requestKey、changeReason → removedAssetId、新 drawingRevision/状态；重复请求按 requestKey 幂等，不物理删除历史引用 |
| API-097 | GET `/api/v1/admin/schemes/{code}/assets/{assetId}/download` | 必填 assetVersionId，可选 disposition=attachment/preview、page（同 API-012）→ 受控文件流；可读获授权历史版本，不要求方案发布 |
| API-042 | GET `/api/v1/admin/schemes/{code}/readiness` | 额外返回 drawings 的 revision、status、requiredViews、coveredViews、missingViews、文件/模型错误；总体仍检查六类资产 |
| API-043 | POST `/api/v1/admin/schemes/{code}/reviews` | `stage=drawings`、expectedDrawingRevision、modelAssetVersionId、requestKey、decision=approved/rejected、四项确认、备注 → reviewId、新 drawingRevision、图纸状态 |
| API-044 | POST `/api/v1/admin/schemes/{code}/publish` | 沿用方案发布输入；重新检查当前模型、图纸、清单及整体审核，资料变化则拒绝 |

API-043 四项确认字段建议为 `checks.modelMatches / viewsComplete / applicabilityConfirmed / deliveryRightsConfirmed`。平面素材阶段的确认字段建议为 `checks.artworkMappingConfirmed / dimensionsVerified / deliveryRightsConfirmed`。核验记录同时保存输入快照修订与成功后的结果修订，避免核验自身递增导致刚核验即失效。

API-096/097 为此次新增的通用资产入口，本稿只定义 drawing 的可用分支；其他类型接入需按其模块定义失效与权限规则，不推断已全部支持。删除虽使用 JSON body，实现前必须验证前端 HTTP 客户端与网关完整转发。

## 8. 项目交接

### 8.1 报价与历史项目

API-019 `POST /api/v1/client/quote-requests` 建议增加可选 `drawingRevision`，与 `bomRevision`、最终效果引用并存。

- 显式指定修订时，报价事务校验该修订仍可取用，失效则 409；不偷偷替换客户已看过的资料。
- 未传时固定提交瞬间可用图纸的不可变引用；若业务允许缺图人工承接，则记录 `drawingsStatus=missing` 和待补资料，不伪造核验通过。
- 报价请求不能借快照扩大资料权限；整合清单/主题/图纸校验在同一项目提交事务完成，任一明确指定引用冲突则整体失败。
- API-023/064 项目详情展示固定图纸元数据和可用性；后台取文件走 API-097，并检查项目数据范围。伙伴历史文件交付建议 API-023 增加 `drawingAssetVersionId + disposition + page` 文件响应模式，必须属于该项目快照且具备项目资料权限，不把旧资料塞回当前方案下载入口。
- 历史项目保留已交接原件；发现旧图有误时追加标识和人工处理记录，不修改原快照、也不把保留解释成“旧图仍适用”。引用保存期限与纠错通知流程待确认。

## 9. 验收场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| D01 | 标准资料查看 | 按编号返回已复核文件，名称/视向/用途/范围准确；不展示 mask 或平面素材 |
| D02 | 无图/无权/失效 | 三类状态可区分；无图隐藏按钮，无权不泄露缩略图，失效不使用旧缓存 |
| D03 | 单张与全部下载 | 原件哈希一致，中文原文件名正确，ZIP 只含当前整套图纸 |
| D04 | 多页/组合视图 | 一个 PDF 可覆盖多个视向；视向缺失不能用凑足三个文件通过 |
| D05 | 预览授权 | 有查看无下载的账户能看预览，不能切换 disposition 取原件；页码越界失败 |
| D06 | 非法文件/文件名 | 伪后缀、不可读、重名、穿越、超限及不支持格式被拒绝；当前集合不受失败上传影响 |
| D07 | 修改/替换/删除 | 复核失效与下架原子完成；最后一件删除为空；旧项目文件仍有固定引用 |
| D08 | 并发和幂等 | 相同键重发不重复上传挂接/审批；异内容同键与旧修订返回冲突 |
| D09 | 发布竞态 | 审核与编辑并发不能将未经复核的新图发布；模型变更使对应图纸和清单核验失效 |
| D10 | 整包失败 | 任一原件缺失、读取失败或打包中发生修改时无缺图成功包，开始响应前给明确错误 |
| D11 | 跨方案/跨账户 | 替换 assetId、文件版本或 projectId 均不能访问无权资料 |
| D15 | 主题与图纸 | 换主题不改图纸修订，不把四面 AI 素材放进结构图集合 |
| D16 | 报价固定引用 | 提交时固定所选修订，过期显式引用被拒绝；新图不会覆盖历史项目 |
| D17 | 文件交付和回收 | 无内部地址/长期公共链接，缓存响应重新鉴权，有项目引用的旧件不被清理 |

实施验证先准备真实标准方案、多视向 PDF 和中文同名文件样例；验证原件哈希、视向覆盖、权限、事务竞态及失败注入，再进行浏览器下载和大包资源测试。本稿交付仅做文档一致性检查，不以此替代上述实现验收。
