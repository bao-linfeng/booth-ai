# 账号登录模块详细功能与接口方案

**版本：** v0.1（开发评审稿）  
**范围：** 客户端 C7-01～C7-06、后台 M7-01、SU 身份接入；已有 API-026/028/090，拟开发 API-029/030/082～084/087～089。  
**状态：** 需求和接口建议，不代表已实现。已有账户接口字段依据提供的地址和截图整理，尚未完成联调。

## 1. 依据与业务边界

- [一期需求书](../灵通_AI_展台方案平台_第一期需求书_v1.0.md)、[开发需求规格说明书](../灵通_AI_展台方案平台_开发需求规格说明书_v1.0.md)中的账户、双入口与权限需求。
- [客户端功能需求](客户端功能需求.md)、[管理后台功能需求](管理后台功能需求.md)、[服务端接口路由](服务端接口路由.md)、[本地用户信息同步](本地用户信息同步.md)、[本地管理员信息同步](本地管理员信息同步.md)。
- 最新接入约定优先于原需求中的本地注册设计：注册由官网完成，密码认证复用灵通现有接口；本平台分别维护 `users`（客户端/SU）和 `admins`（后台）。

一期不建设本地密码库、注册表单、密码重置、订阅套餐、充值或支付接口。统一账户负责身份认证；本平台负责核验该身份、同步资料、建立平台访问上下文，并按业务资源执行授权。登录成功不自动获得伙伴、后台或 SU 操作权限；也不自动触发收费生成。

## 2. 功能与页面流程

| 编号 | 功能 | 完成行为 |
|---|---|---|
| C7-01 | 官网注册 | 打开 `https://lingtong.net.cn/register`；注册完成后由用户回到平台登录，不假定官网支持回跳参数。 |
| C7-02 | 客户端登录 | 使用统一账户凭据登录；平台服务端完成身份核验及本地 `users` 同步后，才建立可用会话。支持邮箱作为 `username` 的能力待外部接口联调。 |
| C7-03 | 登录墙 | 免费浏览、匹配、查看公开效果图免登录；进入 AI 换主题前要求登录；回到原方案和操作入口。 |
| C7-04 | SU 静默登录 | SU 插件打开网页时 URL 携带统一认证 token，网页用 token 验证身份并建立本地会话；token 无效时回到普通登录。 |
| C7-05 | 资料与积分 | 本地白名单资料用于显示头像和身份；积分单独从统一账本读取，生成后刷新。余额不足阻止收费任务，不出现未接入的支付入口。 |
| C7-06 | 退出 | 失效当前平台会话、清理本端状态；公开页面仍可访问。 |
| M7-01 | 后台登录 | 复用 `site=admin` 认证；独立核验管理员资格，同步 `admins` 并加载本平台权限。 |

### 2.1 客户端登录与回跳

1. 用户在免费方案详情点击“AI 换主题”。已登录且本平台会话有效时进入主题编辑页；否则打开登录页。
2. 前端保留站内目标路径、`schemeCode` 和已选原图引用；校验目标是本站允许的相对路径，防止开放重定向。报价表单等敏感草稿不写进 URL。
3. 登录表单提交至已有客户端账户入口，确认业务成功标记并取得凭据；随后调用平台同步接口。平台同步失败时不能显示为已完成平台登录，保留可重试上下文。
4. 同步成功后回到原方案及主题编辑页；重新获取当前方案、能力与积分，不自动创建任务或扣费。
5. 登录态失效时保留不敏感的页面上下文；重新登录后重新确认费用与业务输入，不自动重放写请求。

### 2.2 后台及 SU

- 后台使用独立登录入口及平台会话；客户端身份和 `users` 记录不能替代 `admins` 资格。后台登录仅更新 `admins`，不写 `users`。
- SU 插件以其现有有效身份进入平台时，同步至客户端共用的 `users` 记录；插件操作权限由服务端单独校验。网页仍使用客户端业务接口，不取得后台权限。
- SU 到网页的凭据交接使用统一 token：SU 打开网页时 URL 携带已有统一认证 token，网页端调接口验证 token 并获取用户信息；token 不等于平台业务操作权限，验证后仍需同步本地 users 记录并建立平台会话。

## 3. 已有统一账户接口

以下 URL、字段和方法以现有文档为基础，方法及协议须联调确认。浏览器跨域、凭据传递头、有效期和失败结构尚未验证。

| 编号 | 接口 | 调用与返回 |
|---|---|---|
| API-026 | `POST https://api.lingtong.net.cn/api/auth/login?site=client&lang=zh` | 提交 `username`、`password`；成功时读取 `success`、`code`、`data.JWT`、`data.data.id`、`data.data.username`。邮箱登录是否被接受待确认。 |
| API-090 | `POST https://api.lingtong.net.cn/api/auth/login?site=admin` | 后台账户入口；验证码字段 `captcha` 的含义与必填规则待确认，不可固定传值以绕过验证。 |
| API-028 | `GET https://api.lingtong.net.cn/api/user/username/{username}` | 由服务端使用已验证身份确定的 username 查询；路径段编码，核对详情 `data.id` 与已验证 ID 一致，仅抽取业务白名单。 |

登录响应 `data.JWT` 的字段大小写按现有响应读取；不能仅凭 HTTP 200 判定成功。用户详情可能包含密码散列，任何平台响应、日志或数据库均不得保留或转发。用户详情中没有明确的积分余额字段，`isVip` 也不代表积分。

## 4. 平台接口契约

以下为拟开发接口，沿用[服务端接口路由](服务端接口路由.md)中的编号。受保护端点均根据服务端验证的当前身份确定用户，不从请求体中的用户 ID 判定归属。平台会话的载体、外部凭据所在请求头及错误码细节待协议冻结。

| 编号 | 方法及路径 | 输入与成功输出 | 校验和主要失败 |
|---|---|---|---|
| API-087 | `POST /api/v1/client/auth/sync` | 输入统一登录凭据；返回本地 `userId`、白名单资料、同步时间和本端会话结果。 | 验证外部身份及账户启用状态；获取详情并核对 ID；原子 upsert `users`。凭据无效拒绝，外部详情/写库失败不建立成功会话。 |
| API-088 | `POST /api/v1/admin/auth/sync` | 输入后台统一登录凭据；返回 `adminId`、白名单资料和本端会话结果。 | 必须验证管理员资格及本平台授权，仅 upsert `admins`；不能仅据 URL、前端角色或已有 `users` 记录放行。 |
| API-089 | `POST /api/v1/su/auth/sync` | 输入 SU 统一认证 token；返回同一 `users.id` 和同步结果。 | 服务端验证 token、获取用户信息并原子 upsert `users`，不创建第二套用户或独立积分。 |
| API-082 | `GET /api/v1/admin/me` | 返回当前 `adminId`、本平台后台权限、数据与字段范围。 | 管理员停用、资格撤销或会话失效时拒绝；不把外部角色快照直接当授权。 |
| API-084 | `GET /api/v1/su/me` | 返回当前统一身份和本平台允许的 SU 操作。 | 按服务端身份及 SU 资格判定。 |
| API-029/085 | `GET /api/v1/client/me/credits`、`GET /api/v1/su/me/credits` | 分别返回当前用户的同一统一账本可用余额。 | 不接收查询其他用户的 ID；生成扣费由任务接口完成，不开放客户端自扣积分接口。 |
| API-030/083 | `POST /api/v1/client/auth/logout`、`POST /api/v1/admin/auth/logout` | 失效当前平台会话，返回退出结果。 | 不承诺撤销外部统一账户 JWT；另一端会话不受影响。 |

**建议补充，尚未列入现有接口表：** `GET /api/v1/client/me`。页面刷新后由服务端返回当前客户端 `userId`、白名单资料和用户侧授权，或返回未认证结果。否则仅以本地存储的 JWT 或资料对象判断“已登录”，无法确认账户和平台会话是否仍有效。采用后需更新接口路由表和接口总数。

建议响应只包含本地 ID、必要资料、权限上下文及同步状态；不返回完整外部详情、密码散列、原始角色权限对象或外部 JWT。建议按项目统一错误格式区分无效凭据（401）、已验证但没有该端权限（403）、同步依赖失败（可重试的服务端错误）；最终错误码在实现时冻结。

## 5. 身份、会话与权限

1. **身份核验前提：** 确认外部 JWT 的验签材料、签发方、受众、有效期及撤销方式，或取得统一账户提供的可信验票/当前身份接口。仅解码 JWT，或用浏览器给出的 username 查询详情，都不能证明请求者身份。
2. **同步与会话顺序：** 验证凭据与端点资格 → 获取详情并核对身份 → 更新本地记录 → 确认授权 → 建立本端可用会话。外部登录成功但本地同步失败时，不进入平台受限功能。SU 网页 token 验证同样执行该同步逻辑（API-089），前端不再重复调用 API-087。
3. **平台会话建议：** 与外部 JWT 分离，采用服务端可失效的会话；网页可选 `HttpOnly`、`Secure` Cookie，但必须同时确认 SameSite、站点跨域、CSRF、防会话固定及后台/客户端 Cookie 隔离方式。此处是技术建议，不能在外部登录与部署域名协议未确认时宣称已定稿。
4. **权限强制点：** 公开匹配无需登录；换主题、本人任务、积分及本人项目查询按 `users.id` 校验；后台项目处理按 `admins.id` 的操作、数据和字段范围校验。用户类型只用于入口提示，不替代业务资源授权。前端按钮可隐藏，但服务端仍要逐接口授权。
5. **停用与撤权：** 会话过期、退出、统一账户停用或本平台授权撤销后，受限接口必须拒绝访问；会话有效期内如何及时发现统一账户变更，取决于外部验票和撤销能力，需联调确定。后台不能仅依赖登录时缓存的角色长期放行。

## 6. 本地数据与安全

- `users.external_user_id`、`admins.external_user_id` 在各自表中唯一。客户端/SU 关联 `users.id`；后台审核、操作审计关联 `admins.id`。同一外部 ID 可以同时存在于两表，两表主键不得混用。
- 每次新登录按外部 ID 原子 upsert 白名单资料，记录登录时间及来源；外部详情缺失可选字段时保留旧值，明确给出空值时清空可空字段。外部停用状态须同步并阻止可用会话。
- 资料同步不覆盖本平台后台权限、积分或既有项目联系方式快照；用户类型按已确认的来源同步或由后台维护，不等同于本平台后台权限。
- 不持久化密码、密码散列、外部 JWT 或完整用户响应到 `users/admins`。日志和错误响应不输出凭据；URL 中的 token 不得在访问日志、浏览器历史和第三方资源请求中泄露。

## 7. 现状与实施顺序

当前服务端认证路由仍是占位，数据库只存在基础任务迁移，尚无 `users`、`admins` 或平台会话实现。客户端目前在外部登录成功后立即把 JWT 和完整详情保存到 `localStorage`，详情读取失败仍放行；请求层预设外部和平台接口都接受 `Bearer`，但协议未确认。管理后台仍沿用模板的 `/auth/login`、`/auth/refresh` 等接口，尚未对接灵通后台登录。

建议按以下顺序实施：

1. 联调并冻结外部身份验证、登录/详情请求协议、管理员资格及 SU 凭据接入方式；没有可信服务端验证方式时不开放 sync 接口。
2. 新增迁移和权限初始化配置，落地 `users`、`admins` 及选定的会话机制；已执行的迁移文件只追加、不修改。
3. 实现各端 sync、`me`、退出和服务端权限校验，覆盖跨端隔离与停用/撤权。
4. 接入客户端登录墙及回跳、后台登录和 SU token 登录，最后联通统一积分读取与收费业务。
