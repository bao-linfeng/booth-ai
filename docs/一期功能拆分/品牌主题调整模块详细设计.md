### 1.2 已确定的业务边界

1. 在选定结构方案的一张原始效果图上，修改行业、风格、品牌色及品牌关键词对应的视觉内容；只允许修改预制 mask 区域。
2. 一个生成任务对应一个视角，产出 1～4 张候选图；不是同时重绘三张视角，也不保证不同任务的多视角品牌元素一致。
3. 原结构编号、SKP、材料数量、报馆图保持关联原方案；生成图不作为结构变更或材料计算依据。
4. 登录后方可生成，网页与 SU 使用同一账户和积分账本；免费浏览和原图查看仍免登录。
5. 用户选定一张最终效果后，平面素材生成与报价携带该效果引用；四面正交图是独立任务，不随主题生成自动启动。
6. 失败保留原图，可继续查看原方案或申请报价。新主题是用户私有结果，不自动进入公共方案库。
7. 一期采用外部图像服务，不训练模型、不提供网页结构编辑器或蒙版绘制工具。

### 1.3 本稿建议的落地口径

| 事项 | 建议 |
|---|---|
| 输入 | 行业、风格各单选；品牌色最多 3 个；关键词短文本。与 AI 智选的多选偏好区分 |
| 生成份数 | 用户选择 1～4 张，受当前能力和收费规则约束，默认 1 张 |
| 基础图 | 仅从当前方案已核验原图选择；不把上一次生成图作为下一次结构输入 |
| 品牌素材 | 本期输入色值和关键词；LOGO、产品图上传尚无明确客户端契约，列为评审项，不推断已支持 |
| 积分 | 提交前明示预计消耗；受理时预占，按成功交付图数结算，失败部分释放；缓存复用免费 |
| 缓存 | 仅同一用户、相同完整输入及资产/配置快照复用；“重新生成”明确绕过缓存并告知费用 |
| 最终效果 | 选择保存在任务内；跨模块传任务 ID、结果 ID、选择修订号；不维护账户全局唯一“当前方案” |

单图费用、允许数量、并发配额、保留期限等不使用虚构业务数值。下文字段长度、轮询间隔属于建议技术参数。

## 2. 客户端详细功能

### 2.1 页面与流程

建议页面：`/schemes/:code/theme`（编辑）、`/theme-jobs/:jobId`（任务与结果）；实际路由遵循前端项目命名。

```text
方案详情 → AI 换主题 → 登录/同步本地用户 → 选择原图与填写要求
        → 获取可用能力和费用 → 确认生成 → 创建任务 → 查询状态
        → 对比原图和候选图 → 保存最终效果 → 平面素材 / 获取报价
```

- 从详情保留 `schemeCode`、`sourceAssetId` 和合法站内返回路径；登录完成回到编辑页，不自动提交付费任务。
- 页面顶部展示方案编号、头像、可用积分；费用由 API-092 返回，余额由 API-029 返回，不根据用户详情中的 VIP/折扣字段推算。
- 左侧/移动端上方为原图及可改区域开关，右侧/下方为参数表单。原图可切换，但必须重新加载相应 mask 能力。
- 候选图切换、前后滑动或并排对比均使用同一个原图快照。手机保留清晰的“选为最终效果”和“继续使用原方案”入口。

### 2.2 输入与校验（C2-01）

| 字段 | 控件 / 规则 | 服务端校验 |
|---|---|---|
| schemeCode | 从详情带入，显示唯一编号 | 已发布且当前允许新生成；路径中的特殊字符正确编码 |
| sourceAssetId | 从本方案原效果图中单选 | 必须属于本方案，存在有效、审核通过的对应 mask |
| industryId | 单选，默认方案行业，用户可改 | 字典启用且当前模板/模型支持该组合 |
| styleId | 单选，默认方案风格，用户可改 | 同上；缺失默认值时要求用户选择 |
| brandColors | 色板及 HEX 输入，0～3 个 | `#RRGGBB`，统一大写、去重，保留主次顺序 |
| brandKeywords | 建议不超过 200 个 Unicode 字符 | 去首尾空白，拒绝控制字符；按变量作为内容处理 |
| requestedCount | 默认 1，支持范围由能力接口给出 | 整数 1～4，并且被当前模型能力及费率覆盖 |
| cacheMode | 默认 `reuse`；“重新生成”设 `refresh` | 只能取这两个值；客户端不能指定缓存对象 |

行业、风格必填，品牌色和关键词可空；颜色提示为视觉参考，不承诺物理印刷色差或品牌文字逐字准确。用户无需上传或选择任意 mask URL，可改区域由方案资产决定。若要求“加一面墙、改变层高、扩大展位”，提示去选择其他结构或交给授权伙伴，不把结构变更承诺为换主题能力。

### 2.3 提交与状态（C2-02、C2-05）

1. 点击生成前展示“生成数量、预计积分、缓存/失败处理规则”，由服务端返回可确认的 `offerId`。
2. 用户确认时生成 `requestKey`；网络重发、响应丢失、同一提交按钮连击使用同一键和同一请求体。
3. 收到任务后跳转任务页；建议按服务端 `pollAfterMs` 轮询，默认 2 秒、长等待退避到 5 秒，页面隐藏暂停、恢复后补查。
4. 刷新依靠 URL 的 `jobId` 恢复。创建响应丢失时保留原请求快照并重发 API-006；不生成新键“查询结果”。
5. 建议受理后按钮禁用，显示排队、生成、校验保存、结算中等真实阶段；上游没有进度时不展示虚构百分比。
6. 查询网络失败不等于任务失败；任务仍在处理中时“重新生成”不可作为补救。只有明确终态后，主动新生成才使用新键。
7. 余额不足保留表单，展示差额；登录过期恢复登录后查询原任务，不重新扣费。账户切换清理旧账户草稿和结果缓存。
8. 排队慢/超过 30 秒显示仍在处理及可离开提示，不因前端计时直接认定失败或退款。

### 2.4 结果与选定（C2-03、C2-04）

- 展示通过校验的 1～4 张图、实际产出数量、原图、任务状态和费用状态；失败图不充数，原图不伪装为生成图。
- 只在任务终态且至少有一张可用结果时允许选定；多张中只有一张为最终效果。
- 保存成功前不得跳转下游。并发标签页选择使用 `expectedRevision`，冲突时重新读取，不静默覆盖。
- 用户改变选择后，旧四面素材和已提交报价仍绑定旧结果；新入口携带新结果，不能显示旧素材为新主题产物。
- “继续使用原方案”进入不带主题引用的后续流程，不需要把原图写成生成结果。
- 已选结果重新打开时回显；后续任务不能覆盖其他任务内的选择，也不自动修改已经创建的项目。
- 下载权限继承资料授权规则。候选预览与效果选择不等同于授予 SKP、高清素材或全部项目资料权限。

### 2.5 客户端状态矩阵

| 情况 | 展示和动作 |
|---|---|
| 原图未配 mask / mask 待复核 | 说明该视角暂不支持，切换可用视角；禁用生成 |
| 无模板或无可用模型 | 保留要求、原图，提示暂不可生成 |
| 费率/资产已变动 | 重新获取能力和报价，用户重新确认后新建请求 |
| 排队/运行/结算中 | 轮询原任务，可回原方案；不允许用新键盲目重试 |
| 全部成功 | 对比、选定、进入平面素材或报价 |
| 部分成功 | 展示可用图和实际结算；选定或主动重新生成 |
| 全部失败 | 原图、稳定失败提示、积分释放状态、稍后重试 |
| 任务不存在/无权 | 统一不可访问提示，不暴露他人任务信息 |
| 预览链接过期 | 重新查询原任务取得新链接，不重新生成 |

## 3. 管理后台详细功能

### 3.1 蒙版维护（M2-01）

入口为独立蒙版管理页 `/assets/masks`，支持跨方案筛选（API-098）、选择已有方案上传及同方案效果图配对，复用 API-039～043。方案详情仅汇总并跳转；允许先创建/导入草稿，再补传蒙版。公共页面及上传能力归 W15，配对叠加和对齐核验归 W07，详见[方案资产管理详细设计](方案资产管理详细设计.md)。

1. 展示三张原效果图及各自当前 mask，显示分辨率、文件名、修订号、审核状态和缺失原因。
2. 上传建议采用无损 PNG；解码后验证实际格式、尺寸、像素上限及文件大小，不能只信扩展名。
3. 蒙版与原图宽高一致、方向一致、逐像素对齐；品红 `#FF00FF` 标记可编辑区域。禁止自动拉伸“修复”不一致。
4. 建议采用精确品红像素形成二值区域，拒绝空区域及整图区域；近品红边缘告警并要求人工检查，不悄悄扩大可改区域。
5. 原图/蒙版/叠加三种预览，可缩放检查边缘；审核者确认结构框架、开口、支撑件、地面及植物等不可改内容未误入可改区域。
6. 自动检查只确认文件性质和像素规则；人工确认区域语义及对齐。正式可用状态绑定原图内容哈希、mask 内容哈希及审核记录。
7. 替换原图使对应 mask 审核失效；替换 mask 只影响后续新任务。已受理任务固定引用旧资产，不读“当前最新文件”。
8. 新资产采用不可变对象键；没有完成复核前禁用受影响视角新生成，方案重新发布条件沿用 M1。

### 3.2 提示词模板（M2-02）

列表按用途、行业、风格、模型配置、启用状态筛选。编辑字段：用途 `theme` / `artwork`、行业 ID、风格 ID、模型配置 ID、模板正文、启用状态、修订号。

- 同一用途×行业×风格×模型配置最多一个启用模板；冲突返回 409。
- 变量白名单建议仅 `brandColors`、`brandKeywords`；行业/风格来自模板关联字典，不允许执行表达式或任意模板代码。
- 系统保护指令由服务端管理，运营编辑不能移除“仅修改蒙版内视觉、保持结构及相机”约束；保护指令也不能取代结果处理。
- 后台编辑时即时预览固定样例替换和长度检查，不触发付费生成。提交前按实际变量展开再校验。
- 原规格中的“≤75 字”作为候选供应商限制保留，需按最终模型验证计数单位与实际限制；超长明确拒绝并引导精简，不截断品牌词或保护约束。
- 主备模型分别具有合规模板；缺一项不能声明该行业×风格组合可主备切换。
- 停用影响新任务；任务保存模板正文和修订快照，不因后续编辑改变结果追溯。这里的修订号用于并发/追溯，不扩成用户版本管理。

### 3.3 模型与主备配置（补充 M2-04）

原后台开发需求包含此功能，现有拆分遗漏；本稿新增 API-093～095。

| 配置项 | 规则 |
|---|---|
| provider / model | 从服务端已实现且验证过的适配器清单选择，不是任意 URL 或脚本 |
| 用途和角色 | `theme` / `artwork`；主用/备用，按用途原子保存路由配置 |
| 状态 | 停用、启用；至少一个可用主模型才开放该用途 |
| 能力 | 支持 mask、尺寸、张数、提示词长度、查询/幂等能力；为已验证只读元数据 |
| 模型凭据 | 管理后台录入模型 API Key，服务端加密写入数据库；仅返回是否配置，不向浏览器回传密钥 |
| 执行参数 | 经验证范围内的超时、并发和重试上限；不得把候选值当线上实测能力 |
| 变更说明 | 必填，记录 admins.id、变更前后摘要、时间和修订号 |

建议 API 域名及真实凭据由部署配置管理，后台管理模型选择、受限运行参数和凭据引用。若业务要求在后台录入真实密钥，需要另行确定密钥存储及轮换方案；本期不提供明文密钥读取接口。

主备启用前，同一批原图、mask、品牌输入执行技术验收，记录边界、结构保持、品牌表现、速度、费用及失败恢复结果。未通过验收的模型不能仅因填写名称就启用。

### 3.4 任务查询（M2-03）

- 列表支持任务 ID、用户、方案编号、用途、状态、模型、创建时间、费用状态筛选，分页显示实际成功数/请求数、耗时。
- 详情包含输入快照、原图/mask、模板及模型修订、分次调用记录、结果校验、错误码、积分操作号、选择结果和审计。
- 权限分为模板编辑、蒙版编辑/审核、模型配置、任务读取、私有素材读取、积分流水读取；后端逐项控制，私有图片访问记审计。
- 后台可以定位失败和对账问题；本稿不增加“一键代用户付费重试”或直接改余额功能。任务重试由用户明确发起；系统恢复走原操作号。
- 服务密钥、登录凭证、提供商原始敏感报错不进入页面、响应和日志。

## 4. 服务端执行与生成质量

### 4.1 模块职责

使用仓库现有 API/Worker 双进程、PostgreSQL、Outbox、队列和 S3。HTTP controller 只负责鉴权、Schema 校验和响应；服务层完成资产/模板选择、业务幂等、积分协调和状态流转；Worker 完成调用、查询、下载校验和结果落库。

当前仓库仅有基础任务能力，以下是待实现业务设计；不直接将 `system.echo` 当作生成任务。

### 4.2 正常处理链路

1. API-092 校验视角、模板及模型可用性，生成短期 `offerId`，绑定用户、规范化输入、资产/模板/费率修订及预计最高积分。
2. API-006 首先按本人和 requestKey 查重。同键同请求返回原任务，即使 offer 已过期也不创建新任务；同键异请求冲突。
3. 新请求校验 offer 未过期、输入匹配、资产仍允许新生成；查询用户内缓存。缓存命中直接创建可追溯的成功任务引用，无模型调用及新扣费。
4. 非缓存请求保存任务、积分预占操作及后续分发事件。完成预占后才进入可执行队列；余额不足不调用模型。
5. Worker 取得执行租约，读取不可变输入快照，保存调用意图和提供商幂等标识，再发起外部请求；不持有数据库锁等待网络。
6. 若返回异步 ID，保存并查询原调用；取得结果后下载到受控存储，验证、合成、持久化有效结果，再触发积分结算。
7. 积分状态确认后置成功/部分成功/失败终态；API-007 返回结果和可续期的授权预览链接。

### 4.3 蒙版转换与质量边界

- 资产库品红 mask 是业务标准；提供商可能要求二值、alpha 或其他编码，适配器负责转换，禁止假定所有模型支持同一 `mask_color` 参数。
- 候选结果必须可解码、尺寸及视角满足输入约束，无效或空图视为失败；未批准的裁切、缩放不能强行对齐。
- 建议最终交付图按二值 mask 合成：区域内用生成结果，区域外用原始解码像素，并保存无损 PNG；验收比较解码像素而非压缩文件字节。不要在 mask 外羽化导致越界。
- 该合成保证区域外保持原图，**不能自动保证区域内没有新增虚假构件**。mask 制作必须排除结构元素，并通过固定样本验证结构观感和边界接缝；发现结构幻觉的模型/模板不得上线该组合。
- 原图中的品牌文字和 Logo 可能生成失真；当前能力仅作效果参考，后续平面素材仍需编辑复核，不承诺印刷级准确。

### 4.4 主备、重试与不确定结果

| 场景 | 处理 |
|---|---|
| 调用前连接失败且可确定未受理 | 在预算和重试上限内重试或切换已验证备用 |
| 上游明确终态失败 | 记录尝试，再按配置决定备用；一个业务任务最多结算一次 |
| 请求超时，不知道是否受理 | 标记该 attempt 为 `unknown`，优先按幂等标识/请求 ID 查询；不能直接双源并发重试 |
| 已返回上游任务 ID | 持续查询原任务，不再次提交同一生成 |
| Worker 重启/队列重复投递 | 检查业务状态、租约与 attempt，恢复查询/存储/结算，不盲目重新生成 |
| 上游不支持查询或幂等 | 不确定调用禁止自动重发，进入限时核对；截止后释放用户预占并终结，晚到结果隔离，不再扣费 |
| 下载/入库暂时失败 | 先恢复原结果下载/保存，不重新调用模型；无法交付的图不计成功 |
| 结算服务暂不可用 | 状态保留 `settling`、展示待结算，不重跑模型；用原操作号补偿重试 |

提供商费用与用户积分分账记录。主备多次尝试产生的服务成本不意味着用户重复扣费。原文供应商名和 75 字限制均须技术联调确认，本稿未在线核实这些候选 API。

## 5. 任务、积分与缓存

### 5.1 任务状态

| status | 含义 | 可选择结果 |
|---|---|---|
| pending | 已受理，积分确认或分发准备中 | 否 |
| queued | 可执行，等待 Worker | 否 |
| running | 调用/查询/结果校验中 | 否 |
| settling | 交付数量已确定，积分结算或释放待确认 | 否 |
| succeeded | 全部请求图可用且积分处理完成；也包括免费缓存命中 | 是 |
| partially_succeeded | 仅部分图可用，按建议规则结算成功部分 | 是 |
| failed | 无可用生成图，积分处理完成 | 否 |

典型流转：`pending → queued → running → settling → 终态`；预占被拒绝可 `pending → failed`；缓存可直接 `succeeded`。终态不可被晚到通知覆盖。`phase` 补充 `credit_reserving / provider_submitting / provider_polling / validating / credit_settling`，不替代状态。

### 5.2 统一积分边界（Q09 建议方案）

积分账本为本系统自建 PostgreSQL 账本。API-029/API-085 始终读取同一数据库余额；预占、结算、释放通过本地 `credit_reservations` 表原子完成，不使用平台缓存余额直接扣费。

- 费率快照中保存单图整数积分 `unitCredits`；请求 n 张预占 `n × unitCredits`，成功交付 k 张扣 `k × unitCredits`，释放 `(n-k) × unitCredits`。
- 用户点击选择不会另收费；未选结果也已产生生成费用。所有图失败、调用前取消受理、无法保存交付时释放全部预占。
- 同一 requestKey 重发无额外费用；缓存 `reuse` 命中免费；`refresh` 作为新生成按展示规则收费。
- 余额校验和预占必须由本地积分账本原子完成，防止 SU 和网页同时消费超额。前端余额只用于提示。
- 每任务预占、扣除、释放分别使用稳定操作 ID，`credit_reservations` 必须支持幂等与操作结果查询；业务数据库记录状态及对账结果。
- 账本在同一 PostgreSQL 数据库内，任务、预占、Outbox 在同一事务完成；预占成功后写入 queued 和生成 Outbox。
- 本地操作超时通过原操作 ID 查证；补偿释放也用固定 ID。定期扫描未完成操作，完成结算或释放；不通过重复扣款推测状态。

### 5.3 缓存规则

缓存指纹至少包含：用户 ID、方案/原图/mask 内容哈希、行业/风格、规范化颜色及关键词、请求张数、模板快照哈希、模型配置修订、合成规则修订。

- 只复用完整成功、资产仍存在且当前用户有访问权的结果；部分成功和失败不作为完整缓存。
- TTL 与用户素材保留期在评审时确认。缓存过期只是不能复用，不能立即删除已有报价或素材任务引用的文件。
- URL 不是缓存值；缓存保存资产 ID，每次访问重新鉴权和签发短期链接。
- 主备实际使用的模型记入结果来源，缓存校验该模型仍被当前路由允许。模型被紧急停用后不得通过缓存继续返回其禁用产物。
- 同参但不同 requestKey 表示不同用户操作；缓存尚未形成时可产生不同任务，受并发配额限制。若界面意图为重发，必须复用原键。

## 6. 数据设计与一致性

沿用 users、admins、方案和资产模型；以下为逻辑实体，落地时与既有表合并，不重复建立账户和公共方案库。

| 实体 | 核心字段 / 约束 |
|---|---|
| theme_jobs | id、user_id、scheme_id/code_snapshot、source_asset_id、mask_asset_id、输入与配置快照、request_key、request_hash、offer_id、status、phase、requested_count、usable_count、selected_result_id、selection_revision、时间、deadline_at |
| generation_results | id、job_id、ordinal、asset_id、来源 attempt、质量检查摘要；同任务 ordinal 唯一；asset 不可变 |
| generation_attempts | id、job_id、attempt_no、provider/model、幂等键、provider_request_id、状态、起止时间、租约/栅栏号、脱敏错误码 |
| generation_credit_operations | job_id、本地预占操作记录，对应 `credit_reservations.id`、reserve/capture/release、整数积分、状态、重试时间；操作 ID 唯一。外部账本操作字段已移除 |
| generation_offers | id、user_id、输入哈希、资产/配置/费率修订、费用规则、最高积分、expires_at；费用提议不可被客户端改写 |
| prompt_templates | id、purpose、industry_id、style_id、model_config_id、body、变量白名单、enabled、revision、updated_by_admin_id |
| generation_model_configs | id、provider、model、purpose、credential_ref、启用状态、验证能力、revision；不存可返回浏览器的明文密钥 |
| generation_model_routes | purpose、primary_config_id、backup_config_id、revision；主备变更原子提交 |
| asset mask 关联 | source_asset_id、mask_asset_id、源/蒙版哈希、审核记录、revision；一张原图最多一个当前有效 mask |
| Outbox / audit | 业务事件与任务状态同事务；后台操作者引用 admins.id，客户引用 users.id |

重要约束：

1. `UNIQUE(user_id, kind, request_key)`，任务归属通过服务端身份写入；永不接收客户端 userId 作为所有者。
2. selection 通过 `(job_id, result_id)` 关联校验，只能引用本人任务的可用结果；更新使用选择修订号 CAS。
3. 状态变更、结果绑定和 Outbox 同事务；Worker 使用租约和栅栏号避免旧执行者覆盖新执行者。S3 文件先暂存，事务成功后绑定；未绑定孤儿对象延迟清理。
4. 后台资产替换采用新对象和新引用，历史任务固定旧快照。引用中的原图、mask、结果不得随新上传覆盖或物理删除。
5. 方案下架阻止新任务；建议已受理任务继续使用快照，已有本人结果可访问。因素材授权撤回的紧急封禁需单独撤销访问并停止未执行任务，规则待评审。
6. 平面素材与报价保存 `schemeCode + themeJobId + resultId + selectionRevision` 的受验证快照；选择后续改变不反向改写已有业务记录。
7. 历史报价访问通过项目授权读取绑定资产；伙伴不因此获得客户所有生成任务的查询权限。

## 7. 客户端接口契约

沿用 API-006～008、029；新增 API-092 解决生成能力、费用告知和确认问题。成功响应采用业务 JSON，错误沿用 `error` 包装。所有接口为建议契约。

### 7.1 API-092 获取可生成能力及费用提议

`POST /api/v1/client/theme-offers`，权限：本人。只做能力和费用计算，不创建生成任务、不预占积分。默认 `purpose=theme`；仅当四面素材收费政策及账本协议冻结后，扩展 `purpose=artwork` 分支。

请求包含 `schemeCode`、`sourceAssetId`；可选 `input`、`requestedCount`、`cacheMode`。未提供完整输入时返回支持的行业×风格组合、颜色/关键词限制、张数、价格规则、可用视角及阻塞原因；完整有效输入时额外返回 `offerId` 和 `expiresAt`。

收费的 `purpose=artwork` 分支改为包含 `schemeCode, themeJobId, resultId, selectionRevision`，不接受 theme 分支的 `sourceAssetId/input/requestedCount/cacheMode`；服务端固定四方向、模板、模型、已选效果和费用快照，返回相同形式的限时 `offerId`。创建时仍由 API-015 复核当前选择与费用；该分支未通过 Q09 决策前不得上线。

```json
{
  "available": true,
  "blockedReasons": [],
  "sourceAssetId": "asset-original-01",
  "limits": { "maxBrandColors": 3, "maxKeywordCharacters": 200, "allowedCounts": [1, 2, 3, 4] },
  "supportedCombinations": [{ "industryId": "consumer-electronics", "styleId": "technology" }],
  "offer": {
    "id": "offer-01",
    "expiresAt": "2026-09-24T10:05:00Z",
    "pricingRevision": 1,
    "unitCredits": 10,
    "maxCredits": 20,
    "settlementRule": "per_usable_image",
    "cacheHit": false
  }
}
```

示例积分仅用于展示字段，不是已确定价格。阻塞原因使用稳定码，如 `MASK_UNAVAILABLE`、`TEMPLATE_UNAVAILABLE`、`MODEL_UNAVAILABLE`；不可访问的方案不返回内部维护信息。缓存判断及费率仍须在创建时重验；超出用户已确认最高积分必须重新确认。

### 7.2 API-006 创建任务

`POST /api/v1/client/theme-jobs`，权限：本人。

```json
{
  "requestKey": "7befdc1a-1e5b-4d1f-b2e9-c38906453452",
  "offerId": "offer-01",
  "schemeCode": "TW66_BK_044_F&B",
  "sourceAssetId": "asset-original-01",
  "input": {
    "industryId": "consumer-electronics",
    "styleId": "technology",
    "brandColors": ["#0055AA", "#FFFFFF"],
    "brandKeywords": "智能科技、简洁品牌画面"
  },
  "requestedCount": 2,
  "cacheMode": "reuse"
}
```

- 不接收任意 URL、maskId、prompt、模型、单价或用户 ID；由服务端从 offer 和方案解析。
- Schema 拒绝未知字段；requestKey 建议为 UUID，语义幂等请求哈希包含全部业务字段，不包含凭证及服务端派生值。
- 新异步任务返回 `202`；缓存立即完成或同键重放返回 `200`，响应均含 `jobId/status/reusedRequest/cacheHit/credits/pollAfterMs`；`Location` 指向 API-007。
- 本地积分账本确认中可返回 pending；随后不足或预占拒绝通过任务失败展示。已知不足可在受理前返回 409，两种路径均不得调用模型。
- 同键异请求、报价过期、资产快照变化、价格变化返回 409；重复请求查重优先于 offer 时效检查。
- 服务端检查原图归属、当前发布/禁用状态、mask 审核、模板展开、模型能力、费用和并发配额。

### 7.3 API-007 查询任务

`GET /api/v1/client/theme-jobs/{jobId}`，权限：本人。不存在与他人任务统一 404。示例中的 URL 为占位值。

```json
{
  "jobId": "theme-job-01",
  "schemeCode": "TW66_BK_044_F&B",
  "status": "partially_succeeded",
  "phase": null,
  "requestedCount": 2,
  "usableCount": 1,
  "original": { "assetId": "asset-original-01", "previewUrl": "<短期授权链接>" },
  "results": [{ "resultId": "result-01", "previewUrl": "<短期授权链接>", "width": 1920, "height": 1080 }],
  "selection": { "resultId": null, "revision": 0 },
  "credits": { "status": "settled", "reservedCredits": 20, "chargedCredits": 10, "releasedCredits": 10 },
  "failure": { "reason": "PARTIAL_OUTPUT", "retryable": true },
  "pollAfterMs": null
}
```

完整契约还包含输入回显、createdAt/updatedAt/completedAt、deadlineAt、URL expiresAt、cacheHit。`credits.status` 取 `pending / reserved / settling / settled / released / not_charged`；reservedCredits 为历史预占总额，另返回 `heldCredits` 表示当前仍占用金额，不能把已结算预占额当作当前冻结余额。

返回中不暴露 mask 下载地址、完整系统提示词、提供商密钥、内部对象键。任务失败仍是正常 200 查询响应，错误放在 `failure`，不是 HTTP 500。

### 7.4 API-008 保存最终效果

`PUT /api/v1/client/theme-jobs/{jobId}/selection`，权限：本人。

```json
{ "resultId": "result-01", "expectedRevision": 0 }
```

响应：`{ jobId, schemeCode, resultId, revision, selectedAt }`，HTTP 200。

- 仅成功/部分成功任务可保存，结果必须可用且属于该任务。
- 当前结果已相同则返回当前选择，便于网络重放；切换到其他结果必须匹配 expectedRevision，否则 409。
- 不收费、不触发四面图任务。下游引用由服务端校验，客户端不能自行拼接他人 resultId。

### 7.5 相邻接口的交接补充

| 接口 | 补充契约 |
|---|---|
| API-004 方案详情 | 提供每视角主题能力摘要及不可用提示，不暴露私有数据；实时判定以 API-092/006 为准 |
| API-029 / API-085 积分 | 建议返回 availableCredits、heldCredits、updatedAt；同一本地 PostgreSQL 账本，提交后重新查询 |
| API-015 四面素材任务 | 请求包含 schemeCode、themeJobId、resultId、selectionRevision、requestKey（收费时另带 offerId）；新请求受理时校验当前选择，固定引用后不随选择变化；同键同体重放先返回原任务 |
| API-014/017/018 素材查询下载 | API-014 当前素材入口的主题上下文同时携带 themeJobId、resultId、selectionRevision，服务端校验本人及当前选择；API-017/018 历史私有下载只需 artworkJobId，服务端按任务创建时固定的主题选择快照、用户和方案归属鉴权，不要求当前选择仍相同 |

### 7.6 错误响应

沿用现有 `error.code` 的 `VALIDATION_ERROR / REQUEST_ERROR / INTERNAL_ERROR` 及现有 404 `NOT_FOUND`。建议新增受控 `reason` 和字段错误用于业务提示，需实现时扩展现有错误处理，当前全局错误处理尚不支持这些业务字段。

```json
{ "error": { "code": "REQUEST_ERROR", "reason": "INSUFFICIENT_CREDITS", "message": "积分不足", "requestId": "req-01" } }
```

| HTTP | reason 示例 | 客户端处理 |
|---|---|---|
| 400 | INVALID_INPUT / PROMPT_TOO_LONG | 定位字段，不清空表单 |
| 401 | AUTH_REQUIRED | 登录后恢复上下文 |
| 403 | OPERATION_FORBIDDEN | 提示权限不足 |
| 404 | RESOURCE_NOT_FOUND | 不区分不存在与私有对象无权 |
| 409 | INSUFFICIENT_CREDITS / IDEMPOTENCY_CONFLICT / OFFER_EXPIRED / CONFIG_CHANGED / SELECTION_CONFLICT | 按原因刷新费用、任务或选择，不自动付费重试 |
| 422 | MASK_UNAVAILABLE / TEMPLATE_UNAVAILABLE | 更换视角/组合或等待维护 |
| 429 | GENERATION_LIMITED | 返回 Retry-After，等待重试 |
| 503 | MODEL_UNAVAILABLE / CREDIT_SERVICE_UNAVAILABLE | 保留输入，恢复后复用未确认提交的原 requestKey |

## 9. 性能、权限与运维

- 单图 ≤30 秒是原需求的验收目标，不是当前已验证能力；必须明确并记录排队、模型调用、下载校验、积分结算以及用户可见端到端耗时。批量四图不能冒充单图时延。
- 提交接口建议在 2 秒内完成本地受理；本地积分账本使用 pending 协调，避免阻塞 HTTP 等待整张图生成。
- 提供商超时、任务总截止时间、队列最长等待及每用户并发由技术验证冻结；任务超时不会自动证明上游未计费。
- 按用户和全局限制在途任务、请求频率及模型并发；所有限制在服务端校验，不能靠按钮禁用实现。
- 原图/结果使用受控存储；浏览器链接使用公开可达存储端点、短时有效且不写日志，禁止暴露 `silo` 等容器 hostname。
- 提供商结果下载仅访问适配器允许的域名和协议，并限制大小、跳转及耗时；不接受客户提供的任意图片 URL。
- 监控成功率、部分成功率、排队时长、主备调用次数、未知 attempt、预占滞留、结算失败、孤儿资产及可用结果数；按 jobId/requestId 排障。
- 素材和任务保留期、客户删除诉求、项目引用保留约束待冻结；清理不得破坏已经交接的报价和素材任务。

## 10. 验收与评审

### 10.1 功能及异常验收矩阵

| 场景 | 预期证据 |
|---|---|
| C2-01 / B-01 输入与登录回跳 | 行业/风格/颜色/关键词可回显；登录不会自动付费；更换视角正确换 mask |
| M2-01 / B-02 错配蒙版 | 分辨率不一致、空 mask、原图替换均阻止新生成；人工审核关联实际哈希 |
| B-03 主备样本 | 相同样本跑通两源，记录成本、耗时、失败恢复，不能只验 HTTP 成功 |
| B-04 模板展开 | 品牌变量正常替换；未知变量、重复启用、超长实际输入被拒绝 |
| C2-02 同键重发 | API 响应丢失及并发连击仅一个任务、一次预占/结算；异请求同键返回 409 |
| 网页与 SU 并发消费 | 本地积分账本原子预占，余额不透支，两端读取一致 |
| Worker 重启 / 重复投递 | 已有上游 ID 恢复查询；结果已存则仅恢复结算，不再次调用 |
| 上游超时不确定 | 不盲目切换备用，进入核对；晚到结果不改终态、不再次扣费 |
| C2-03 / B-05 结果 | 1～4 张候选可对比、实际张数准确，原图不充当成功结果 |
| 区域外保持与结构 | 合成后区域外解码像素一致；设计人员对区域内虚假构件/接缝抽样验收 |
| 部分结果与费用 | 请求 4 张交付 2 张，按确认费率结算 2 张，释放其余；失败图无公开 URL |
| C2-05 / B-06 全失败 | 原图可用，预占释放或清晰显示处理中，可继续原方案报价 |
| 结算不可用 | 保留 settling，恢复使用同操作 ID，结果不丢失、用户不重复付费 |
| 缓存隔离 | 同用户相同完整快照复用免费；其他用户不可命中私有结果；refresh 明确新付费 |
| C2-04 并发选择 | 不同结果并发保存一项成功、一项冲突；同结果重放幂等 |
| 下游引用 | 切换选择后旧报价/四面图仍绑定旧结果，新任务校验并绑定新结果 |
| 私有对象越权 | 他人 jobId/resultId 不可读写；后台图片访问受限并留审计 |
| 资产/方案变动 | 新任务拒绝过期 offer，已受理任务仍使用快照；历史项目引用有效 |
| B-07 单图性能 | 报告声明模型、样本、并发及端到端时间，核对 ≤30 秒目标和瓶颈 |

实施时积分并发、幂等、状态恢复使用可控模拟与数据库集成验证；图像边界使用固定样本像素比较，结构/品牌表现由设计人员验收；供应商时延及真实故障恢复需联调证据，模拟不能替代。

### 10.2 开发前需冻结的决策

| 编号 | 待确认事项 | 本稿建议 |
|---|---|---|
| T01 / Q09 | 单次费用、部分失败、缓存、扣费时点 | 单图费率×实际可用图，先预占后结算，失败释放、缓存免费 |
| T02 | 积分账本本地验收 | 本地预占/扣除/释放与并发场景验收（Web/SU 共用同一 PostgreSQL 账本） |
| T03 | 最终提供商和模型 | 候选双源同样本验证，冻结 mask 编码、文本限制、输出和幂等能力 |
| T04 | 生成数量与输入 | 默认 1、可选 1～4；行业/风格单选，最多 3 色；是否需要 LOGO/产品图片上传 |
| T05 | 蒙版与生成质量 | 无损精确品红、区域外合成保护，区域内结构/品牌由样本验收确定准入 |
| T06 | 30 秒验收口径与任务截止 | 明确单图端到端测试环境与负载；超时核对上游再终结 |
| T07 | 后台 API 配置边界 | 后台选模型/主备/凭据引用，密钥和域名由部署维护 |
| T08 | 历史素材保留和紧急撤回 | 正常下架不破坏已受理任务/项目；授权撤回另行封禁 |
| T09 | 缓存期限、并发限额、offer 有效期 | 根据成本和联调冻结，不写死为业务事实 |

建议按三个可验收闭环实施：① 单模型、单图、登录积分、生成及选择交接；② 蒙版/模板/模型后台维护及完整失败恢复；③ 1～4 张部分成功、缓存和性能达标。各阶段均使用同一正式数据与积分边界，使用本系统 PostgreSQL 自建账本，网页与 SU 共用同一数据库余额。
