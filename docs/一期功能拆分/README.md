## 依据和范围

- 来源 R：《灵通_AI_展台方案平台_第一期需求书_v1.0.md》，以正文第三章七个模块为客户端范围。文件正文标注 v0.6，与文件名不同。
- 来源 S：《灵通_AI_展台方案平台_开发需求规格说明书_v1.0.md》，以下直接引用其 REQ 编号。正文首尾版本标记不同，按条目内容拆分，不据文件名推断优先级。
- 最新用户确认：登录复用灵通已有接口，用户详情复用按 username 查询接口，注册跳转官网；本服务维护 users（客户端/SU）与 admins（后台）两张独立信息表，每次登录后更新对应记录；后台登录使用 site=admin；该确认优先于原始需求中的本地注册设计。接口字段依据用户提供截图整理，本次未进行在线调用。
- 来源 X：《source/灵通展台方案打标模板.xlsx》，读取“方案打标”A1:T1、“下拉选项”A1:F13、“字段说明”A1:F29。

客户端七个模块为：AI 智选、品牌/主题调整、简化清单、报馆图素材、平面素材、获取报价、账户登录。双入口和权限是横跨模块的能力，不新增第八模块；模型下载归入方案详情，伙伴项目跟进归入获取报价。SU 内部结构编辑由插件完成，不扩成网页设计器。

后台操作和 API 是为落实来源需求做的功能级拆分。所有路由均为本次建议设计，未声明已实现。标注“建议补齐”的业务规则需要确认后采用；结构母版、变体、主题、品牌先维护关联，不扩成自由拼装系统。

一期不包含：从零生成展台结构、自由组件组合、网页结构编辑器、自动报价、自动下单、订阅套餐定价与支付充值、小程序、完整版本管理、自动生成可直接印刷文件。

## 原文差异与待确定事项

这些事项仅影响对应条目，不影响其他功能拆分。

| 编号 | 差异或缺失 | 本次拆分处理 |
|---|---|---|
| Q01 | S A-04 要求不足随机补齐；R 3.1、S A-05 要求不放宽条件硬给结果 | 建议有条件查询仅返回合格结果，不足三套如实展示；只有全空输入随机选取。最终补齐规则待确认 |
| Q02 | X 只有开口面数；R/S 要求开口方向与模板适用条件匹配 | 后台补充维护开口方向、适用条件；具体字段枚举待确认。面数相同不代表方向相同，缺失时不能判定可直接采用 |
| Q03 | X 将 F～K 定义为硬筛选；S 允许面积接近、长宽或开口不符的相似参考 | 建议先硬筛选可采用集合，再单独检索并标明相似参考；产品体系不符合不得混入可采用。参考范围及限高不符是否允许参考待确认 |
| Q04 | S 给出长宽容差 3%、参考面积偏差 30%及建议排序权重 | 保留为候选规则，不把建议权重写成已冻结业务规则；最终阈值、尺寸旋转规则待确认 |
| Q05 | C-02 要总价公式；C-06 要导出单价/总价留空 | 建议导出保留八列，单价空时总价显示空，填价后按公式计算；是否要求总价单元格完全无公式待确认 |
| Q06 | X S 列“已核验”实际指清单核验，不代表六类资产已完整审核 | 清单核验与方案发布分开；不得仅凭该字段自动发布 |
| Q07 | 公开/伙伴入口资料权限未给出完整矩阵，报价是否必须登录未定 | 免费浏览免登录、换主题必登录已确定；清单/图纸/素材下载按授权，模型仅授权伙伴。报价匿名提交、资料开放范围待确认 |
| Q08 | 已确定使用已有登录、用户详情与官网注册；现有接口接入细节仍不完整 | 不再开发本地注册或密码认证；邮箱登录支持、请求方法/Content-Type、JWT 传递及校验方式、有效期/退出机制、跨域、后台角色映射和 SU 凭据兼容性待联调；注册不假定支持自动回跳 |
| Q09 | 积分单次消耗、失败退还、缓存命中及四面素材是否收费未明确 | 服务端统一扣费、防重复执行；具体扣费时点和退还规则待定，不增加充值支付模块 |
| Q10 | 预算低/中/高端点及币种未明确；X 行业说明比下拉表少三项 | 枚举采用完整“下拉选项”表；不自行把 3 万、8 万边界和币种硬编码成筛选规则 |
| Q11 | 渠道归属识别、公共线索默认承接人、客服厂商与接入参数未冻结 | 保留归属和客服功能；来源识别、分配规则及 SDK 配置待确认，不自建即时通信系统 |
