# 管理后台功能需求

后台分组是维护职责，不受客户端七个模块数量限制。本表只列业务操作；原始需求未明确界面但完成业务所必需的维护操作，标为“维护拆分”。

## M1 方案库与打标

| 编号 | 独立功能 | 完成行为 | 来源 |
|---|---|---|---|
| M1-01 | 查询方案列表 | 按编号/名称、空间条件、标签、核验状态、发布状态筛选并分页，进入详情 | S H；X，维护拆分 |
| M1-02 | 新建方案 | 建立唯一编号、名称、来源和打标数据，重复编号拒绝保存，不自动发布 | S H-03、H-04 |
| M1-03 | 编辑方案打标 | 编辑下述 20 字段及开口方向/适用条件，校验尺寸、面积、枚举与关联；不得无声更换已被项目引用的编号 | S A-04、H-04；X |
| M1-04 | 维护母版与变体关联 | 为结构/功能变体建立独立编号并关联母版，纯视觉主题复用结构；保留视觉主题、品牌资料关联，不创建版本管理 | S H-01、H-04 |
| M1-05 | 导入打标模板 | 读取 Excel 二十列，忽略只有序号的空行；预览新增/已有编号/错误行；不把重复编号静默覆盖，确认后导入有效记录 | X，建议补齐批量维护 |
| M1-06 | 维护匹配字典 | 维护开口面数、产品体系、风格、行业、预算、核验状态及标签可选值；已引用值的变更需保留原关联 | X 下拉选项，维护拆分 |
| M1-07 | 上传方案模型 | 上传/替换当前方案 SKP，关联唯一编号，仅向授权伙伴提供下载 | S H-02、G-02 |
| M1-08 | 维护效果图 | 上传三张高分辨率 16:9 效果图，维护展示顺序及与 mask 的对应关系 | R 5.3；S A-06、H-02 |
| M1-09 | 检查资产完整性 | 检查模型、简化清单、效果图、蒙版、报馆图、平面素材六类资产及编号对应，显示缺失项 | S H-02 |
| M1-10 | 记录审核结果 | 记录设计筛选、模型转化、清单/图纸复核、产品型号/配件/适用条件和素材授权确认结果；不把线下制作误做成 AI 自动审核 | S H-03；R 六 |
| M1-11 | 发布方案 | 业务负责人确认审核通过和资产齐全后发布，客户端可匹配；待核验清单不能支撑正式发布 | S H-03；X S列 |
| M1-12 | 下架方案 | 停止进入公开匹配和新选择，保留已有项目引用；历史资料后续访问按授权处理 | 审核发布维护拆分 |

### 打标字段

| Excel 列 | 字段 | 功能规则 |
|---|---|---|
| A | 序号 | 导入展示用行号，不是业务主键 |
| B | 方案编号 | 全库唯一；沿用实际编号，不按模板说明中的 LT-XXX 示例强行改号 |
| C | 方案名称 | 后台维护检索；客户端结果不展示 |
| D | 母方案编号 | 可空；非空必须关联有效母方案，不能关联自身 |
| E | 配套清单文件 | 关联实际清单资产，只有文件名不代表已上传 |
| F、G | 展位长(m)、展位宽(m) | 数值，参与硬筛选 |
| H | 展位面积(㎡) | 模板手填值需与长×宽一致 |
| I | 展位高度(m) | 方案实际高度；与客户限高比较 |
| J | 开口面数 | 1面、2面、3面、4面、岛式；与开口方向不同 |
| K | 产品体系 | FS62布框、铝合金框、桁架、灯箱墙、艺四方墙、混合 |
| L | 风格 | 模板单选；客户端查询允许多选 |
| M | 适用行业 | 模板单选；客户端查询允许多选 |
| N | 预算档位 | 低(3万以内)、中(3-8万)、高(8万以上)；材料购买预算，币种/边界见 Q10 |
| O | 功能分区 | 逗号分隔多值，按标签维护 |
| P | 关键特征 | 逗号分隔多值，按标签维护 |
| Q | 一句话描述 | 自然语言语义匹配信息 |
| R | 关键词 | 逗号分隔多值，参与检索 |
| S | 核验状态 | 已核验/待核验，表示清单核验状态，与发布状态分开 |
| T | 备注 | 后台补充说明，不自动作为公开文案 |

风格完整枚举：现代简约、自然环保、科技未来、新中式、轻奢、工业风、暖色温馨、极简黑白、商务冷色、美术馆白、潮流活力。

行业完整枚举：消费电子、建材家居、珠宝钟表、汽车、食品饮料、医药健康、服装纺织、文化艺术、通用、五金电器、婴童用品、护肤美妆。后三项出自“下拉选项”，不能只按“字段说明”截取前九项。

开口方向、模板适用条件是需求书要求但模板缺少的补充字段；不擅自改变原 Excel 二十列格式。

## M7 账户与权限管理

| 编号 | 独立功能 | 完成行为 | 来源 |
|---|---|---|---|
| M7-01 | 后台登录 | 内部人员使用已有 site=admin 登录接口及用户详情接口，通过后台登录同步接口创建/更新独立 admins 表中的管理员记录，再校验平台后台权限；不新增用户名密码登录接口，已有角色与后台权限的映射待确认，仅登录成功不代表可进入后台 | S G-03、K-02，维护拆分 |
| M7-02 | 查询账户 | 从本地 users 查询已同步账户身份，关联角色、伙伴归属和积分余额，显示最近登录与同步时间；不展示密码及 token，也不视为官网全量用户列表 | S K-05、K-06，维护拆分 |
| M7-03 | 配置角色授权 | 分别为 users 中的伙伴用户、admins 中的内部管理员授权可执行的操作，分别控制内部成本、渠道价格、项目资料和资产访问范围 | S G-02、G-03 |
| M7-04 | 配置渠道归属 | 维护客户与合作伙伴的归属关系，使申请承接可沿用既有关系 | S G-04，维护拆分 |
| M7-05 | 查询积分流水 | 查看余额及关联生成任务的扣费情况，网页与 SU 共用同一账本；不扩成套餐/支付系统 | S K-05、K-06，维护拆分 |
| M7-06 | 查询操作审计 | 按操作者、对象和时间查询审核发布、授权及项目操作记录；管理员引用 admins.id，伙伴用户引用 users.id，混合记录带身份类型 | S G-03、I-05 |
