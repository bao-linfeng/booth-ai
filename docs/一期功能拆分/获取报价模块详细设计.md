### 1.2 已确定业务边界

1. 用户从详情或清单页填写申请，成功后形成关联唯一方案编号的项目，交销售或合作伙伴跟进。
2. 无匹配人工需求是独立来源，可以先没有方案；后续人工关联经确认方案。
3. 预算仅指材料购买预算，不等于报价；人工录入单价后计算金额，不由 AI、预算档位或效果图推算价格。
4. 客户在线清单不展示价格；空价简化清单与人工报价单分别保存和导出。报价单由销售通过客服等渠道交付。
5. 渠道客户保持渠道归属，公共客户落到明确承接方。账户登录不自动赋予伙伴或后台权限。
6. 实时消息由第三方客服承担；演示模拟必须标明模拟状态。报价不涉及积分、支付、自动下单。

### 1.3 本稿建议

| 项目 | 建议及影响 |
|---|---|
| 提交身份 Q07 | 推荐一期登录后提交报价和人工需求，免费浏览及无项目客服咨询仍可匿名；此项不是已确认需求 |
| 公共承接 Q11 | 配置一名有效的内部默认承接管理员，提交即分配；渠道项目使用已有有效归属伙伴，另可分配内部协助人 |
| 报价文件 | 推荐 XLSX，方便人工交付；金额由服务端计算并以固定值导出，模板与格式待业务确认 |
| 报价状态 | 项目六种状态与人工报价修订分开；保存/下载报价都不自动标记“已报价”，发送后由跟进记录确认 |
| 历史资料 | 项目固定提交时资料；报价修订留存不可变内容，以便追溯已发送版本，不扩展为通用方案版本系统 |

后文身份契约以“推荐登录提交”为基线。若采用匿名提交，须先完成第 10 节 FQ01 的替换契约，不能只把鉴权改为可选。

## 2. 客户端详细功能

### 2.1 C6-01 填写报价申请

入口携带 `schemeCode`、已读取的 `bomRevision / drawingRevision / artworkRevision`；选择过主题时携带 `themeJobId + resultId + selectionRevision`，如已生成四面图可带 `artworkJobId`。点击按钮只打开表单，不创建项目。

页面包括方案及效果摘要、展会信息、需求范围、材料预算、联系人、备注和提交按钮。参考匹配方案显示原需求与差异，不能将“参考”展示为已确认适用。

| 字段 | 建议必填与校验 |
|---|---|
| `schemeCode` | 必填，只读展示，服务端重新查方案；不接受浏览器上传清单作为依据 |
| `exhibition.name` | 必填，去首尾空格后 1～200 字符 |
| `exhibition.countryCode / city` | 国家用于跨国地点与客服上下文，建议必填；城市必填，1～100 字符 |
| `exhibition.startDate / endDate` | 必填 `YYYY-MM-DD`，结束不早于开始；日期为展会当地日历日期，不转为 UTC 零点 |
| `scopeCodes` | 至少一项；建议 `materials / graphics / transport / installation / other`，最终枚举需确认 |
| `scopeNotes` | 选择 other 时必填，其他情况可选，最多 2000 字符；需求范围不构成交付承诺 |
| `materialBudget` | 必填 `{currency, amount}`；金额为正十进制字符串，不用智选低/中/高档位替代；允许待定/区间与否见 FQ03 |
| `contact.name` | 必填，1～100 字符 |
| `contact.email / phone` | 至少一项；邮箱校验基本格式，电话允许国际区号，不只支持大陆手机号 |
| `customerType / company` | 建议 `individual / company`；企业类型要求 company，最多 200 字符 |
| `notes` | 可选，最多 2000 字符 |

账户资料仅预填，用户可核对；提交保存本次联系信息快照，不回写统一账户资料。最终必填范围见 FQ02。未知字段、非法币种、负预算、无联系方式在服务端拒绝。

### 2.2 C6-02 提交与回执

1. 未满足提交身份时登录，回到原表单；恢复数据避免将完整联系方式写进 URL。
2. 前端为一次确认的提交生成 `requestKey`，提交期间禁用按钮；超时保留同一请求体和标识重发。
3. 服务端固定方案、资料、主题、来源、归属及承接人后，事务创建申请和项目。
4. 成功显示申请号、项目号、已受理提示及“联系在线客服”；不能把受理成功显示为报价已出具。
5. 修订变化时保留表单，刷新相关资料并由用户确认；修改业务内容后使用新标识。网络结果未知时应先用原请求重试确认结果，避免误建第二项目。
6. 不承诺尚未确定的响应时限。普通客户一期通过回执和客服跟进，不新增未列入范围的“我的项目”列表。

| 异常 | 页面处理 |
|---|---|
| 字段不合格 | 定位字段，不清空其他输入 |
| 登录失效 | 登录后恢复上下文，不自动重复创建 |
| 方案下架、指定资料修订或主题选择变化 | 显示冲突，重新确认，不静默改成当前资料 |
| 缺少清单/图纸但允许人工承接 | 明示待补资料并记录缺失，不伪造已核验资料 |
| 承接配置不可用 | 显示受理暂不可用，保留内容并可咨询客服，不返回虚假的项目号 |
| 提交成功但客服不可用 | 保留成功回执，客服可重试，不撤销项目 |

### 2.3 C6-03 在线客服

- 详情页可在未提交项目时咨询；提交后从回执携带项目上下文进入。
- 服务端产生白名单上下文：当前用户/访客标识、项目号、方案编号、个人/企业、国家、城市、语言；不得携带内部成本、完整报价或凭据。
- 项目参数必须属于本人或当前被授权伙伴。项目号是业务标识，不是访问凭据。
- 问候语展示方案编号等信息；客服工作台可以接收和回复才算真实接入成功，仅弹出窗口不算验收通过。
- 厂商选定后再冻结 SDK 初始化、短期签名、语言及身份绑定协议；当前文档不虚构第三方字段。
- SDK 加载失败/客服离线分别提示；离线留言仅在厂商支持时使用，不能显示已进入实时对话。
- 演示模式响应 `mode: mock` 并显示“模拟客服”；生产配置不能静默降级为假回复。

### 2.4 C6-04 无匹配人工需求

复用需求和联系人表单，但不要求方案编号。保存原始描述、已解析结构化条件、用户最终确认条件；原文与结构化字段分开保留，不将匹配失败原因伪造为业务结论。提交标记 `sourceType: manual_request`，仍必须有承接人。

### 2.5 C6-05 / C6-06 伙伴项目

- 列表仅返回归属当前伙伴的项目；详情包含需求、授权联系方式、方案和资料快照、可见跟进记录。
- 伙伴可写跟进及允许的状态变化；不能自行改客户渠道归属、把项目分给其他伙伴、编辑平台人工报价。
- 内部联系记录默认 `internal`，共享记录为 `partner`；伙伴提交记录固定 `partner`。对客户交付仍走客服，不把内部跟进全文推送给客户。
- 伙伴可见的历史图纸由项目接口受控交付；清单快照在详情中按资料权限返回结构化数据。主题效果通过项目权限取得受控预览，不借本人任务接口访问客户全部生成记录。

## 3. 后台详细功能

| 功能 | 页面与行为 |
|---|---|
| M6-01 项目列表 | 项目号、方案、客户、展会、城市/日期、预算、授权联系方式、状态、来源、归属、承接人、更新时间；筛选和分页由服务端执行 |
| M6-02 项目详情 | 申请快照、原始需求、方案/效果/差异、清单和图纸状态、归属依据、承接记录、报价区、跟进时间线 |
| M6-03 分配 | 选择有效管理员或伙伴，填写原因；渠道归属与实际协助人分开，不能靠分配接口洗掉渠道归属 |
| M6-04 跟进 | 联系方式类型、联系时间、内容、下次跟进时间、可见范围及可选目标状态；记录不可覆盖，纠错追加说明 |
| M6-05 人工报价 | 从项目清单快照复制材料行作为编辑起点，人工填价；可新增运输/搭建等服务行，差异填写原因；不修改原清单 |
| M6-06 导出 | 指定报价修订下载文件；展示报价号、修订、项目和方案、币种、金额、有效期、包含/不包含范围及客户可见条款 |
| M6-07 人工方案关联 | 仅对尚无方案的人工需求关联一次；重新验证可见性、资料及客户确认依据，固定快照并记录处理人 |
| M6-08 客服 | 打开厂商工作台；能定位平台项目，平台不保存一套重复的实时消息 CRUD |

方案关联不能以普通文本框任意替换既有报价方案。结构变化使用独立方案编号；已有关联后需要更换方案的业务在 FQ07 单独确认，初版不开放覆盖。

## 4. 状态、归属与一致性

### 4.1 项目状态机

| 状态 | 中文 | 允许的普通后继状态 |
|---|---|---|
| `pending` | 待跟进 | following、closed |
| `following` | 跟进中 | quoted、won、lost、closed |
| `quoted` | 已报价 | following、won、lost、closed |
| `won` | 已成交 | 无普通后继 |
| `lost` | 未成交 | 无普通后继 |
| `closed` | 已关闭 | 无普通后继 |

- 每次状态变更随跟进记录原子保存；仅添加记录可不传目标状态。
- 进入 `quoted` 必须填已发送依据：平台报价修订或外部人工报价说明；保存/下载文件不构成发送证据。此字段记录人工声明，不证明第三方实际送达。
- 伙伴可能线下报价，允许 `external_manual` 依据，不要求伙伴获得内部报价编辑权限。
- `won` 填成交结果，`lost / closed` 填原因；成交是业务跟进结果，不代表本平台发生支付。
- 终态可追加结果说明；重开仅后台专用权限允许回到 `following`，必填原因。
- 终态项目禁止修改承接、关联方案和新存报价；先重开再处理。历史报价及记录仍可按权限读取。
- `quoted → following` 用于重新沟通，旧已发送报价记录保留；报价草稿更新不反向改写既有跟进证据。

这些为建议流转规则；原始需求只给出六个状态，重开及跳转需 FQ05 确认。

### 4.2 来源、归属与承接

三个概念分别存储：`sourceType` 是报价/人工需求；`entryPoint` 是清单/详情/匹配结果/SU 网页等来源；`attribution` 是确定的渠道归属。客户端 entryPoint 只作分析，不能授予权限。

1. 服务端读取客户现有归属，不信任客户端提交 `partnerId / ownerId / userId`。
2. 有渠道归属：快照保存渠道、关系修订和依据；归属伙伴为默认承接，内部可指派协助人。
3. 公共线索：默认有效内部管理员承接；有分配权限的后台可改派有效伙伴。
4. 渠道伙伴停用或默认人无效时，不能把渠道客户改为公共客户。建议保留归属并使用配置的内部兜底承接人；没有有效兜底则整体受理失败。
5. 普通分配不改渠道；归属纠错由 API-078 单独授权审计。建议新归属影响后续申请，已存项目不批量改写；历史项目迁移需独立确认。
6. 伙伴访问范围：渠道项目以固定归属伙伴为准；公共项目以当前伙伴承接关系为准。改派后旧公共伙伴失去访问，新伙伴仅取得共享资料；停用伙伴始终不能访问。

### 4.3 提交事务与资料快照

同一事务完成：幂等登记、方案状态与显式修订校验、主题选定校验、渠道归属和承接校验、申请记录、项目、资料快照、首条系统事件、待通知 Outbox 事件。申请与项目使用预生成 ID，关联外键在同一事务内按依赖顺序插入；不要求数据库中同时保留互相必填的循环外键。

- 方案申请必须存在且可供新申请选用；下架方案不能以新项目绕过限制。
- 清单/图纸/标准平面素材有当前有效资料时固定修订、元数据、内容哈希及不可变文件版本；主题已选时不取标准底图充当换主题素材，若带 `artworkJobId` 须校验本人、方案和所选结果一致且整套可交付。无有效素材且政策允许承接时保存 `missing/pending`；显式传了过期素材修订或错配任务即返回 409，不按缺资料处理。
- 主题三个引用必须同时提供、属于申请人、匹配方案且是当前选定的可用结果；生成失败可用原方案申请。
- 已提交项目不随方案纠错、主题改选或用户资料同步变化；错误历史资料追加风险标识及人工跟进，不覆盖快照。
- 快照保存不自动授予客户/伙伴源文件、模型或图纸下载权限；读取时仍按项目和资料权限过滤。
- 与资料变更共用确定的锁顺序并在事务内校验相同修订，防止先查后写竞态；文件读取/复制、第三方客服调用不持有数据库锁。
- 优先引用已存在的不可变对象，项目事务不依赖临时下载 URL，也不在事务中执行 S3 文件复制。

### 4.4 幂等、并发和通知

- 创建与变更请求带 `requestKey`；作用域为“主体类型+主体 ID+操作+目标对象”，创建接口目标为固定集合。
- 唯一约束保护同键并发；规范化请求摘要包含全部业务字段（含预期修订）。同键同体返回首次结果，同键异体返回 409。
- 重放先验证当前身份与对象权限，再查已完成幂等结果；命中后不重复校验已经变化的资料/业务修订，也不再产生记录或通知。
- 项目写操作使用 `expectedRevision`，任何承接、跟进、方案关联、报价保存成功均递增项目修订；报价另有独立递增的 `quotationRevision`。
- 幂等结果与业务在同一事务提交；数据库失败全部回滚。建议申请幂等映射与项目同生命周期保存，避免延迟重试生成第二项目；保留期见 FQ08。
- 通知由 Outbox 提交后投递，消费者按事件 ID 去重；失败可重试并显示内部异常。通知失败不影响已受理项目，后台列表始终是承接依据；具体通知渠道待定。
- 不按手机号/邮箱自动合并客户或项目，也不因同方案重复申请直接拒绝；不同请求可能是真实不同展会需求。

## 5. 人工报价规则

### 5.1 报价内容

一期每个项目维护一份当前人工报价、若干不可变保存修订。`quotationNo` 为稳定业务编号，`revision` 区分改价。报价需已关联方案；无方案人工需求先联系并关联方案，再生成平台报价。

每次保存提交完整集合：币种、有效期、价格口径、客户可见条款和条目。条目包含类别、名称、型号、规格、数量、计价单位、人工单价、可选 ERP 编码、备注、可选清单快照行引用。

- 清单引用仅能指向本项目快照，复制后保持与原行对应；数量/单位/材料规格有差异时需说明。
- 新增服务行明确类别，不伪装为原模型材料；不得由报价编辑反向改变结构清单。
- 未填价用 `null`，零价用 `"0"`；保存允许未完成草稿，不能把 null 自动换成 0。
- 建议完整性状态 `incomplete / ready` 由服务端派生；至少一条有效行、全部填价、客户及方案明确、币种/有效期/范围完整才可导出。
- `ready` 仅表示可导出，不表示技术审核、审批通过或已发送。

### 5.2 金额、币种和税费

1. API 数量、单价及金额均用十进制字符串，数据库使用精确十进制，金额计算不用二进制浮点。
2. 建议数量及单价最多 6 位小数；数量大于 0、单价非负。建议数据库分别 `numeric(18,6)`，汇总金额 `numeric(30,6)`，超限拒绝而非截断；最终限制需样例验证。
3. 单份报价只允许一种已配置币种；预算币种可不同，但不自动换汇、不据此判定超预算。
4. `lineAmount = round(quantity × unitPrice, currencyScale, HALF_UP)`；`totalAmount = sum(lineAmount)`，不能先累计未舍入值再整体舍入。
5. 币种小数位由服务端配置并快照留存，不默认所有币种两位。例：两位币种下 `3 × 0.335 = 1.01`，两行各 1.01 合计 2.02。
6. 初版建议税费口径 `included / excluded / not_applicable`；人工单价按选定口径填写，总额为该口径行金额之和。`excluded` 明示不含税，必须写客户可见税费说明；平台不输出推定含税应付总额。
7. 运输/搭建等纳入报价则人工单列；未纳入的费用在 exclusions 明示。税率拆分、折扣、跨币种换汇若业务必需，须在 FQ03 冻结后扩展公式，不偷偷加入总额。
8. 数量×人工单价的算术计算属于人工报价辅助，不是自动估价。

### 5.3 导出与交付

- API-069 必填保存后的报价修订；固定快照生成文件，文件正文含报价号/修订、项目号、真实方案编号和客户信息。
- 推荐文件名 `{项目号}@报价单-r{revision}.xlsx`；非法文件名字符安全替换，正文编号不改写。
- 使用结构化白名单生成，客户条款和文本按文本单元格写入，不执行用户公式；不含内部成本、渠道价、内部跟进和隐藏源表。
- 导出金额为服务端计算的固定值，与页面一致；不依赖收件人打开软件重算。
- 不完整报价禁止正式导出；历史可导出报价保留原有效期，失效时提示，不能自动延长有效期。
- 文件接口每次校验项目范围及报价权限，返回受控附件流；导出后人工发送并新增跟进记录，标记所发送修订。

## 7. 接口公共约定

- 保留 14 个已有路由编号，不新增自建聊天、自动报价或客户历史查询接口。
- 下文 JSON 是建议业务响应，不预设已有统一响应包装；沿用账户同步身份，不据此规定尚未联调的外部 JWT 请求头。
- 路径 ID 是不可猜测内部标识，`projectNo / requestNo / quotationNo` 是人可读业务号；方案编号按路径段 URL 编码。
- 创建首次成功 `201`，同键重放 `200`；变更成功 `200`（创建跟进首次为 `201`）。所有业务写操作拒绝未知字段。
- `expectedRevision` 为当前项目修订正整数；报价额外带 `expectedQuotationRevision`，尚无报价为 0。
- 列表 `page=1, pageSize=20`，最大 100；固定 `updatedAt DESC, id DESC`，返回 `{items,page,pageSize,total}`。所有计数和筛选先应用数据范围。
- `followUps` 在详情中分页：`followUpPage=1, followUpPageSize=20`，最大 100；响应相同分页结构，伙伴分页/计数不含内部记录。
- 时间戳 ISO 8601 UTC；展会和报价有效期为日历日期，报价同时保存 `validityTimeZone`，明确到期当地日结束。
- 文件与私有响应 `Cache-Control: private, no-store`；对象不可见返回统一 404，具有对象范围但缺少操作权返回 403。

```json
  "schemeCode": "TW66_BK_044_F&B",
  "bomRevision": 7,
  "drawingRevision": 5,
  "themeSelection": {
    "themeJobId": "theme-example",
    "resultId": "result-example",
    "selectionRevision": 2
  },
  "entryPoint": "bill_of_materials",
  "exhibition": {
    "name": "示例展会",
    "countryCode": "CN",
    "city": "上海",
    "startDate": "2026-11-10",
    "endDate": "2026-11-12"
  },
  "scopeCodes": ["materials", "graphics"],
  "scopeNotes": "请确认品牌画面制作范围",
```

成功：

```json
{
  "quoteRequestId": "request-example",
  "requestNo": "QR-EXAMPLE-001",
  "projectId": "project-example",
  "projectNo": "PJ-EXAMPLE-001",
  "status": "pending",
  "revision": 1,
  "schemeCode": "TW66_BK_044_F&B",
```

### 8.2 API-020 提交人工需求

`POST /api/v1/client/manual-requests`

请求：`requestKey, originalDescription, parsedRequirements?, confirmedRequirements, exhibition, scopeCodes, scopeNotes?, materialBudget, contact, customerType, company?, notes?, entryPoint`；共同字段校验同 API-019。原描述非空且建议不超过 5000 字符，结构化字段使用智选白名单；明确拒绝 `schemeCode / themeSelection / bomRevision / drawingRevision`，避免两种来源混用。

成功返回 `manualRequestId, requestNo, projectId, projectNo, status: pending, revision: 1, schemeCode: null, createdAt`。展会/预算尚未确定的简化留资诉求在 FQ02 评审，不能在实现时自行把必填删掉。

### 8.3 API-021 客服上下文

`POST /api/v1/client/customer-service/sessions`

请求：`projectId?、schemeCode?、customerType?、company?、countryCode?、city?、locale`。项目场景以服务端项目快照为准；同时传 schemeCode 与项目不一致则 409。无项目时读取可见方案，身份取当前会话；访客身份由服务端可信访客会话建立，客户端不得传目标 userId。

成功 `200`：`mode: live / mock, provider, sessionContextId, context, expiresAt, connection`。`context` 只含上述白名单；`connection` 是待厂商联调冻结的公开接入信息及必要短期凭据，不能包含服务端密钥；若 SDK 不需要凭据则为空对象。

本接口仅准备上下文，不声称第三方对话已创建。厂商不可用返回 503，已有报价申请保持成功。重复打开可以复用当前访客会话，不创建新项目。

### 8.4 API-022 伙伴列表

`GET /api/v1/client/partner/projects`

筛选：`projectNo, schemeCode, status, sourceType, exhibitionName, createdFrom, createdTo, page, pageSize`。不接受查询任意 partnerId；服务端按当前用户及有效伙伴关系限制。

列表项：`projectId, projectNo, schemeCode, sourceType, exhibition, customerSummary, status, revision, createdAt, updatedAt`，预算/联系摘要按字段权限附加。默认不返回报价和完整联系方式。

### 8.5 API-023 伙伴项目详情与历史文件

`GET /api/v1/client/partner/projects/{projectId}`

默认 `200` 返回 `projectId, projectNo, revision, status, request, schemeSnapshot, materialsStatus, bomSnapshot?, drawingSnapshot?, artworkSnapshot?, themePreview?, followUps, allowedActions`。各资料按权限返回；`allowedActions` 帮助界面渲染，不替代写接口校验。主题预览如使用短期受控 URL，只绑定本项目选定结果；素材快照如未就绪则展示待补状态，不伪造文件。

历史图纸沿用既有设计：查询 `drawingAssetVersionId, disposition=attachment|preview, page?` 时返回文件流；版本必须在项目图纸快照中，预览与原件分别授权，不再要求当前方案公开。文件缺失返回明确错误，不自动换成最新图纸。文件模式不接受跟进分页参数。

### 8.6 API-024 伙伴新增跟进

```json
  "requestKey": "follow-up-example-001",
  "expectedRevision": 1,
  "contactMethod": "email",
```

联系类型建议 `phone / email / customer_service / meeting / other`；内容 1～5000 字符，联系时间不得晚于当前时间容差，下一次时间如填写须晚于本次联系。进入终态补 `outcome`；进入 quoted 补 `quoteEvidence`，见 API-066。伙伴不能提交内部可见性或重开终态。

## 9. 后台接口契约

### 9.1 API-063 / API-064 项目查询

`GET /api/v1/admin/projects`

在伙伴筛选之外增加 `customerUserId, assigneeType, assigneeId, attributionPartnerId, city, exhibitionStartFrom, exhibitionStartTo`；客户名称按快照搜索，允许范围内分页。列表预算含币种；联系方式按权限返回，不能通过筛选计数探测范围外数据。

`GET /api/v1/admin/projects/{projectId}`

返回伙伴详情的授权字段，增加 `attribution, assignee, assignmentHistory, quotationSummary?, auditSummary`；内部跟进按内部读取权限返回。报价摘要仅报价读取权限可见。

历史图纸复用 API-097：从项目详情生成带 `projectId` 上下文及 assetVersionId 的下载入口，服务端确认项目范围及该版本属于其快照；方案管理员也可按方案资料权限访问。不能只检查提供了 projectId 而不核验关联。

### 9.2 API-065 分配承接

`PUT /api/v1/admin/projects/{projectId}/assignee`

请求：`requestKey, expectedRevision, assignee: {type: admin|partner, id}, reason`。

目标必须为有效、具备承接资格的管理员或伙伴用户。渠道项目仅可选归属伙伴或有权内部协助人，不能改派到其他渠道；公共项目可按授权改派。成功返回 `projectId, revision, assignee, attribution`，归属快照不变。无实际变化可返回当前修订，但仍校验预期修订和目标资格。

### 9.3 API-066 后台新增跟进/变更状态

`POST /api/v1/admin/projects/{projectId}/follow-ups`

基础字段同 API-024，增加 `visibility: internal|partner`（默认 internal），状态重开需 `reopenReason` 及专用权限。原状态由服务端读取，不接受客户端自报 fromStatus。

进入 quoted 时 `quoteEvidence` 二选一：

```json
{ "type": "platform", "quotationRevision": 2, "sentAt": "2026-09-24T10:00:00Z", "channel": "email" }
```

```json
{ "type": "external_manual", "reference": "伙伴线下人工报价编号/说明", "sentAt": "2026-09-24T10:00:00Z", "channel": "email" }
```

平台修订必须属于此项目、可导出、发送时仍在有效期内；记录该版本，不要求是目前最新草稿。伙伴只能使用 external_manual，避免探测内部报价。共享记录中平台证据只暴露授权摘要，不自动开放报价金额及文件。

进入 won 时 outcome 需包含非空结果摘要；lost/closed 需非空原因。追加记录与状态写入同一事务，成功响应同 API-024。

### 9.4 API-067 查看人工报价

`GET /api/v1/admin/projects/{projectId}/quotation?revision=2`

省略 revision 取当前修订；无报价返回 `200 {projectId, projectRevision, quotation: null}`。指定不存在的修订返回 404。

有报价返回 `projectId, projectRevision, quotation: {quotationId, quotationNo, revision, completeness, currency, currencyScale, roundingMode, priceBasis, items, totalAmount, validUntil, validityTimeZone, terms, inclusions, exclusions, createdAt}`。

条目返回服务端行金额；存在未填价时该行金额及总额为 null，附 `validationIssues`，不把部分合计显示为总价。

`PUT /api/v1/admin/projects/{projectId}/quotation`

```json

  "expectedRevision": 3,
  "expectedQuotationRevision": 0,
  "currency": "CNY",
  "priceBasis": "excluded",
  "validUntil": "2026-10-24",
  "validityTimeZone": "Asia/Shanghai",
  "items": [
    {
      "clientLineId": "line-1",
      "kind": "material",
      "bomItemId": "snapshot-item-example",

      "model": "MODEL-EXAMPLE",

      "quantity": "2.5",
      "pricingUnit": "m",
      "unitPrice": "100.00",
      "erpCode": "000123",
      "notes": ""
    }
  ],
```

首次 expectedQuotationRevision 为 0；后续须与当前报价一致。完整替换当前编辑内容但保留所有旧修订；clientLineId 在同一报价内唯一并用于对应差异，不能凭它引用其他项目行。

`kind` 建议 `material / graphic / transport / installation / other`。`bomItemId` 可省略；引用行与快照数量/规格/单位不同时补 `differenceReason`。请求不能提供 lineAmount、totalAmount、成本字段或任意公式。草稿可空价，但数量/单位和数值格式仍需合法；初步最多 10000 行，正文限额须与清单上限一起验证。

### 9.6 API-069 导出报价单

`GET /api/v1/admin/projects/{projectId}/quotation/download?revision=2`

revision 必填正整数。具备报价导出权限且修订 completeness=ready 时返回 `200` 文件流，建议 XLSX MIME 和支持中文的 `Content-Disposition`；格式最终见 FQ04。缺价返回 409 `QUOTATION_INCOMPLETE`；生成失败返回 JSON 错误，不返回空附件。

生成固定修订，响应前重新校验权限；新保存另一报价修订不使明确指定的历史下载失效。导出不改项目状态、不生成新报价修订。页面须展示下载的是历史还是当前版本。

### 9.7 API-070 关联人工处理方案

`PUT /api/v1/admin/projects/{projectId}/scheme`

请求：`requestKey, expectedRevision, schemeCode, bomRevision?, drawingRevision?, confirmationNote`。仅限 sourceType=manual_request、尚无 scheme、非终态；必须记录客户确认依据。

校验方案可用于此客户及资料可用性后，同一事务创建方案/清单/图纸快照并递增项目修订；原人工需求记录不覆盖。成功返回 `projectId, revision, schemeCode, bomRevision, drawingRevision, materialsStatus`。

不允许管理员在此随意指定某客户私有主题任务。后续需要补主题或更换方案时，应先明确客户确认和历史报价处理规则再扩展。

### 9.8 错误契约

沿用平台标准 `error.code`（VALIDATION_ERROR / REQUEST_ERROR / INTERNAL_ERROR），建议增加 `reason, fields, requestId`；细分 reason 是设计建议，实施时需适配现有处理器。

| HTTP | reason | 处理 |
|---|---|---|
| 400 | INVALID_INPUT | 字段、未知枚举、非法日期/金额错误 |
| 401 / 403 | AUTH_REQUIRED / ACCESS_DENIED | 登录或权限提示 |
| 404 | RESOURCE_NOT_FOUND | 对象不存在或不在调用方范围 |
| 409 | IDEMPOTENCY_CONFLICT | 同键异内容，不能当作重复成功 |
| 409 | PROJECT_REVISION_CHANGED / QUOTATION_REVISION_CHANGED | 刷新比较，不覆盖他人更新 |
| 409 | SCHEME_UNAVAILABLE / BOM_REVISION_CHANGED / DRAWING_REVISION_CHANGED / THEME_SELECTION_CHANGED | 更新方案资料并重新确认 |
| 409 | INVALID_STATUS_TRANSITION / QUOTATION_INCOMPLETE / SCHEME_ALREADY_LINKED | 显示业务前置条件 |
| 422 | INVALID_ASSIGNEE / QUOTATION_RULE_INVALID | 修正承接人或报价内容 |
| 429 | RATE_LIMITED | 依 Retry-After 重试，保留相同提交标识 |
| 503 | ASSIGNMENT_UNAVAILABLE / CUSTOMER_SERVICE_UNAVAILABLE / EXPORT_UNAVAILABLE | 可重试；客服/导出故障不能回滚已创建项目 |

无权对象检查优先于修订和状态细节，避免错误差异泄露他人项目信息。

## 11. 验收场景与交付顺序

| 编号 | 场景 | 预期证据 |
|---|---|---|
| F01 | 从详情/清单申请 | 正确方案和可选资料修订进入表单；点击入口不建项目 |
| F02 | 正常提交 | 一份申请、一份项目、明确承接人、不可变快照和一份通知事件同事务创建 |
| F03 | 并发同键、超时重发、异体同键 | 同体只建一次且回执一致；异体 409；不重复通知 |
| F04 | 提交与下架、清单/图纸修改、主题改选并发 | 固定同一有效快照或整单冲突，不能混合新旧资料 |
| F05 | 缺资料允许询价 | 明确 missing，无虚假核验状态；显式旧修订不能降级成缺资料 |
| F06 | 提交后更改方案、账户资料或最终效果 | 原项目内容和选定图不变，仍按权限读取 |
| F07 | 公共/渠道/停用伙伴/失效默认人 | 按规则承接；渠道不丢失；无兜底不创建悬空项目 |
| F08 | 改派及并发跟进 | 无权跨渠道改派被拒；陈旧修订冲突；公共旧伙伴失去访问 |
| F09 | 猜测他人项目、历史文件或生成结果 | 列表/详情/下载/客服上下文/错误均不泄露他人数据 |
| F10 | 无匹配人工需求与后续方案关联 | 初始允许无方案；确认后固定资料；重复关联和覆盖既有方案被拒 |
| F11 | 空价、零价、小数、多行舍入 | 空价不完整、零价有效；逐行舍入与总额按金标准一致；预算不影响单价 |
| F12 | 草稿保存、导出、实际发送 | 前两者不标已报价；人工发送记录绑定准确修订；历史报价不被新草稿覆盖 |
| F13 | 状态与伙伴线下报价 | 合法流转通过；非法终态写入拒绝；线下报价有说明，成交不创建支付 |
| F14 | 导出价格权限及文本注入 | 文件和页面金额一致；不含内部字段；用户文本不作为公式执行 |
| F15 | 客服项目身份和跨国场景 | 正确上下文、真人接收回复及翻译验证；未授权项目拒绝，模拟态明确 |
| F16 | 客服/通知/导出故障 | 项目仍可在后台查询，操作可恢复，不把副作用失败误报为项目未受理 |
| F17 | 历史图纸更新/缺失和下载权限 | 下载固定项目文件版本；缺失不替换最新；只有项目权限仍不足以越过资料授权 |
| F18 | 列表/跟进分页及内部备注 | 筛选总数均限制范围；伙伴分页不出现内部记录；授权字段不靠前端隐藏 |

建议按端到端顺序实施：

1. 申请 → 原子项目及快照 → 默认承接 → 后台列表/详情，先跑通 F01～07。
2. 分配、跟进、伙伴权限及人工需求关联，验证并发和跨账户隔离。
3. 人工报价保存/修订/导出，使用业务确认的多币种精度、税口径和空价样例验证。
4. 第三方客服与通知接入，完成真人对话及失败恢复验收。

实现沿用服务端薄路由、service/repository 分层、事务与 Outbox；对外部客服调用保持事务外执行。测试应覆盖数据库唯一约束/事务并发、接口权限、金额精度和导出真实内容，再做客户端到后台的人工闭环。本文仅完成设计文档，尚未执行业务实现与运行验收。
