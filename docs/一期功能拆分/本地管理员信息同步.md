# 本地管理员信息表与后台登录同步

后台登录使用已有接口 `https://api.lingtong.net.cn/api/auth/login?site=admin`。本服务单独维护 `admins` 表，记录成功登录管理后台的管理员信息；客户端和 SU 用户继续保存在 `users` 表。

接口与响应字段依据用户提供的地址和截图整理，未在线调用。表名、字段名及同步规则为开发设计，不代表已建表。

## 独立功能

| 编号 | 功能 | 完成行为 |
|---|---|---|
| ADM-01 | 首次后台登录创建管理员 | 通过已有后台登录和服务端管理员身份校验后，获取用户详情，创建本地管理员记录 |
| ADM-02 | 后台登录更新管理员 | 再次登录按 external_user_id 更新同一条 admins 记录及登录时间，并发或重复调用不产生重复记录 |
| ADM-03 | 管理员业务关联 | 后台权限、审核人、操作人和审计关联 admins.id；管理员登录不创建或更新 users 记录 |

## admins 表

| 字段 | 建议类型 / 约束 | 来源或用途 |
|---|---|---|
| `id` | BIGINT，主键 | 本地管理员 ID |
| `external_user_id` | BIGINT，非空、唯一 | 已有用户详情 data.id，作为跨系统关联键 |
| `username` | VARCHAR，非空 | data.username，可更新，不作为关联主键 |
| `nickname` | VARCHAR，可空 | data.nickname |
| `email` | VARCHAR，可空 | data.email |
| `mobile` | VARCHAR，可空 | data.mobile |
| `avatar_path` | VARCHAR，可空 | data.avatar.path，完整图片地址规则待确认 |
| `company` | VARCHAR，可空 | data.company |
| `language_code` | VARCHAR，可空 | data.fkLanguageCode |
| `external_enabled` | BOOLEAN，非空 | data.enabled，外部账号状态 |
| `external_roles` | JSON | 外部角色 ID/名称白名单快照 |
| `external_authorities` | JSON | 经服务端验证的已有登录响应中 data.data.authorities；不接受前端自报权限 |
| `last_login_at` | TIMESTAMP，非空 | 最近一次成功完成后台登录同步的本服务时间 |
| `last_synced_at` | TIMESTAMP，非空 | 最近一次资料同步成功的本服务时间 |
| `created_at` | TIMESTAMP，非空 | 本地记录创建时间 |
| `updated_at` | TIMESTAMP，非空 | 本地记录更新时间 |

不保存密码、密码散列、JWT、验证码内容或完整原始响应。本平台管理员权限独立维护，不被外部资料同步覆盖。

## 登录与同步

1. 后台调用已有 API-090：`/api/auth/login?site=admin`。请求字段包括 username、password；截图还显示 captcha=true，该字段的含义、必填规则及验证码流程需联调确认，不能据截图把它当作可固定绕过验证的参数。
2. 成功响应读取 data.JWT、data.data.id、data.data.username 以及角色信息；接口协议与客户端类似，但入口参数使用已确认的 site=admin，不附加未经确认的 lang 参数。
3. 调用本服务 API-088：`POST /api/v1/admin/auth/sync`。本服务验证现有凭据及管理员资格，按可信 username 获取 API-028 用户详情并核对外部用户 ID。
4. 以 external_user_id 原子 upsert admins，更新白名单资料和登录时间，返回 adminId、白名单资料与后台权限上下文。不能根据请求路径、浏览器提交的角色或 users 中已有记录授予管理员身份。
5. 后台权限和审核操作引用 admins.id；API-082 返回当前管理员身份与权限。外部角色到本平台权限的映射待确认，截图出现 ROLE_ADMIN 不代表已确定全部权限规则。

## 两张表的边界

- 同一统一账号如果既使用客户端又使用后台，可以在 users 和 admins 各有一条记录，external_user_id 相同；两表主键独立，不要求数值相同。
- 后台登录仅更新 admins；客户端/SU 登录仅更新 users。两边的登录时间、资料同步时间和本地权限分别维护。
- 客户项目、生成任务、积分和渠道归属关联 users；后台审核人、管理员授权关联 admins。销售管理员承接与伙伴用户承接须区分身份类型。
- 跨端跟进、承接和审计建议明确记录身份类型（user/admin）及对应记录 ID，避免把 admins.id 与 users.id 混用；角色也需区分适用对象。
- 普通用户查询 API-071/API-072 继续查询 users；它们不因新增管理员表而改为管理员目录。本次不额外扩展管理员增删页面。

## 更新与异常

外部资料明确返回空值时清空相应可空字段；缺失可选字段时保留旧值。凭据无效、身份不匹配、账号停用或无管理员资格时拒绝本次后台登录，不新建管理员记录；已有管理员的停用或角色撤销状态应同步，不保留可用后台权限。资料获取或写库失败时保留原记录，不更新成功登录时间，提示重试。

本次只更新需求和接口设计，不包含数据库迁移或代码实现。
