# 本地管理员信息同步详细设计

**版本：** v1.0  
**适用范围：** 管理后台端（`apps/admin`）管理人员与运营人员  
**关联接口：** `API-090`、`API-088`、`API-082`、`API-083`

---

## 1. 设计背景与定位

灵通 AI 展台方案平台的管理后台（`apps/admin`）**不自建本地管理员密码库**，管理员身份认证同样依托灵通统一 SSO 认证体系（`site=admin`），由平台服务端进行管理员资格验证和权限授权。

本地维护一张 `admins` 同步表，用于：
1. 记录后台管理员与外部统一账户的映射（`external_user_id`）。
2. 维护管理员在本平台的角色与权限（如：超级管理员、方案审核员、人工报价员、资源运营等）。
3. 记录管理后台的审核、发布、报价、配置变更等操作审计日志归属。

---

## 2. 数据库设计（`admins` 表）

```sql
CREATE TABLE IF NOT EXISTS admins (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    external_user_id VARCHAR(128) NOT NULL UNIQUE, -- 灵通统一 SSO 管理员 ID
    username VARCHAR(128) NOT NULL,                -- 统一管理员用户名
    real_name VARCHAR(128),                        -- 真实姓名
    avatar_url VARCHAR(512),                       -- 头像地址
    mobile VARCHAR(32),                            -- 联系电话
    email VARCHAR(128),                            -- 电子邮箱
    roles TEXT[] NOT NULL DEFAULT '{}',            -- 本平台角色列表，如: {'super_admin'}, {'auditor'}, {'quoter'}
    permissions TEXT[] NOT NULL DEFAULT '{}',      -- 细粒度权限编码
    status VARCHAR(32) NOT NULL DEFAULT 'active',  -- 状态: active(正常), disabled(停用)
    last_login_at TIMESTAMPTZ,                     -- 最近登录时间
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX IF NOT EXISTS idx_admins_external_id ON admins(external_user_id);
CREATE INDEX IF NOT EXISTS idx_admins_username ON admins(username);
CREATE INDEX IF NOT EXISTS idx_admins_status ON admins(status);
```

## 3. 同步与授权业务流程

### 3.1 后台登录与同步流程（`API-088`）

```
[管理后台前端 apps/admin]
  │
  ├─ 1. 提交统一后台凭据至灵通后台认证接口 (API-090: POST /api/auth/login?site=admin)
  │     └─ 外部认证通过，取得外部管理凭据
  │
  ├─ 2. 调用平台本地管理员同步接口 (API-088: POST /api/v1/admin/auth/sync)
  ▼
[平台服务端 apps/server]
  │
  ├─ 3. 校验外部凭据与管理员有效性。
  │
  ├─ 4. 检查本平台授权资格：
  │     - 查询 `admins` 表中是否存在且 `status = 'active'` 并且分配了有效角色。
  │     - 若外部认证通过但该账号未在平台分配管理角色，返回 403 Forbidden（无管理权限）。
  │
  ├─ 5. 原子更新 `admins` 基础资料（姓名、头像、联系方式）及 `last_login_at`。
  │
  ├─ 6. 颁发管理后台专用会话凭据（独立 Admin Token / Session）。
  │
  └─ 7. 返回 `adminId`、白名单资料、已分配的角色列表与权限清单。
```

### 3.2 权限获取（`API-082`）

* 管理后台进入或路由守卫时调用 `GET /api/v1/admin/me`（`API-082`）。
* 服务端返回当前管理员的最新资料、权限集、数据范围。
* 若管理员已被停用或角色被撤销，立即失效会话并要求重新登录。

---

## 4. 安全与隔离约束

1. **库表强隔离：** `admins` 与 `users` 是两张完全独立的表，主键 UUID 互不干扰；用户端 `users` 记录绝不能作为管理后台登录依据。
2. **严禁越权创建：** 普通用户不能通过调用 `POST /api/v1/admin/auth/sync` 将自己升级为管理员；初始管理员由系统初始化迁移脚本或超级管理员后台分配。
3. **数据脱敏与审计：** 后台登录不保存明文密码和散列；所有方案审核、资产操作、报价发布必须在审计日志中精确关联 `admins.id`。
