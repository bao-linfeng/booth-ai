## 5. 检索采集与数据模型

### 5.1 采集原则与一次检索的定义

**一次业务检索 = 一次用户明确提交的 attemptId；一次实际匹配执行 = 一个 searchId。** 客户端对自动重试复用 attemptId；用户主动“再搜一次”生成新 attemptId。同键同条件重试复用执行结果，避免统计翻倍；同键不同条件返回 409。幂等查询按身份/匿名上下文隔离，不允许查询其他访客结果。

- [ ] **D01** 服务端在 API-003 完成后生成可信结果快照：最终条件、直接/参考/随机数量、返回编号、规则版本、过滤原因、耗时、时间与会话身份；不采信前端 resultCount、matchedSchemeCodes、userId。
- [ ] **D02** 原规划 `POST /scheme-searches/log` 不作为结果流水的事实来源。本轮建议由服务端写流水，前端仅上报有必要的交互事件；确认后更新原路由设计。
- [ ] **D03** 解析未完成/用户未确认不计“已匹配搜索”；保存独立 attempt/解析诊断，能识别解析失败流失，不能伪造为零命中。
- [ ] **D04** 建立匿名标识采集和登录成功关联。同设备只代表同浏览器环境，不代表同一人；指纹不可用时可退化为第一方随机 visitorId，并在统计标记标识类型。
- [ ] **D05** 冻结浏览器指纹方案、保留周期和访问权限；IP 从可信代理配置后的请求上下文读取，User-Agent 来自请求头。指纹不是认证凭据，用户 ID 从服务端会话获取。
- [ ] **D06** 登录成功由服务端建立 visitorId ↔ userId 事件；不接受客户端任意绑定；旧匿名流水保留当时身份，不追溯篡改成“已登录检索”。
- [ ] **D07** 冻结原文/标识留存配置。建议原文与可识别明细 90 天、去标识聚合 365 天，均为待确认值；删除到期明细前先完成日聚合，记录可查询数据范围。
- [ ] **D08** 采集落库失败不将成功匹配改成空结果：返回 `analyticsRecorded=false`、安全告警和缺失计数。建议搜索记录允许少量丢失，不伪称“完全可靠”；若业务要求零丢失，评审可靠写入边界后再实现。
- [ ] **D09** 重试缓存/存储结果在重新返回前重验公开可见性；下架方案不能因幂等返回旧可选结果。可返回结果已失效，要求新 attemptId，不覆盖历史快照。

### 5.2 建议表结构（新增迁移，复用现有方案和用户表）

| 表/数据 | 关键字段 | 约束与用途 |
|---|---|---|
| `scheme_search_attempts` | id/attempt_key、匿名范围标识、user_id 可空、raw_query 可空、input_form、parse_status、parser/degraded、parse_ms、started_at、expires_at | 接住仅解析未匹配流程；唯一键含上下文；原文与日志分开受控读取 |

| 请求上下文字段 | visitor_id、identifier_type、user_id、login_state、request_id、受控 ip/ua | user_id 取本地 users.id；系统账号操作不得写入真实运营统计 |

索引：时间、身份+时间、user_id+时间、visitor_id+时间、status/mode+时间；结构化筛选先提取实际使用的维度，必要时 JSONB 索引；基于查询计划决定，不一次性给全部字段建索引。

## 7. 管理后台：统计分析 AP-21

### 7.1 指标口径（必须服务端统一计算）

默认日界线 `Asia/Shanghai`、数据库 UTC，时间范围 `[from,to)`；响应回传 timezone、from/to、generatedAt、完整性说明。成功 filtered 搜索 N 为默认业务分析样本，random 单列；error/未完成解析不进 N。

| 指标 | 定义 | 易错点 |
|---|---|---|
| 有效搜索次数 | 去重 attempt 后，API-003 成功返回 matched/no_match 的次数 N | needs_clarification 不算有效匹配；不按 HTTP 请求次数累加 |
| 结果命中率 | `total>0` 的搜索次数 / N | 有参考也算有结果，不等于直接采用 |
| 直接命中率 | `direct>0` 的搜索次数 / N | 不是 direct 返回条数 / 全部方案条数 |
| 零命中率 | `total=0 && status=no_match` 次数 / N | 数据库错误、429、解析失败不算零命中 |
| 仅参考率 | `direct=0 && reference>0` 次数 / N | 单独反映结构适配缺口 |
| 热门词 TopN | 规范化关键词按搜索去重计次数 | 单次同词只计一次；停用词/同义词版本化；无可提取词记“无关键词” |
| 零命中缺口排行 | no_match 的关键词及规范化条件组合频次 | 原因取实际过滤统计；不因一个零结果就断言某行业完全缺库 |
| 偏好分布 | 最终条件中行业/风格/预算/体系/面积/开口 | 多选各计一次，百分比分母为有该维度的搜索，合计可能超过 100% |
| 返回方案曝光 | 服务端返回某 code 的搜索次数 | 标为“返回次数”，不是用户真实看见/点击；真实曝光另需事件 |
| 活跃设备/用户 | 区间内 distinct visitorId / 已登录 userId | 身份无法采集者单列；不能把设备数叫人数；跨日 UV 重新去重 |
| 检索频次 | 每个设备/用户在区间内的搜索次数分桶 | 1、2～5、6～10、>10 为建议桶，图表显示边界 |
| 解析降级率 | degraded 的解析次数 / 实际调用解析次数 | 分母不是全部搜索；仅表单不调用解析 |
| 响应时间 | 有定义的执行样本 p50/p95/max、超时比例 | 浏览器点击至匹配返回和服务端耗时分别展示 |
| 登录转化率 | 见下文 cohort 定义 | 不能以当前登录人数 / 当前匿名次数替代 |

**登录转化建议口径**：选择期间内每个 visitorId 首次匿名有效搜索作为 cohort 起点，分母为这些唯一设备；分子为该起点后 24 小时内存在可信 login_success 的设备，单设备最多计一次。转化事件允许落在筛选结束之后；尚未满 24 小时标“观察中”，成熟 cohort 单独出率。此为设备登录转化，不等同新用户注册或询价成交。建议同时展示可归因设备覆盖率；无标识设备不虚构归因。

原规划的“单次选型时长、留存、注册转化”不能仅靠检索时间戳可靠计算：

- [ ] **A11** 如果纳入选型时长，补 sessionId、进入/活跃/退出或超时事件，冻结空闲阈值；否则明确显示“未采集”，不展示伪指标。
- [ ] **A12** 如果纳入留存，冻结 D1/D7 cohort、回访事件和标识可用范围；注册转化依赖外部 SSO 可信注册事件，不能用登录冒充注册。
