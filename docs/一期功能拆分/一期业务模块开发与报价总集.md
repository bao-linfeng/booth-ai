**版本：** v0.1（范围与估算评审稿）

**用途：** 范围确认、模块发包、分端排期、工期评估、报价及逐模块验收。  
**状态：** 根据需求与详细设计整理的待开发工作分解，不是现有代码完成度报告或已确认合同报价。

## 1. 使用口径与依据

### 1.1 阅读结论

一期拆为 **15 个业务/公共能力模块（W01～W15）+ 2 个项目公共工作包（W00、W16）**。客户端仍保留原有七大业务分组；方案基础维护与资产管理分开报价，W15 单列统一资产及四类独立管理页面。

- 每个模块包含所需的客户端 UI、客户端接口联调、后台 UI、后台接口联调、服务端和验收任务。
- **中小参展商是客户端主力用户；授权经销商/搭建商/设计师主要使用 SU。两类用户都来自统一注册账户，平台记录用户类型并据此做入口识别和提示。内部项目分配、跟进、报价与状态处理归管理后台；SU 资产文件由人工导入后台。**
- 一个接口只有一个主责模块；共享路由的业务分支由对应模块实现，公共入口不能重复计价。
- 可以按模块分别开发，但发布、资料核验、身份权限和项目快照存在明确依赖，不能把“独立模块”理解为互不依赖的系统。
- 当前接口总表基线：**客户端 27 + 管理后台 55 + SU 3 = 85 个拟开发接口，另复用 3 个企业账户接口**。API-022/023 改为提交人本人只读项目查询，API-024 客户端跟进取消；包含 W15 跨方案资产查询 API-098，其他未编号缺口尚未纳入。
- 人工报价与联系跟进构成一期成交闭环；成交记录不等于平台支付或下单。

## 2. 一期业务闭环

### 2.1 资产供给闭环

```text
历史方案/标准方案/经授权的 SU 新结构
  → 独立方案编号、母版关系、结构参数与标签（W03）
  → 先保存/导入零资产草稿（W03），再独立上传并关联模型/效果图（W15）+ 蒙版（W15/W07）
  → 已核验清单（W08）+ 报馆图（W09）+ 标准平面素材（W10）
  → 分项核验 → 六类资产检查 → 整体审核发布（W03）
  → 客户可检索/授权取用（W04、W08～W10）
  → 资料纠错、核验失效、下架、重新审核发布
```

**完成标准：** 后台能维护真实完整资产；缺件或未审核不能发布；资料更新不覆盖历史项目文件。设计人员制作和模型逐项核对属于真实人工工作，不用“上传成功”代替。

### 2.2 客户选型到成交闭环

```text
匿名描述需求 → AI 解析与条件修正 → 精确/参考方案 → 详情（W04）
  ├─ 使用原方案 → 授权查看清单/图纸/标准底图（W08～W10）
  ├─ 登录（W01）→ 积分确认（W05）→ 换主题、选最终效果（W07）
  │                                      └→ 按需生成四面素材（W11）
  └─ 无匹配 → 人工需求（允许无方案）（W12）
        ↓
报价申请/人工需求 → 固定资料、需求、来源和归属 → 明确承接人（W12）
  → 管理后台分配管理人员联系、人工补关联方案 → 人工填价与导出（W13）
  → 客服/约定渠道发送报价（W14）→ 记录报价依据和跟进（W12）
  → 成交 / 未成交 / 关闭，并记录结果或原因（W12）
```

**完成标准：** 客户有受理回执，后台有项目，责任人可看到并跟进，报价有固定修订，结果有记录；客服或通知故障不丢已受理项目。

### 2.3 用户类型与 SU 闭环

```text
用户类型标记（W02）
  → 伙伴类注册用户进入 SU → SU 修改结构
  → 人工导出新模型/清单/图纸/素材文件
  → 在管理后台手动导入各类资产（W08～W10）
  → 后台分项核验（W08～W10）→ 整体审核发布（W03）→ 管理后台继续跟进项目（W12）

SU 已有身份 → URL 携带统一 token → 网页验证 token 换取用户信息 → 建立本地会话（W01）
  → 网页/SU 共用积分（W05）→ 网页业务沿用客户端接口
```

**边界：** SU 结构修改、导出文件由 SU 人工完成，平台不自动接收导出包；资产导入复核走现有后台流程。项目已有方案的更换机制尚未冻结，不能用“补关联”接口覆盖已有方案来声称完成该场景。

## 4. 各模块分端任务、边界与验收

以下每个模块均可拆成 `Wxx-CU`（客户端 UI）、`Wxx-CI`（客户端联调）、`Wxx-AU`（后台 UI）、`Wxx-AI`（后台联调）、`Wxx-S`（服务端）、`Wxx-V`（验收）。没有对应页面的项明确记为不适用，不另行凑页面。

### W00 公共工程与接口契约

- **客户端 UI/联调：** 响应式布局、导航回退、公共加载/空态/异常态；请求层、身份失效处理、文件流下载与错误识别、请求追踪。
- **后台 UI/联调：** 接入现有后台框架，通用列表/表单/上传组件、权限菜单与路由、分页筛选、并发冲突提示。
- **服务端：** 统一成功/错误 Schema、ID/修订/幂等约定、迁移与种子规范；复用现有数据库、存储、API/Worker、Outbox 和队列基础，完善业务所需配置。
- **边界：** 只做各模块确实使用的公共基础。管理员自身的后台访问权限由 W01/后台公共工程负责；用户类型标记属 W02；资产生命周期属 W15、业务任务恢复属 W06，不重复实现通用平台。
- **验收：** 两端能调用真实 API 并正确处理 JSON/附件、401/403/409/503；接口契约能支持分端并行开发。

### W01 统一账户与平台会话

- **客户端 UI：** 登录表单、官网注册跳转、回跳提示、退出；SU token登录状态、刷新后的身份恢复。
- **客户端联调：** 企业登录 → 平台同步 → 本地会话；登录墙回原方案、不自动付费；SU URL token 验证与失效处理。
- **后台 UI/联调：** 企业后台登录、验证码按外部真实协议接入、管理员同步、权限上下文读取、退出与失效。
- **服务端：** 企业凭据可信验证；`users/admins` 分表同步；可失效平台会话；SU token 验证、users 表同步。
- **依赖/边界：** 依赖企业验签/验票协议；本地授权调用 W02，积分调用 W05；不建设注册密码库、订阅与充值。
- **验收：** 外部成功而同步失败不能放行；普通用户不能登录后台；网页/SU 同一用户；退出后受限接口拒绝。

### W02 用户类型与端入口

- **客户端 UI/联调：** 登录后读取用户类型；中小参展商提示进入客户端，伙伴类用户提示使用 SU，不新增伙伴工作台或伙伴项目页面。
- **后台 UI：** 已同步账户列表/详情展示用户类型标记；如需人工修正，只提供简单类型标记维护，不建设伙伴授权矩阵、渠道归属或审计页面。
- **后台联调：** 账户类型读取与保存；入口提示与统一账户/SU 会话状态一致。
- **服务端：** 在 `users` 中保存用户类型标记，并在客户端/SU 当前用户信息中返回；不由该标记推导项目、资料或后台权限。
- **边界：** 本模块只回答“这个注册用户主要使用客户端还是 SU”；具体资料下载、项目处理和后台管理员权限仍由各业务模块或后台基础能力负责。
- **验收：** 两类注册用户均能登录；用户类型可读取；客户端与 SU 给出对应入口提示；用户类型变化不会自动获得跨客户项目、渠道归属或后台操作权限。

### W03 方案库与审核发布

- **客户端：** 提供公开方案/资产摘要契约，详情 UI 与调用在 W04 实现。
- **后台 UI：** 方案列表、基础/结构/打标/关联编辑、JSON/XLSX 导入预览、字典、资产摘要与独立页跳转、六类完整性与审核面板。
- **后台联调：** 零资产草稿新增/修改、无文件导入确认、检查、审核、发布/下架、冲突恢复。
- **服务端：** 唯一编号与母版校验、受控字典、导入事务、就绪状态汇总、技术修订及整体发布事务。方案与资产一对多，文件名不自动生成资产或核验结果。
- **边界：** 文件及资产维护归 W15；蒙版、清单、图纸、素材业务核验分别由 W07～W10 提供。W03 负责汇总及最终发布，不替代分项核验；缺资产不阻止保存/导入草稿。
- **验收：** 打标“已核验”不能自动发布；六类资产缺一或审核过期拒绝；结构变更使用新编号；下架停止新匹配，历史项目原件保留。

### W04 AI 智选、方案详情与检索统计分析

- **客户端 UI：** 尺寸/开口面数/偏好表单、自然语言、解析来源与修正、最多三套结果、参考差异、详情三视角、无结果、模型下载及业务入口；前台检索行为与未登录指纹埋点。
- **客户端联调：** 字典 → 解析 → 匹配 → 详情；旧请求不覆盖新结果；前进后退恢复；特殊编号编码；转人工只交接上下文；异步上报检索行为与设备指纹。
- **后台 UI/联调：** 方案检索记录查询页（AP-20 / M8-01）支持多维组合筛选与明细抽屉；检索统计分析看板页（AP-21 / M8-02）支持热门词/0命中缺口/偏好排行、频次分布与登录转化分析。
- **服务端：** LLM 结构化解析与规则降级、条件覆盖/澄清、硬条件判定、参考候选及确定性排序、空输入随机、公开 DTO、授权模型下载；检索行为流水落库及统计聚合接口（API-099/100/101）。
- **边界：** 不生成新结构；不使用不合格方案凑三套；不承担 API-020 项目受理；阈值与预算边界待冻结；检索分析采用应用内统计，不外接庞大独立数仓。
- **验收：** 长宽/开口面数不符不判直接采用，已知超高不能作为参考；无结果可交人工；LLM 故障可解释降级；按原需求验证 ≤5 秒目标；检索记录可查且统计指标对账一致。

### W05 统一积分读取、预占结算与对账

- **客户端 UI/联调：** 可用余额、冻结/结算/释放状态与不足提示；余额组件共享，主题及四面页的费用确认交互由各自模块负责。
- **后台 UI/联调：** 用户积分流水及按任务检索、未完成操作状态；复用任务详情链接。
- **服务端：** 对接唯一权威账本、稳定操作号、原子预占/扣除/释放及查询、未完成操作恢复、网页/SU 并发一致性。
- **边界：** 不额外建立第二套余额；外部账本不支持预占时，需冻结等效原子扣费/退款协议。外部账本功能改造由其提供方单独报价。
- **验收：** 并发不透支、重放不重复扣、失败可释放、结算故障恢复不重生成；流水与余额来源一致。

### W06 生成任务公共服务、模型与模板运营

- **客户端：** 供 W07/W11 复用公共任务状态、轮询约定与安全预览能力；页面由消费者负责。

- **客户端 UI：** 报价申请、人工需求、回执；已登录提交人的本人项目列表/详情只读查询，资料冲突或失败保留表单。

- **验收：** 零资产方案可先建/导入，四个页面可分批上传关联同一方案；跨方案错误关联拒绝，失败重试不重复登记；缺件无法发布，替换不改变历史项目及报价文件。

## 7. 工期预估与报价口径

### 7.1 估算假设

下表是**依据设计复杂度给出的首轮预算区间，不是代码审计后的剩余工时**。1 人日按 8 小时计算，评估熟悉现有技术栈的开发人员；复用现有前后端框架及基础设施。未核验现有功能可复用程度，不能直接减去“已有页面”认定的工时。

- 客户端和后台列均包含对应 UI 实现与该端接口联调；合同细表再拆成 CU/CI/AU/AI，不能把联调另加一遍。
- 服务端包含数据库迁移、业务实现、外部适配及开发者自测；验收列包含模块专项验证、业务样例核对和一轮验收修正。W16 仅为跨模块上线验证。
- 范围按：一期响应式 Web、现有后台、已支持的固定样表、两个经验证图像提供商、一个 LLM、一个客服厂商；不含通用 ETL、任意模型接入或多套 UI 方案。
- 等待账号/协议/样包的时间不算开发人日，但必须算入日历工期。新增范围、外部系统改造和多轮需求返工另估。

### 7.3 可填写的正式报价行

每个工作包按以下结构复制填写，未冻结项注明基线和增量条件：

**计算：** 模块费用 = 各角色确认人日 × 对应日单价后求和；项目开发费 = W00～W16 模块费用之和。W15 独立报价，原方案及专项模块剥离公共资产费用。税费、项目管理/视觉设计是否含在日单价中须明确，未包含则独立列项，不能暗中重复加到模块内。

**风险预留：** 可按双方确认比例单列，或包含在最终固定报价中；采用人日区间上限报价时，应说明是否已吸收同类风险，避免上限与全额风险金双重计算。

**日历排期：** 按客户端、后台、服务端、验收各角色的有效产能和依赖排期，取资源瓶颈及关键路径；总人日除以团队人数只能作粗算，不能代替排期。正式报价应同时给出人数、投入比例、外部等待时间和批次验收时间。

## 9. 模块交付与总体验收清单

### 9.1 每个模块完成的共同条件

1. 对应 CU/CI/AU/AI/S/V 任务完成或明确不适用；界面不是仅静态演示。
2. 服务端鉴权、DTO、数据库迁移、错误状态、并发/幂等和文件契约满足该模块设计。
3. 客户端、后台均使用真实接口完成本模块闭环；第三方能力有真实联调证据。
4. 关联模块可消费其输出；只返回 ID 而下游不能使用不算交付。
5. 模块测试与类型/构建检查通过，提交对应场景的验收记录；人工结构/图像质量由指定业务角色确认。
6. 代码、接口文档、迁移、配置说明、样例和未决问题清单同步交付。
