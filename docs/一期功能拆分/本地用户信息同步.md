# 本地用户信息表与登录同步

本服务维护一张 `users` 表，保存已登录客户端/SU 用户的资料；后台管理员另存 admins 表，见[本地管理员信息同步](本地管理员信息同步.md)。账号注册、密码认证仍由灵通已有服务负责；本表用于本平台业务关联和资料读取，不承担密码认证。表名与字段名为本次建议设计。

## 独立功能

| 编号 | 功能 | 完成行为 |
|---|---|---|
| U-01 | 首次登录创建用户 | 验证已有登录凭据，由服务端获取用户详情，按统一用户 ID 创建本地记录 |
| U-02 | 再次登录更新用户 | 同一用户登录客户端或以 SU 身份进入本服务时，更新同一条记录的资料和登录时间，不重复创建 |
| U-03 | 本地业务关联用户 | 项目、生成任务、积分账本、用户侧权限和审计通过本地 `users.id` 关联用户；后台账户查询读取本地已同步用户，不视为官网全量用户目录 |

## users 表

| 字段 | 建议类型 / 约束 | 来源或用途 |
|---|---|---|
| `id` | BIGINT，主键 | 本服务用户 ID，业务外键引用它 |
| `external_user_id` | BIGINT，非空、唯一 | 已有用户详情 `data.id`；客户端与 SU 共用此关联键；后台 admins 表独立关联同一外部 ID |
| `username` | VARCHAR，非空 | `data.username`；可以更新，不作为跨系统关联主键 |
| `nickname` | VARCHAR，可空 | `data.nickname` |
| `email` | VARCHAR，可空 | `data.email` |
| `mobile` | VARCHAR，可空 | `data.mobile`，供联系信息预填 |
| `avatar_path` | VARCHAR，可空 | `data.avatar.path`；保留路径，不猜测完整图片地址 |
| `company` | VARCHAR，可空 | `data.company` |
| `country` | VARCHAR，可空 | `data.country` |
| `city` | VARCHAR，可空 | `data.city` |
| `language_code` | VARCHAR，可空 | `data.fkLanguageCode` |
| `external_enabled` | BOOLEAN，非空 | `data.enabled`；记录统一账户状态 |
| `external_roles` | JSON | `data.roles` 中的角色 ID/名称白名单快照；不保存整个原始响应 |
| `last_login_at` | TIMESTAMP，非空 | 本服务最近一次成功完成登录同步的时间 |
| `last_login_source` | VARCHAR，非空 | `client` / `su`，由接收接口确定 |
| `last_synced_at` | TIMESTAMP，非空 | 最近一次成功更新资料的本服务时间 |
| `created_at` | TIMESTAMP，非空 | 本地记录创建时间，仅首次写入 |
| `updated_at` | TIMESTAMP，非空 | 本地记录最近更新时间 |

不保存密码、密码散列、JWT 或完整原始响应。积分余额、渠道归属、本平台角色授权由各自业务维护，登录同步不得覆盖；外部角色快照不直接等于后台授权。

## 同步流程

1. 客户端调用已有登录 API-026。SU 插件打开网页时 URL 携带统一认证 token。
2. 调用对应端的登录同步接口（API-087 / API-089）。客户端接收用户名密码凭据，SU 端接收 URL 中的统一 token；两者均不接收可任意指定的用户 ID、角色或完整用户资料作为可信输入。
3. 本服务验证凭据或 token，确定当前统一身份及 username，再调用已有用户详情 API-028；核对详情中的 `data.id` 与已验证身份一致。JWT/token 校验及请求鉴权协议沿用既有服务，尚待联调确认，不能仅解码 token 就信任身份。
4. 以 `external_user_id` 执行原子 upsert：不存在则插入；存在则更新白名单资料。并发或重复调用受唯一约束保护，只产生一条用户记录。
5. 写入登录来源、登录时间、同步时间；SU 另校验插件操作权限；后台同步单独使用 admins 表。资料同步成功不代表获得所有业务权限。
6. 返回本地用户 ID、白名单资料和同步结果，后续业务关联本地用户。

建议每次新登录或 SU 新建立本服务访问上下文时执行同步，不在每一次业务请求中重复同步。SU token 验证（API-089）已完成同步逻辑；前端不必再次调用客户端同步接口（API-087）。

## 更新与异常规则

- 外部详情明确返回空字符串或 null 的可空字段，同步清空本地值；字段缺失时保留旧值，避免部分响应擦除资料。身份 ID、username、enabled 等必要字段缺失视为无效详情。
- 身份不匹配、凭据无效时拒绝同步。已停用账户不得建立可用业务会话；已存在记录可同步更新 `external_enabled=false`。
- 资料获取或数据库写入失败时，保留原记录、不更新成功同步时间，返回“登录信息同步失败，可重试”；首次登录不能留下半条用户记录。建议本次本服务登录待同步成功后再完成，不把外部登录成功等同于本服务登录完成。
- 不向已有账号服务回写资料；用户修改官网资料后，在下一次登录本服务时刷新。旧项目已提交的联系方式等业务快照不随用户资料同步改写。
