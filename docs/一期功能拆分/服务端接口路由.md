# 服务端接口路由

登录和用户详情复用用户指定的已有接口；其余是根据功能需求拟定的接口，不代表仓库已有实现或原文已规定路由。接口按实际调用方分为客户端、管理后台、SU 三组，表内列出完整路由。每行是一项服务端接口任务；三端可以复用内部业务服务，但分别使用各自的接口入口与权限校验。

权限简称：公开＝无需登录；本人＝当前账户及其私有对象；资料授权＝按角色和方案授权；伙伴＝仅归属项目；后台＝对应操作权限及数据范围。后台路径本身不构成授权，服务端必须校验权限。`{code}` 是唯一方案编号，路径中须 URL 编码（真实编号可能包含 `&` 等字符）。

列表接口支持分页及该功能所需筛选。下面只定义关键输入和输出，不展开完整字段 Schema。文件下载接口返回受控下载结果，不暴露内部存储地址。批量下载建议打包 ZIP，保留原文件名。异步生成接口返回任务编号，查询返回等待/处理中/成功/失败及结果；具体状态英文值在实现前统一。

| 调用端 | 路由前缀 | 范围 |
|---|---|---|
| 客户端 | `/api/v1/client` | 七个业务模块，含公开与伙伴网页，共 28 个拟开发接口，另复用下述已有账户接口 |
| 管理后台 | `/api/v1/admin` | 后台会话、数据维护、审核、项目及权限管理，共 52 个拟开发接口，另复用下述已有账户接口 |
| SU 插件 | `/api/v1/su` | 插件身份、统一积分、网页登录票据、导出提交与状态，共 6 个接口 |

保留原接口编号以便追踪。API-026、API-028 改为已有外部接口；API-025 本地注册、API-081 后台密码登录取消，不复用其编号。现有清单含 86 个拟开发接口和 3 个复用接口；注册跳转不计为 API。统一账户不代表三端权限相同。

### 已有响应字段使用

| 来源 | 字段路径 | 使用方式 |
|---|---|---|
| 登录响应 | `success`、`code`、`msg` | 截图成功值为 `true`、字符串 `"200"` 及成功消息；失败格式待联调，不能只凭 HTTP 成功判断已登录 |
| 登录响应 | `data.JWT` | 大小写按现有字段读取；用于后续鉴权，具体请求头/前缀尚未提供，不擅自规定为 Bearer |
| 登录响应 | `data.data.id`、`data.data.username` | 识别统一用户；客户端/SU 的 users.external_user_id、后台 admins.external_user_id 分别关联已有用户 ID；各端业务引用对应本地主键，不新增密码认证体系 |
| 登录响应 | `data.data.roles`、`data.data.authorities` | 已有角色信息；平台权限映射由后台校验，不能仅信任浏览器传入的角色 |
| 用户详情 | `data.id`、`data.username`、`data.nickname`、`data.email`、`data.enabled` | 获取个人信息与账户状态，按所需字段读取 |
| 用户详情 | `data.avatar`、`data.avatar.path` | 获取头像资料；完整图片地址的组装规则待确认，不直接假定目录路径就是图片 URL |
| 用户详情 | `data.company`、`data.country`、`data.city` | 可用于报价/客服信息预填，用户仍可核对修改 |
| 用户详情 | `data.roles` | 为后台授权映射提供身份信息，不等于本平台完整的权限矩阵 |

截图中的用户详情含 `password` 字段（密码散列），平台不得展示、持久化或透传该字段；只保留业务所需字段。文档不保存示例密码、JWT、密码散列或个人资料值。用户详情未提供积分余额字段，积分接口继续单独保留，不把 `isVip` 或折扣字段解释成积分。

### 接入边界

- 客户端使用 `site=client&lang=zh`（API-026）；后台使用用户已确认的 `site=admin`（API-090），不自行增加 lang 参数；SU 沿用已有登录态，不猜测 site=su。
- 客户端/SU 登录同步 `users` 表，见[本地用户信息同步](本地用户信息同步.md)；后台登录同步独立 `admins` 表，见[本地管理员信息同步](本地管理员信息同步.md)。API-087/API-089 更新 users，API-088 更新 admins，均由服务端获取已有详情，不接收用户名密码进行认证。
- 已有接口负责账号密码认证与基础用户资料。后台 API-082、SU API-084 只负责本平台入口上下文与操作权限，不另建用户资料接口。
- 既有 JWT 的服务端校验方式、有效期、刷新/注销、用户详情请求鉴权、跨域和 Content-Type 待联调确认；截图不能证明这些能力已就绪，也不能证明允许查询任意其他用户。
- API-027/API-086 的 SU 网页票据，以及 API-030/API-083 的平台会话退出仍是建议设计，需与已有鉴权机制对齐；清理平台会话不等于撤销统一账号 JWT。
