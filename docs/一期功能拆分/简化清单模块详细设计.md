**日期：** 2026-09-24  
**范围：** 客户端 C3-01～C3-03、后台 M3-01～M3-05、清单导入/核验/导出服务，以及方案发布和报价交接。

### 1.2 已确定边界

1. 使用已人工核对的方案清单，平台不让 AI 生成材料数量，也不从效果图反推数量。
2. 方案编号贯穿模型、清单、图纸、素材及项目；结构变体使用独立编号，不覆盖原结构方案。
3. 网页展示六个非价格字段；客户 XLSX 固定八列，价格由客服提供。清单不等于报价单。
4. 品牌/主题视觉调整不改变结构清单；新增制作、服务或品牌物料需求进入人工报价确认，不自动追加到结构清单。
5. 清单页提供申请报价入口，复用报价模块；不新增点击埋点式业务接口、自动报价、支付或积分扣费流程。
6. 源 XLSM 只用于提取和核对，不执行宏、不直接作为客户下载文件。

### 1.3 本稿建议及冲突处理

| 事项 | 建议口径 |
|---|---|
| Q05：公式与空价格 | 单价单元格真正为空；总价保留受控公式，单价为空时显示空。若业务要求总价也完全无公式，须统一改成纯空白导出 |
| 数量含义 | 八列中的数量统一为该行的计价数量，单位由说明页逐行明确；长度/面积已是汇总值时不重复乘件数。需与 SU 实际样例确认 |
| 编辑后可见性 | 修改清单条目后，使清单核验失效，并在同一事务内下架方案；模型资产变化仍需按方案资产审核规则处理发布状态，但不重置清单核验 |
| 技术修订 | 保存防并发覆盖的 revision 和审计快照，不设计面向用户的方案版本树；历史项目固定已提交清单快照 |
| 资料权限 | 沿用 Q07；清单查看和下载分别校验授权，是否允许匿名访问尚未冻结，不默认登录即拥有所有资料 |

## 2. 客户端详细功能

### 2.1 C3-01 查看材料清单

入口：方案详情的“简化清单”，或选定主题后的资料区。以路由中的 `schemeCode` 为唯一结构上下文，不以列表下标或主题图片名称定位。

- 页头：方案编号、清单核验提示、单位说明入口、下载清单、申请报价。
- 表格：序号、产品名称、产品型号、尺寸规格(mm)、数量、ERP编码；数量旁标注单位，列数仍为六列。
- 不渲染单价/总价占位列，也不请求包含内部价格的后台接口；价格字段由服务端白名单排除。
- 默认保留核验后的行序，不按 ERP 自动合并。同型号不同规格、位置或计量规则的行可以同时存在。
- 型号、ERP 编码按文本展示，保留前导零；规格为展示文本，不在浏览器解析成计量依据。
- 建议初版一次取得受限规模内的完整清单，长表可客户端分页；下载始终包含全部条目，不仅当前页。
- 切换方案时清空旧清单并取消或忽略旧请求响应；不得在新方案页残留上一个方案的清单。

| 页面状态 | 行为 |
|---|---|
| 加载中 | 表格骨架，下载暂不可用 |
| 可用 | 展示已核验条目及单位说明，允许授权下载 |
| 未登录且需要身份 | 登录后回到相同方案与清单入口 |
| 无资料权限 | 显示权限提示，不把内部条目或存储地址带到浏览器 |
| 已知方案暂无可用清单 | 明示“清单暂不可用”，关闭下载；方案仍可询价时保留申请报价入口 |
| 数据发生变化 | 提示刷新，用户确认后重新载入，不偷偷下载另一修订 |
| 请求失败 | 提供重试，不能将失败显示为空清单成功 |

### 2.2 C3-02 下载简化清单

1. 使用查看响应的 `revision` 发起下载，服务端再次校验方案状态、权限和清单核验。
2. 当前修订变化返回冲突，客户端刷新并再次确认下载。
3. 成功以附件保存 `{方案编号}@简化清单.xlsx`；真实编号保持不变，例如 `TW66_BK_044_F&B`，请求路径按段 URL 编码。
4. 文件名遇操作系统非法字符可安全替换，仅影响下载名；正文和 API 中的真实方案编号不得改写。
5. 初版建议直接返回受控文件流；已生成文件缓存也必须经过本接口鉴权，不向客户端提供永久公共地址。

### 2.3 C3-03 申请报价

- 按钮跳转报价表单，不在点击时自动创建项目。
- 携带 `schemeCode`、页面已读取的 `bomRevision`，以及可选的本人 `themeJobId + resultId + selectionRevision`。
- 提交复用 API-019；服务端重新确认方案、清单修订及主题归属，不能相信客户端上传的材料行或核验状态。
- 有可用清单时，项目保存该修订的不可变条目和单位快照；后续后台纠错不改变历史项目。
- 用户携带的清单修订已失效时返回 409，要求刷新确认。尚无清单但方案允许人工承接时，可以不传 `bomRevision`，项目记录“待补清单”；不得伪造空清单已核验。
- 未提供修订而当前有清单时，服务端固定提交时的有效快照。报价是否允许匿名提交仍按 Q07 确认。

## 3. 管理后台详细功能

### 3.1 页面组成与权限

在方案详情中设置“简化清单”页签：源文件及导入预览、当前条目、计量规则、核验记录、客户清单下载。

操作权限分为清单查看、导入/编辑、核验、方案发布；均绑定后台 `admins` 身份及数据范围。源文件可能含成本和内部价格，源文件读取还需独立的内部资料权限。API-057 只提供客户空价文件，不复用为源文件下载。

### 3.2 M3-01 导入与替换

1. 先选定已存在方案，上传 XLSM/XLSX，通过 API-051 得到预览和 `importId`。
2. 服务端检验文件真实格式、压缩展开限制、工作表及字段映射；不执行宏、外部链接、源公式或嵌入对象。
3. 首期采用按已确认样表配置的固定提取映射，不做通用拖拽 ETL 工具。工作表名称、表头行、数据范围、合计行识别须在真实样例对齐后冻结。
4. 预览显示源工作表/行号、映射后的条目、单位规则来源、价格已忽略提示、逐字段错误及警告。
5. 业务列含公式时只读取文件已有缓存结果并标记来源；缺失、错误或类型不符则阻断提交，要求在可信桌面软件中重新计算保存或提供纯值表。缓存值可能陈旧，仍需人工源数据核对。
6. 文件内有方案编号且与路径不符时拒绝；未含编号时提示管理员显式确认归属。不能单凭文件名自动判断正确方案。
7. 完整预览通过并确认警告后调用 API-052，一次原子替换全部当前条目，不做部分有效行导入。没有提交前不改变现有清单和发布状态。
8. 提交后进入 `pending_verification`，记录源文件哈希、提取映射修订、操作者、时间和导入操作说明（由服务端写入审计，无须管理员填写）。已发布方案同步下架。
9. 相同 `importId` 的重复提交返回第一次提交结果，不再次替换；预览过期则要求重新上传。建议预览保留 24 小时，最终期限待运维确认。

### 3.3 M3-02 维护条目

- 编辑产品名称、型号、规格、数量、ERP 编码、计量类型及规则引用；序号按提交顺序生成连续正整数。
- 完整集合保存使用 `expectedRevision`，冲突时保留本地修改供比较，不自动覆盖他人更新。
- 数量使用十进制字符串传输；建议数量大于零、个数为整数，长度和面积允许小数。退料负数、零数量占位不纳入客户清单，若实际样例需要则另行确认。
- 产品名称、数量、计量规则必填；型号、规格、ERP 缺失列为警告，是否禁止核验由业务确认，不能自动补“未知”或虚构编码。
- 不按产品名称或 ERP 静默去重，不凭规格字符串重算数量。
- 人工修正必须填写原因，保留原提取值。核验记录要说明源差异是已认可纠错还是待解决问题，不能把修正后的值称为与源文件完全一致。
- 不在此页面录入销售价格；人工报价在 M6 维护。原文件中的价格不进入客户清单条目模型。

### 3.4 M3-03 计量与单位规则

每行明确 `measurementKind`（`count / length / area`）、源数量、源单位、计价单位和换算方式。API-055 一次保存方案内规则集合，事务内重算受影响数量、递增清单修订并使核验失效。

| 类型 | 示例源数量 | 换算示例 | 客户数量/计价单位 |
|---|---|---|---|
| 个数 | 4 个 | ×1 | 4 个 |
| 长度 | 合计 2500 mm | ÷1000 | 2.5 m |
| 面积 | 合计 1200000 mm² | ÷1000000 | 1.2 m² |

这些是单位示例，不代表所有材料均按米或平方米计价。长度来源必须是已核对总长度，面积来源必须是已核对总面积；只有单件尺寸和件数的表格，需样表映射明确计算字段并与 SU 对齐后才支持提取，不能从自由文本猜算。

- 单位换算使用维度匹配的服务端白名单，禁止管理员提交任意可执行公式。不能直接将“个”乘一个常数解释成“平方米”。
- 建议十进制精确计算，数量最多 6 位小数；超出精度时阻断确认或采用与 SU 一致的明确舍入规则，不能静默截断。
- 单价定义为“每计价单位价格”，导出总价直接 `数量 × 单价`，不再额外乘尺寸或件数。
- 已被条目引用的规则不能删除；规则更新必须校验全部引用，不允许留下无单位条目。

### 3.5 M3-04 清单核验

核验面板针对当前方案的清单修订，只选择通过或不通过。通过时不要求逐项勾选或绑定 SKP；不通过时必须填写核验意见。核验记录保留清单修订、内容哈希、结论及操作人，原有历史模型核验信息仍可留作审计。

1. **提取一致性**：源行与提取行对应、漏行和重复行、数值与 ERP 保真；人工修正有已认可的差异说明。
2. **模型逐项核对**：型号、规格、数量与对应 SKP 一致，此项由技术人员完成，系统不声称自动证明完整。
3. **配套项确认**：必要连接件、支撑件及配套项已检查，遗漏不能仅靠“源表一致”放行。
4. **单位一致性**：个数/长度/面积口径及换算与 SU 一致，样例和核对依据可追溯。

核验和内容更新并发时，版本不一致拒绝核验。清单内容变更使清单核验失效；模型资产更换不单独改变清单核验状态。上述四项是人工制作方案库时可参考的核对内容，不作为提交时的独立确认字段。

核验通过为 `verified`，只使清单成为可发布条件之一；仍由 API-043/044 完成方案整体审核和发布。打标表“已核验”不能替代本次绑定到具体内容的证据。是否要求录入者与核验者不同，列评审项。

### 3.6 M3-05 导出客户清单

后台从当前 `verified` 清单生成与客户端相同的八列空价文件，可用于发布前验收；未核验只提供后台结构化预览，API-057 不输出正式客户文件。客户文件不包含成本、内部价或人工报价。

## 4. 服务端流程与一致性

### 4.1 清单状态

| 状态 | 含义 | 客户端当前清单下载 |
|---|---|---|
| `absent` | 无已提交清单（派生状态） | 不允许 |
| `pending_verification` | 首次提交或修改后待核验 | 不允许 |
| `rejected` | 最近一次核验不通过 | 不允许 |
| `verified` | 当前内容、规则、模型绑定已核验 | 仍须方案发布及资料授权 |

预览状态独立为 `ready / invalid / committed / expired`。一期建议受限文件同步解析，超时返回失败且保留旧清单，不创建只有 ID 却无法查询的异步任务；若实测需要异步导入，另补查询契约后评审。

### 4.2 事务边界

- 导入预览和文件解析在数据库事务外执行；对象存储上传不持有数据库行锁。
- 提交、条目修改、单位规则修改、核验均锁定同一清单记录并比较 `expectedRevision`；所有会影响清单的模型替换沿用同一锁定顺序。
- 内容变更原子完成：新条目/规则、修订递增、旧核验失效、方案下架、审计记录。并发发布需在事务内重查相同修订的核验，不得“先检查后无条件发布”。
- 首次不存在清单时以 `expectedRevision: 0` 表示创建预期，通过方案级锁及唯一约束防止同时创建两份。
- 核验状态变化也递增 revision；审核记录绑定被审核内容及产生的核验修订。重发核验用 `requestKey`，同键同内容返回原结果，同键异内容 409；幂等查重优先于修订检查。
- 导入提交先按 `importId` 查提交结果，再比较修订；这样网络重发不会将已成功操作误报为失败。
- 文件生成固定已经读取的不可变内容快照，完成后再次确认当前修订与授权才开始响应；操作在该检查点生效，不承诺撤回用户已经下载的文件。

### 4.3 导出规则

从白名单结构化数据新建 XLSX，不能复制源工作簿再隐藏价格列。客户工作簿固定：

**工作表“简化清单”**：A1:H1 为 `序号｜产品名称｜产品型号｜尺寸规格(mm)｜数量｜单价｜总价｜ERP编码`，第二行开始数据。方案编号放在“说明”页及文件名，不挤占表头或新增第九列。

- A/E 列为数值；B/C/D/H 列强制文本，保留 ERP 前导零、长编码及原规格。
- F 列为空；G2 示例受控公式为 `IF(F2="","",E2*F2)`，后续按行生成。未填价时显示空，填 0 时显示 0，不把 0 当作未填。
- 建议对 F 列设置非负数输入验证；文本价格由电子表格显示错误，不能自动当 0。是否统一保留两位金额小数及舍入方式待报价/SU 口径确认，示例公式不提前 ROUND。
- 设置打开后重算；空价文件的公式缓存不得写为 0，需验证 Excel/WPS 实际打开行为。纯空白方案与公式方案最终二选一，不按客户端随机变化。
- 不增加混合单位的“数量合计”，不提供自动预报价总额。

**工作表“说明”**：真实方案编号、清单修订、核验时间、条目序号与计量/计价单位及换算说明、价格由客服提供、结构清单适用范围。只使用客户可见字段，不包含后台人员个人信息或内部审核备注。

文本值即使以 `= / + / - / @` 开头也必须以文本单元格写入，不能被识别成源公式。仅服务端生成的 G 列公式可执行。新文件不得含宏、隐藏源表、外链、源批注、嵌入对象或内部价格；不能依赖前端隐藏保障保密。

### 4.4 缓存与历史引用

- 缓存键至少包括 `schemeId + revision + exportTemplateRevision + customerAudience`，缓存内容必须已去内部信息。
- 客户端响应建议 `Cache-Control: private, no-store`；服务端每次下载先鉴权再访问文件缓存。
- 模型/清单变化即时阻止当前公开取用；历史项目持有的快照不覆盖、不级联删除，访问沿用项目权限。
- 历史项目不通过当前方案下载接口猜测旧文件；其交付入口在项目模块中定义。本稿只要求 API-019 固定快照，不新增历史版本浏览接口。

## 5. 逻辑数据模型

以下为实现建议，实际迁移需与现有方案/资产模型对齐，不表示数据库已经存在这些表。

| 实体 | 关键字段与约束 |
|---|---|
| `scheme_boms` | `id, scheme_id UNIQUE, revision, status, source_asset_id, content_hash, verified_at`；历史模型绑定字段由迁移移除 |
| `scheme_bom_items` | `id, bom_id, ordinal, product_name, product_model, specification_mm, source_quantity, source_unit, quantity, unit_rule_id, erp_code, source_sheet, source_row`；`(bom_id, ordinal)` 唯一 |
| `scheme_bom_unit_rules` | `id, bom_id, measurement_kind, source_unit, pricing_unit, conversion_code`；受控换算及修订说明 |
| `bom_imports` | `id, scheme_id, created_by_admin_id, source_asset_id, source_hash, mapping_revision, base_revision, preview, errors, warnings, expires_at, committed_revision` |
| `bom_verifications` | `id, bom_id, request_key, request_hash, content_revision, resulting_revision, content_hash, decision, notes, admin_id, created_at`；旧记录中的模型与逐项确认字段保留历史值，新记录不再填写 |
| 项目清单快照 | `project_id, scheme_id/code, bom_revision, content_hash, items, unit_rules, verified_at`；与项目申请在同一事务创建，复用项目已有快照机制即可 |

数量数据库使用精确十进制类型，API 用十进制字符串；字符串长度和数值上限在样表验证后冻结。源文件留在受限对象存储，清单行不持久化内部单价/总价。源资产和项目快照的保留期限待确认，不能删除仍被审计或项目引用的对象。

## 6. 客户端接口契约

沿用 API-009、010、019，不新增路由。以下 JSON 是建议业务结构；鉴权沿用已有账户接入，不能据此假定外部 JWT 的请求头协议已完成联调。

### 6.1 API-009 查看清单

`GET /api/v1/client/schemes/{code}/bill-of-materials`

前置：方案对调用方可见、资料读取授权通过，当前清单已核验。成功 `200`：

```json
{
  "schemeCode": "TW66_BK_044_F&B",
  "revision": 7,
  "status": "verified",
  "verifiedAt": "2026-09-24T08:00:00Z",
  "items": [
    {
      "id": "item-example",
      "ordinal": 1,
      "productName": "示例型材",
      "productModel": "MODEL-EXAMPLE",
      "specificationMm": "按核验清单",
      "quantity": "2.5",
      "erpCode": "000123",
      "unitRuleId": "rule-length"
    }
  ],
  "unitRules": [
    {
      "id": "rule-length",
      "measurementKind": "length",
      "sourceUnit": "mm",
      "pricingUnit": "m",
      "conversionDescription": "已核对总长度由毫米换算为米，除以1000"
    }
  ]
}
```

示例条目和时间只演示字段，不是该真实编号的实际材料数据。响应不得出现 `unitPrice / totalPrice / costPrice`、源文件地址、内部备注或其他用户项目内容。方案可见但当前清单不可用返回 409 `BOM_NOT_AVAILABLE`；对象不可见返回统一 404，不泄露内部状态。

### 6.2 API-010 下载清单

`GET /api/v1/client/schemes/{code}/bill-of-materials/download?revision=7`

- `revision` 必填，正整数；与当前已核验修订不一致返回 409 `BOM_REVISION_CHANGED`。
- 成功 `200`，`Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，`Content-Disposition: attachment`，兼容中文的 `filename*`。
- 不以 `200` 返回 JSON 错误或空文件；生成失败返回标准 JSON 错误，客户端先检查状态和类型再保存。
- 返回二进制，非 `{url}` 包装；存储内部地址不暴露给浏览器。

### 6.3 API-019 报价交接补充

保持既有报价申请字段与 `requestKey`，增加可选正整数 `bomRevision`。同用户/访客范围下重复请求的身份策略由报价模块冻结；相同请求重发返回同一项目。若包含 `bomRevision`，在创建项目事务内读取、验证并固定对应当前有效清单；冲突不创建半成品项目。返回保持 `quoteRequestId + projectId`，可附服务端固定的 `bomRevision`，无清单则为 `null`。

## 7. 管理后台接口契约

共同约定：方案编号按路径段编码；预览对象必须属于该方案及当前管理员可操作范围；写接口拒绝未知业务字段，`expectedRevision` 是防覆盖校验，不是用户可选择的历史方案版本。

### 7.1 API-051 上传预览

`POST /api/v1/admin/schemes/{code}/bill-of-materials/imports`

- `multipart/form-data`：`file`（一份 XLSM/XLSX）、`expectedRevision`（整数文本，首次为 0）。提取映射由服务器依据已支持样表识别；无法唯一识别时返回明确错误。
- 成功 `201`：`importId, schemeCode, baseRevision, expiresAt, status, sourceFileName, sourceHash, mappingRevision, items, unitRules, errors, warnings, canCommit`。
- `errors/warnings` 每项包含 `code, sheet, row, field, message`；预览中的字段为清单白名单，不回传原表价格。
- 可读取文件但数据不合格时返回 `201 + status: invalid + canCommit: false`；不是上传成功即数据合格。损坏、加密或不支持格式返回 422/415，无可提交预览。
- 初步建议上限：上传 20 MiB、展开 100 MiB、10000 条有效行；总单元格、工作表数、压缩比和解析时间另设资源限制，须实际样例压测确认。需专用上传配置，不沿用普通 JSON 请求体限制。

### 7.2 API-052 确认导入

`POST /api/v1/admin/schemes/{code}/bill-of-materials/imports/{importId}/commit`

```json
{
  "expectedRevision": 7
}
```

要求 `expectedRevision` 等于预览 `baseRevision` 且仍为当前修订；警告在预览展示但无须勾选确认，阻断错误不能通过提交绕过。成功 `200` 返回 `schemeCode, revision, status: pending_verification, itemCount, unpublished`。同一预览重复提交返回首次结果；异内容重发 409 `IDEMPOTENCY_CONFLICT`；过期 410 `IMPORT_EXPIRED`。

### 7.3 API-053 后台查看

`GET /api/v1/admin/schemes/{code}/bill-of-materials`

成功 `200` 返回 `schemeCode, revision, status, items, unitRules, source, latestVerification`。无清单为 `revision: 0, status: absent, items: [], unitRules: []`，与不存在方案的 404 区分。

条目比客户端增加源行、源数量、已认可差异说明；`source` 只含授权可见的资产 ID、名称、哈希、提取时间，不返回存储地址。此模块不保存价格；未来若关联内部价格，其字段权限仍须单独校验，不能直接扩散到客户 DTO。

### 7.4 API-054 修正完整条目集合

`PUT /api/v1/admin/schemes/{code}/bill-of-materials/items`

请求：`expectedRevision, changeReason, items[]`。每行传已有 `id` 或新增时省略、`productName, productModel, specificationMm, sourceQuantity, unitRuleId, erpCode` 及可选差异说明。顺序即序号，最终 `quantity` 由服务端按已确认规则计算，不同时接受相互矛盾的两份数量。

要求已有清单和规则；空集合拒绝。客户端不可提交别的清单条目 ID，重复 ID 拒绝。成功 `200` 返回新 `revision, status, items, unpublished`。保存会使核验失效；恢复旧内容也需重新核验。完全相同内容的 PUT 可返回当前结果不递增，但仍先检查预期修订。

### 7.5 API-055 保存计量规则

`PUT /api/v1/admin/schemes/{code}/bill-of-materials/unit-rules`

请求：`expectedRevision, changeReason, unitRules[]`。规则字段为 `id`（新增可省略）、`measurementKind, sourceUnit, pricingUnit, conversionCode`；不接受任意公式脚本。服务端校验维度、引用及精度后事务内更新规则、重算条目数量并使核验失效。成功 `200` 返回新 `revision, status, unitRules, items, unpublished`。无法换算时整个请求失败，不保存部分规则。

### 7.6 API-056 提交核验

`POST /api/v1/admin/schemes/{code}/bill-of-materials/verifications`

```json
{
  "requestKey": "verification-example-001",
  "expectedRevision": 8,
  "decision": "pass"
}
```

`decision: pass / reject`；不通过时还须传非空 `notes`（核验意见），通过时无需意见。服务端计算当前清单内容哈希；不接收逐项勾选或模型资产 ID。成功 `201` 返回 `verificationId, revision, status, verifiedAt`；不通过时 `verifiedAt: null`。幂等重发 `200` 返回原记录，不再次审核，也不把旧结果应用到新内容。

### 7.7 API-057 后台客户版下载

`GET /api/v1/admin/schemes/{code}/bill-of-materials/download?revision=9`

当前清单必须 `verified`，不要求方案已公开发布；其余文件格式、空价规则和冲突处理与 API-010 相同。该接口不是源 XLSM 或人工报价单下载。

### 7.8 错误契约

沿用平台标准 `error.code`，建议扩展 `error.reason`、字段错误和请求追踪 ID。现有错误处理器是否支持这些细分需在实施时适配，不视为已具备。

| HTTP | reason 示例 | 客户端/后台处理 |
|---|---|---|
| 400 | `INVALID_INPUT` | 标记缺失/非法字段 |
| 401 / 403 | `AUTH_REQUIRED / ACCESS_DENIED` | 登录或权限提示 |
| 404 | `RESOURCE_NOT_FOUND` | 对象不存在或不可见，避免跨方案探测 |
| 409 | `BOM_REVISION_CHANGED / BOM_NOT_AVAILABLE` | 刷新确认或等待核验，不自动强制保存 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同标识异请求，不能当作重复成功 |
| 410 | `IMPORT_EXPIRED` | 重新上传预览 |
| 413 / 415 | `FILE_TOO_LARGE / UNSUPPORTED_FILE_TYPE` | 更换符合限制的文件 |
| 422 | `INVALID_WORKBOOK / UNIT_RULE_INVALID / VERIFICATION_INCOMPLETE` | 显示具体行/字段及核验问题 |
| 503 | `EXPORT_UNAVAILABLE` | 可重试，不返回空文件冒充成功 |

错误不返回源文件全文、内部价格、堆栈或对象存储凭据。

## 8. 模块交接与实施约束

| 对接模块 | 交接要求 |
|---|---|
| AI 智选/方案库 | API-042 使用真实清单状态检查完整性；API-044 重查清单、模型绑定和整体审核，不能仅依赖导入标记 |
| 品牌/主题 | 仍读原结构 `schemeCode` 清单；主题失败或改选不改条目，不使材料核验失效 |
| 报价/项目 | API-019 固定清单快照；M6 人工报价与客户空价清单分别保存，不覆盖彼此 |
| SU 导出复核 | 结构变化创建新方案；API-058/062 接收的清单沿用提取、单位与核验规则，不能因插件提交直接视为已核验 |
| 资产管理 | 清单走 API-051～057 专用入口；替换模型使核验失效并下架；源文件不能通过普通资产下载泄漏 |
| 审计与权限 | 查看/导出/修改/核验分别授权；记录对象、修订、管理员及原因，不记录完整价格源表或凭据 |

采用现有服务端框架的薄路由、业务 service/repository 分层；工作簿读写先检查实际包依赖并选择维护中的成熟库，本文不指定尚未核验的库版本，也不实现自制 XLSX 解析器。清单导出不依赖图像模型、不引入独立生成积分任务。

## 9. 验收场景

| 编号 | 场景 | 预期证据 |
|---|---|---|
| B01 | 已核验方案在线查看 | 六个业务列正确；响应、DOM 均不含价格；方案编号与资料一致 |
| B02 | XLSX 导出 | 八列名称/顺序固定，全部条目齐全，说明页单位明确 |
| B03 | 空价、填 0、填正价 | 初始价格显示空；0 价总价为 0；填价后数量×单价正确，Excel/WPS 分别验收 |
| B04 | 个数/长度/面积 | 与 SU 提供的同一基准样例逐行一致，无重复乘件数或二次换算 |
| B05 | ERP 前导零、长编码、文本公式前缀 | 导入、预览、网页、重新打开导出文件均不丢失文本或执行源文本 |
| B06 | 源表含宏、隐藏价格表、外链 | 宏不执行；客户新建文件不包含这些内容；只读数值缓存需人工复核 |
| B07 | 缺少公式缓存、坏文件、压缩炸弹、超限行 | 拒绝或标记不可提交，不覆盖现有清单，不导致解析进程无限占用 |
| B08 | 源编号错误、其他方案 importId/itemId | 拒绝跨方案引用，不把另一方案清单替换进来 |
| B09 | 预览后其他人修改；重复 commit | 前者冲突且不丢数据，后者返回第一次结果，不重复替换 |
| B10 | 修改清单/单位/模型与发布并发 | 原子失效并下架，过期核验不能发布；无短暂窗口暴露未核验资料 |
| B11 | 核验通过但整体资产不完整 | 清单 verified 不等于方案发布成功 |
| B12 | 修改后下载、旧 revision 下载 | 当前客户取用被阻止或返回修订冲突，不静默换成其他清单 |
| B13 | 未授权查看/导出及源文件访问 | 服务端拒绝，缓存不能绕过鉴权，内部源文件不泄漏 |
| B14 | 主题改选和 SU 结构变更 | 主题仍引用原清单；结构变更使用独立编号及新核验 |
| B15 | 报价提交后修正当前清单 | 旧项目条目/单位不变，新申请使用新核验数据；过期显式修订提交冲突 |
| B16 | 缺清单但允许人工询价 | 下载不可用，可正常形成待补清单项目，不伪造核验记录 |
| B17 | 客户快速切换方案、下载失败 | 不显示旧响应；JSON 错误不会被保存成 .xlsx |

实施验证需包含：服务层精度/并发/权限测试、导入真实 XLSM/XLSX 样例、导出文件结构检查、Excel/WPS 手工填价以及与 SU 的金标准逐行比对。自动化解析一致不能代替技术人员模型逐项核验。本次仅文档交付，尚未执行这些业务验收。
