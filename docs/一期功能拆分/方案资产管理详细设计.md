# 方案资产管理详细设计

**状态：** 已确认方案与资产为一对多、四类图片独立管理、先创建/导入方案再上传资产；本文为开发与验收约定，不代表已实现。

## 1. 模型与存储

- `schemes` 与 `scheme_assets` 为一对多；草稿方案可以有零条资产，每条正式资产必须归属一套已存在的方案，`scheme_id` 为非空外键。不建立跨方案多对多素材库。
- 六类资产共用 `scheme_assets`，不按页面拆四张文件表。类型统一使用 `type`：`model`、`checklist`、`rendering`、`mask`、`drawing`、`artwork`。
- 已实现的公共/用户资产边界使用 `source`、`owner_user_id`、`visibility`；公共方案维护、发布、选型、下载与询价基线统一读取 `scheme_baseline_assets` 视图，用户生成结果通过任务与用户归属读取。迁移与历史引用保护见 [方案资产边界](../asset-scope.md)。
- 逻辑资产字段：`id`、`scheme_id`、`type`、名称、排序、`related_asset_id`、创建/更新时间。蒙版通过 `related_asset_id` 关联同方案的效果图，服务端校验类型、归属及一一配对；文件名仅辅助导入识别。
- 文件替换保留逻辑 `assetId`，新增不可变 `asset_versions` 记录（`id`、`asset_id`、`object_key`、原文件名、MIME、字节数、校验和、像素尺寸/页数、创建时间）。历史项目固定 `assetVersionId`，不按当前文件解析。现有详细设计中在资产行描述的文件属性由当前文件版本提供。
- 图纸视向、素材物理尺寸、清单画面映射、分项核验等仍由对应模块维护；素材与清单画面用稳定 ID 关联，名称作为核对项。
- 文件存于本地 Silo 的 `booth-assets` Bucket，沿用 `schemes/{方案编码}/` 分类目录。文件版本在分类目录内使用唯一对象 Key，不覆盖同名旧对象；下载保留原始文件名。数据库不保存临时签名 URL。
- 普通资产编辑不允许跨方案改归属；传入其他方案的 assetId、配对效果图或清单项须拒绝。资产业务删除移除当前集合成员并保留历史引用，不级联删除项目文件。

## 2. 独立管理路由

| 页面编号 | 页面 | 前端路由 | 类型 | 业务核验主责 |
|---|---|---|---|---|
| AP-22 | 效果图管理 | `/assets/renderings` | rendering | W15 |
| AP-23 | 蒙版图管理 | `/assets/masks` | mask | W07 |
| AP-24 | 报馆图素材管理 | `/assets/venue-materials` | drawing | W09 |
| AP-25 | 素材图管理 | `/assets/artworks` | artwork | W10 |

AP-20/21（方案检索记录与统计分析）已正式纳入一期开发主页面；四个资产页面保持 AP-22～AP-25 独立路由不变。四个页面均支持跨方案分页列表、方案编号/名称与核验状态筛选、选择方案上传、预览、替换、删除及排序。上传/编辑使用页内抽屉，不另计详情页。

方案详情集中显示六类资产数量、预览、核验状态及缺项，并携带方案筛选跳转独立页面，不重复建设四套编辑器。模型与简化清单保留原工作区，复用公共文件能力。

## 3. 先建方案，再补资产

1. 手工创建或通过 JSON/XLSX 导入方案基础信息及打标数据，成功后得到方案 ID/编码，状态为草稿；零资产不阻止保存。
2. 打标导入中的配套清单文件名只是待匹配提示，不自动创建资产或认定清单已核验。源表“已核验”不替代平台分项审核。
3. 在独立资产页面选定已存在的方案，单独或分批上传文件；从方案详情跳转时预选该方案。清单仍走专门导入/核验接口。
4. 文件写入 Silo 成功且元数据登记成功才返回资产上传成功。失败保留方案草稿，可重试；同一幂等请求不能重复登记，未登记文件由清理机制回收。
5. 草稿允许缺件、未配对或待核验，页面展示待补项；文件格式、方案归属、错误关联在保存时校验。蒙版正式关联须已有对应效果图；分项审核检查本类条件，整体审核通过及发布必须满足六类完整性。
6. 发布事务重新校验效果图/蒙版各 3 张、效果图 16:9、配对尺寸一致，以及模型、已核验清单、图纸视向和素材映射等要求。缺件不允许发布，不进入客户端匹配。
7. 已发布方案的资产替换/删除使受影响核验失效并原子下架，复核后重新发布；历史项目和报价资料仍引用原文件版本。

## 4. 接口分工

- API-033、035、036 仅负责方案创建/导入，不要求随请求提交文件；空资产不算导入错误。
- 新增 API-098：`GET /api/v1/admin/assets`，支持 `type`、`schemeCode`、`schemeName`、核验状态与分页；只返回授权数据范围内的资产摘要、方案标识、当前版本及操作能力，不返回凭据或内部地址。
- API-039 为单方案资产汇总；API-040/041/096/097 继续负责所选方案下的上传、编辑/替换、删除、受控预览/下载。独立前端路由不重复创建四套服务端 CRUD。
- API-096/097 补齐 rendering/mask 分支及其归属、核验失效和历史保护规则；drawing/artwork 沿用专项契约。模型复用公共能力，清单仍由 API-051～057 管理。
- API-042/043/044 负责完整性、审核、发布。`scheme_id` 非空及配对同方案约束须由服务端保证，不能仅靠前端下拉框。

## 5. 报价与验收边界

- W03：方案基础资料、打标导入、资产摘要与跳转、整体审核发布。
- W15：统一资产/文件版本、Silo 上传与关联、跨方案查询、公共预览下载、四类独立管理页面及其通用操作、效果图规则。
- W07/W09/W10：分别负责蒙版对齐、图纸视向及模型绑定、素材尺寸及清单映射等专项交互与核验；嵌入对应独立页，只计算专项增量。
- W08：清单解析、条目、核验与导出；W12/W13：项目/报价固定资产版本并读取，不承担公共素材维护，不重复计上传费用。
- 开发报价须将 W15 独立列项，并从 W03/W07/W09/W10 原资产维护预算中剥离公共部分；拆分后的新工时待评估，不能在原合计上直接叠加。

验收至少覆盖：零资产手工建草稿；零资产批量导入；四个独立页面筛选及分批上传关联；非法跨方案配对被拒绝；缺件保存成功但发布失败；补齐审核后可发布；上传失败重试不重复登记；替换或删除后下架且历史项目/报价版本不变。
