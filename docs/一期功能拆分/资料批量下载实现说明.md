# 资料批量下载（D-04 / E-06）

## 入口与范围

方案详情页的“三视图”和“平面素材”列表顶部提供“下载全部”。仅在资料列表加载成功且非空时展示；处理期间禁止重复下载。返回 ZIP，包内使用单张下载的原文件名，不加入模型、清单、mask、历史版本或带 `themeJobId` / `artworkJobId` 的私有任务资产。

压缩包名称为 `{方案编号}@报馆图素材.zip` 或 `{方案编号}@平面素材.zip`。方案编号中的文件系统非法字符仅在 ZIP 附件名中替换；包内原件不会自动改名。

## 接口

资料列表保持原有路径：

- `GET /api/v1/client/schemes/{code}/drawings`
- `GET /api/v1/client/schemes/{code}/artworks`

`data` 新增 `revision`：64 位小写十六进制集合指纹，绑定方案编号、资料类型、当前资产元数据和最新不可变文件版本。它不是数字修订，也不要求数据库迁移。

批量下载路径：

- `GET /api/v1/client/schemes/{code}/drawings/download?revision={revision}`
- `GET /api/v1/client/schemes/{code}/artworks/download?revision={revision}`

`code` 按 URL 路径分段编码；`revision` 必填。成功返回 `application/zip`、支持中文名的 `Content-Disposition` 和 `Cache-Control: no-store`。沿用现有已发布方案公开资料访问规则。

## 完整性与失败

服务端在存储读取前固定当前类型的完整集合（包含缺少版本或空版本的活动资产），校验文件名和重复名，再逐件读取原件并核对字节数及 SHA-256。全部成功后生成 ZIP，发送前重查发布状态和集合指纹。整个过程不持有数据库锁，不创建生成任务、不扣积分。

同步打包上限为 **30 个文件 / 原件总计 50 MiB**，限制常量在 `apps/server/src/modules/assets/deliverables.ts`。存储读取同时按每件声明字节数限制响应体，防止实际对象超限。ZIP 使用 STORE，避免图片/PDF 二次压缩的额外 CPU 开销。

| 状态 | HTTP | 客户端行为 |
|---|---|---|
| 修订缺失或格式无效 | 400 | 拒绝请求 |
| 空集合 | 404 / `DELIVERABLES_NOT_FOUND` | 不返回空 ZIP |
| 方案不存在或已下架 | 404 | 清除旧列表，提示刷新页面 |
| 集合发生变化 | 409 / `DELIVERABLE_REVISION_CHANGED` | 刷新列表，要求用户确认后重新点击 |
| 缺版本、空文件或校验元数据不完整 | 409 / `DELIVERABLES_INCOMPLETE` | 提示工作人员补齐 |
| 文件名不合法或规范化后重名 | 409 / `DELIVERABLE_FILENAME_INVALID`、`DELIVERABLE_FILENAME_CONFLICT` | 提示修正原文件名，不自动改名 |
| 超过同步打包上限 | 413 / `DELIVERABLE_ARCHIVE_TOO_LARGE` | 提示逐张下载或人工交接 |
| 存储读取失败、原件丢失、字节数或哈希不符 | 503 | 整包失败，允许重试，无部分成功 ZIP |

## 验证

- `apps/server/tests/client-scheme-assets.test.ts`：实际解压两个接口的 ZIP，核对中文/空格文件名和二进制内容；验证类型隔离、重复下载、修订失效、缺件、重名、非法名称、超限、读取/完整性失败以及打包期间资料变更或下架。
- `apps/server/tests/storage.test.ts`：使用本地 HTTP S3 响应验证二进制读取、Content-Length 超限、分块实际超限和对象不存在。
- 后端 `npm run check`、`npm test`；前端 `pnpm build`。
