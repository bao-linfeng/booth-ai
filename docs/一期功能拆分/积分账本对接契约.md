> 本文件原描述的外部接口提案不再执行，保留仅供历史参考。

---

本契约用于客户端自选 Gemini / 通义万相后，按后台配置的单图整数积分收费。**企业已有积分系统为唯一权威账本**；网页与 SU 共用用户 ID 和可用余额。本平台不得用本地余额模拟扣费。

## 必须由企业积分服务提供的服务端接口

建议由企业用户系统提供 `/internal/v1/credits` 服务；以下路径和字段是待双方确认的**接口提案**，不是已存在的接口。所有接口须为服务对服务认证（服务账号令牌或双向 TLS）；凭据仅在 API/Worker 环境中保存，不传浏览器。金额单位为非负整数积分，不支持浮点。调用者以稳定的企业用户 ID（SSO 同步的 `externalUserId`）和不可重复 `operationId` 标识操作。同一 `operationId` 相同请求重试必须返回相同结果，不同请求复用应返回 409。

| 操作 | 输入 | 输出及约束 |
|---|---|---|
| `GET /internal/v1/credits/users/{externalUserId}/balance` | URL 用户 ID | `availableCredits`、`heldCredits`、`updatedAt`，不可从本地资料或用户等级推算 |
| `POST /internal/v1/credits/reservations` | `externalUserId`、`jobId`、`operationId=jobId:reserve`、`amount=n×unitCredits` | 原子校验余额并预占，返回 `reservationId`；不足返回稳定码 `INSUFFICIENT_CREDITS`，不得仅先查余额后写冻结 |
| `POST /internal/v1/credits/reservations/{reservationId}/capture` | `externalUserId`、`jobId`、`operationId=jobId:capture`、`amount=k×unitCredits` | 从同笔预占结算交付成功的 k 张图；结算幂等，不能超过预占 |
| `POST /internal/v1/credits/reservations/{reservationId}/release` | `externalUserId`、`jobId`、`operationId=jobId:release`、`amount=(n-k)×unitCredits` | 释放失败部分；全失败全部释放；不得重复释放 |
| `GET /internal/v1/credits/operations/{operationId}` | URL 操作 ID | 返回账本权威状态、金额、关联预占 ID；用于超时和响应丢失恢复，不因超时自动推断操作结果 |

所有写接口返回 `{ operationId, reservationId, status, amount, availableCredits, heldCredits }`，`status` 取 `pending / succeeded / rejected`。同一预占中的 `capture + release` 金额之和必须等于原始 `reserve` 金额；状态可查询，调用方不依赖异步回调的送达顺序。只有 `reserve` 明确成功才可提交生成。账本应在自身事务中检查账户与余额、写操作去重记录并更新余额；锁/唯一约束保护 SU 与网页并发消费。定义稳定错误码 `INSUFFICIENT_CREDITS`、`USER_NOT_FOUND`、`OPERATION_CONFLICT`、`RESERVATION_NOT_FOUND` 和 `LEDGER_UNAVAILABLE`，不得回传内部堆栈或凭据。

服务需定义鉴权方式、超时、限流、幂等保存时长（至少覆盖最长任务恢复窗口）、操作状态、用户不存在/禁用、错误码及账本故障恢复 SLA。发布前需通过网页/SU 同时预占、超时响应丢失、部分成功、全部失败及服务重启恢复测试。

## 本平台的收费时序

1. 后台只允许配置固定供应商适配器及每张图的积分；客户端获取启用模型列表并自选，不能自行传费率。
2. API 基于所选模型、配置修订、资产/蒙版和请求张数签发短期费用 `offerId`；客户端明示最高消费并确认。创建请求携带 `modelProvider`、`offerId` 和稳定 `requestKey`。
3. 新任务先持久化 `pending` 与积分操作意图。仅当权威账本确认预占后，事务内置 `queued` 并写生成 Outbox。积分不足或账本未知时**绝不调用图像服务**。
4. Worker 从 S3 读取原图和已审核蒙版，适配模型输入；结果需保存到私有 S3 并校验蒙版外区域未改变，才计入 k 张交付。主备切换不能跨用户已选择的模型收费；变更价格或模型时重新确认。
5. 按成功张数结算，失败部分释放。余额及流水均从企业积分账本读取。对每个不确定操作用 `GET operation` 恢复后才推进状态；超时不推断成功/失败。

当前仓库无企业积分服务的上述接口、费率与真实蒙版质量样本；在契约确认和联调前，客户端仅展示后台配置的模型和费用，付费生成按钮保持不可提交，避免无预占调用付费 API 或虚构扣费。
