> 整理日期：2026-09-26  
> 用途：需求评审、开发拆分、接口联调及验收。  
> 状态：依据当前工作区需求文档及代码整理；下列业务功能和接口均待开发，不代表已经实现。接口字段是关键契约摘要，不替代实施时的完整 Schema。

## 1. 范围与结论

本文将“资源模块”对应到已有设计中的“方案资产管理”，统一采用资产类型 `model / checklist / rendering / mask / drawing / artwork`。

| 范围 | 包含内容 | 交付边界 |
|---|---|---|
| 方案模块 | 方案列表、创建编辑、结构化打标、母版/变体、批量导入、字典、完整性、审核、发布下架 | 维护方案业务信息及整体可用状态 |
| 公共资源模块 | 六类资产的统一归属与文件版本；上传、替换、查询、预览下载、删除、排序 | 效果图、蒙版、报馆图、平面素材四个独立页面，共用一套资产接口 |
| 专项资源规则 | 蒙版配对、图纸视向与模型绑定、平面素材画面映射与尺寸复核 | 嵌入独立资源页面，不重复建设公共上传与文件系统 |
| 清单专项 | 清单导入、条目、单位规则、核验及客户版导出 | 属于六类资源之一，但走专用业务接口，不用普通附件上传替代 |
| 相邻依赖 | 后台身份与权限、客户端资料读取、匹配、项目历史引用 | 列出交接要求；不将完整 AI 生成、报价和账号模块算入本次主体工作量 |

**核心流程：创建/导入方案草稿 → 分批补充资产 → 分项核验 → 整体审核 → 发布 → 后续修改失效下架 → 复核后重新发布。**

核心约束：

1. 方案与资产一对多，正式资产必须归属已存在的方案；不建立跨方案共享的多对多素材库。
2. 零资产允许保存、批量导入为草稿；缺件阻止整体审核通过和发布，不阻止方案建档。
3. 方案详情提供资产汇总与跳转，四类图片在独立页面维护；模型和清单保留详情工作区。
4. 替换文件保留 `assetId`，生成新 `assetVersionId`，不能覆盖旧对象；项目及报价固定不可变版本。
5. 核验状态、审核结果和发布状态分开管理；导入表写“已核验”不能代替平台核验。
6. 结构/功能变体用独立编号和新资料；纯品牌/主题变化不修改结构模型、材料数量或报馆图。

## 3. 服务端接口清单

### 3.1 公共约定

- 以下管理接口统一前缀为 `/api/v1/admin`，表格为节省篇幅列相对路径；例如 `/schemes` 的完整路径是 `/api/v1/admin/schemes`。
- `{code}` 为业务方案编号，须 URL 编码；`assetId` 是逻辑资产，`assetVersionId` 是不可变文件版本，不可混用。
- 全部接口校验后台会话、具体操作权限和数据范围；`capabilities` 只指导 UI，服务端每次独立鉴权。
- 列表提供分页和筛选；分页参数名、排序白名单、响应包装在实现时统一，不把本稿建议字段当成已存在接口。
- 写入采用预期修订防覆盖。图纸使用 `expectedDrawingRevision`，素材使用 `expectedArtworkRevision`，清单使用 `expectedRevision`；方案及效果图/蒙版修订字段需进一步统一。
- 已规定的写操作使用 `requestKey`：同键同内容返回首次结果，同键不同内容冲突；上传摘要包含服务端文件哈希。其他写接口的幂等契约需一并冻结。
- 文件流接口与 JSON 接口分开建模。文件响应支持正确 MIME、中文原文件名和受控缓存，不在数据库保存临时签名 URL。
- 冲突、非法文件、权限不足、存储失败须有可识别响应；现有错误格式仅有通用 code，细分业务原因及 HTTP 状态需要补齐 Schema，不能假定已经实现。

### 3.2 方案基础与字典：8 个接口

| API | 方法 | 相对路径 | 关键输入 | 输出及服务端行为 |
|---|---|---|---|---|
| API-031 | GET | `/schemes` | 编号/名称、空间、标签、核验/发布状态、分页 | 授权范围内方案列表及状态；也用于资产上传选方案 |
| API-032 | GET | `/schemes/{code}` | 方案编号 | 基础字段、补充条件、母版/变体及主题品牌关联、审核摘要、`schemeRevision` |
| API-033 | POST | `/schemes` | 唯一编号、名称、来源及元数据 | 新建草稿及标识；不要求文件 |
| API-034 | PATCH | `/schemes/{code}` | 打标/关联修改、预期修订（字段待冻结） | 校验并保存；必要时失效下架；不允许直接改发布/核验结论 |
| API-035 | POST | `/scheme-imports` | 打标 XLSX 或 JSON | `importId`、新增/重复/有效行、逐行错误；不写正式方案 |
| API-036 | POST | `/scheme-imports/{importId}/commit` | 选定有效行、明确的既有编号处理策略 | 重验唯一性和关联，返回新增/更新/失败结果；不自动发布 |
| API-037 | GET | `/catalog-options` | 所需分类，具体参数待冻结 | 后台字典及引用情况 |
| API-038 | PUT | `/catalog-options/{type}` | 某类完整字典集合 | 校验并保存，保护既有引用 |

打标导入须支持 JSON 顶层“方案打标”记录；忽略只有序号的空行。方案导入允许选择有效记录，清单导入则要求整个清单通过，两种提交语义不可混用。

### 3.3 公共资源：6 个接口

| API | 方法 | 相对路径 | 关键输入 | 输出及服务端行为 |
|---|---|---|---|---|
| API-098 | GET | `/assets` | `type`、`schemeCode`、`schemeName`、核验状态、分页 | 跨方案资产摘要、所属方案、当前文件版本、操作能力 |
| API-039 | GET | `/schemes/{code}/assets` | 可选类型 | 单方案六类资产/专项集合，当前版本、关联、顺序、核验状态及修订 |
| API-040 | POST | `/schemes/{code}/assets` | multipart 文件、类型、名称、排序、专项字段、幂等键及专项预期修订 | 上传并关联到既有方案，返回 `assetId`、`assetVersionId` 和新修订；清单除外 |
| API-041 | PATCH | `/schemes/{code}/assets/{assetId}` | JSON 元数据或 multipart 替换文件，修订、原因及专项字段 | 禁止跨方案/跨类型修改；替换保留资产 ID 并生成新版本；按规则失效下架 |
| API-096 | DELETE | `/schemes/{code}/assets/{assetId}` | 对应预期修订、`requestKey`、`changeReason` | 移除当前成员并返回新修订，保护历史文件与引用 |
| API-097 | GET | `/schemes/{code}/assets/{assetId}/download` | `assetVersionId`、`disposition=attachment/preview`，图纸预览可带 `page` | 返回授权原件/预览流；允许有权管理员核查未发布及历史版本 |

API-096/097 已有详细设计覆盖 drawing/artwork，并要求扩展 rendering/mask。model 的后台下载与删除分支、清单内部源文件的读取入口尚未完整冻结，不能将“通用接口”理解为任意类型天然可用。

#### 类型分支需要补齐的契约

| 分支 | 上传/编辑关键字段 | 服务端检查 |
|---|---|---|
| rendering | 名称、排序、文件；并发令牌待统一 | 实际图像、比例及像素；替换后检查原配对蒙版是否仍有效 |
| mask | 名称、排序、`related_asset_id` 对应的 API 字段 | 效果图存在、同方案同类型、一一配对、尺寸相同；人工对齐核验 |
| drawing | `viewCodes`、`purpose`、`applicability`、`exportSpecVersion`、`modelAssetVersionId`、`expectedDrawingRevision` | 规范/模型一致、格式可读、视向有效、文件命名合法且不重名 |
| artwork | `artworkKey`、`wallPosition`、`physicalSize`、`dimensionUnit`、`dimensionEvidence`、`expectedArtworkRevision` | PNG、合法画面定义、物理尺寸及证据、清单和模型关联 |
| model | SKP、名称及当前版本上下文 | 方案归属、文件格式与限额；替换同步处理依赖资料核验 |

### 3.4 完整性、审核与发布：4 个接口

| API | 方法 | 相对路径 | 关键输入 | 输出及服务端行为 |
|---|---|---|---|---|
| API-042 | GET | `/schemes/{code}/readiness` | 方案编号 | 六类完整性、当前修订、核验缺项及发布阻断项 |
| API-043 | POST | `/schemes/{code}/reviews` | 阶段、通过/拒绝、确认项、备注、被审核修订和幂等键 | 固定本次资料创建审核记录；不自动发布；drawings/artworks 按专项契约核验 |
| API-044 | POST | `/schemes/{code}/publish` | 方案上下文；并发/幂等字段待统一 | 事务内重验当前资产及审核；满足全部条件才发布 |
| API-045 | POST | `/schemes/{code}/unpublish` | 下架原因；并发/幂等字段待统一 | 下架、审计、保留项目引用 |

清单核验使用 API-056，不用 API-043 绕过清单专项确认。蒙版及整体审核的阶段枚举、确认字段需统一 Schema。

### 3.5 清单专项：7 个接口

| API | 方法 | 相对路径 | 关键输入 | 输出及服务端行为 |
|---|---|---|---|---|
| API-051 | POST | `/schemes/{code}/bill-of-materials/imports` | XLSM/XLSX、`expectedRevision` | 导入编号、完整预览、错误/警告；不执行宏，不改变当前清单 |
| API-052 | POST | `/schemes/{code}/bill-of-materials/imports/{importId}/commit` | 预期修订、警告确认、原因 | 原子替换整套清单并待核验；同一导入重复提交幂等 |
| API-053 | GET | `/schemes/{code}/bill-of-materials` | 方案编号 | 当前条目、单位、核验状态、源文件关联及修订；字段按权限返回 |
| API-054 | PUT | `/schemes/{code}/bill-of-materials/items` | `expectedRevision`、完整条目、原因 | 保存条目并递增修订，使核验失效 |
| API-055 | PUT | `/schemes/{code}/bill-of-materials/unit-rules` | `expectedRevision`、完整规则、原因 | 规则校验、重算数量、重新核验 |
| API-056 | POST | `/schemes/{code}/bill-of-materials/verifications` | `expectedRevision`、`requestKey`、四项确认、意见 | 针对当前清单/规则/模型记录核验，不自动发布 |
| API-057 | GET | `/schemes/{code}/bill-of-materials/download` | 当前已核验 `revision` | 客户版空价 XLSX 附件；不是内部源文件或报价单 |

**本次核心后台接口共 25 个：8 个方案/字典 + 6 个公共资源 + 4 个审核发布 + 7 个清单专项。** 四种图片共用接口，不能按页面数重复计为四套 CRUD。

### 4.1 建议逻辑实体

以下用于拆分建模任务，不是已存在表，也不要求每项机械拆成独立表。

| 实体 | 核心内容 |
|---|---|
| `schemes` | 不可变内部 ID、唯一业务编号、打标、母方案关联、发布状态、技术修订 |
| 字典及引用 | 类别、稳定选项标识、名称、排序/启用及被引用情况 |
| 导入预览/结果 | 操作者、源文件、解析结果、重复/错误、提交状态和有效期 |
| `scheme_assets` | `id`、非空 `scheme_id`、`type`、名称、排序、效果图配对、当前成员状态 |
| `asset_versions` | `asset_id`、唯一对象 Key、原文件名、MIME、字节数、SHA-256、像素/页数、创建时间 |
| 清单及条目/规则 | 修订、源文件版本、模型版本、条目、单位规则、核验状态和快照 |
| 图纸/素材集合 | 当前修订、成员版本及元数据快照、模型/清单绑定、规范和核验状态 |
| 审核/审计 | 阶段、固定修订、确认项、结果、意见、管理员、时间、幂等请求 |
| 历史资料引用 | 项目/报价对应不可变资产版本及清单/集合快照；由项目模块写入和读取 |

对象沿用 `booth-assets` Bucket 及 `schemes/{方案编码}/` 分类目录，版本使用唯一 Key。实际原文件名只用于显示和下载，不直接作为对象路径。文件上传、转码和打包放在数据库事务之外。

### 4.2 修改影响矩阵

| 变更 | 需要失效/重检的内容 | 发布和历史影响 |
|---|---|---|
| 模型替换 | 清单逐项核验、图纸模型绑定、素材模型/画面对应 | 原子下架；历史模型及项目快照保持原版本 |
| 清单条目/单位规则修改 | 清单核验；画面行变化还影响素材映射 | 下架后复核；不修改已提交项目数量 |
| 效果图/蒙版替换、删除或配对修改 | 图像配对、尺寸、蒙版对齐及相关审核 | 已发布方案下架；不自动改动材料数量或图纸 |
| 图纸内容/元数据/顺序/规范修改 | 图纸集合核验 | 下架；历史图纸仍指向旧版本 |
| 标准素材内容/映射/尺寸/顺序修改 | 素材集合核验 | 下架；历史项目素材版本不变 |
| 方案结构/适用条件修改 | 受影响的完整性、匹配条件与审核 | 重核受影响资料；具体字段影响表需冻结 |
| 私有主题改选 | 私有生成上下文 | 不使原结构模型、清单、图纸核验失效；不把私有结果写入公共资源 |

技术修订和文件版本是并发与历史保护机制，不新增面向用户的完整方案版本树。

## 8. 文档差异与处理原则

1. **接口编号冲突**：现有接口总表把跨方案资产查询和暂缓的客户端检索日志均标为 API-098。本文 API-098 专指 `GET /api/v1/admin/assets`；规划检索日志需另行分配唯一编号，本次未更改其他文档编号。
2. **版本含义**：不建设用户方案版本树，与保留不可变文件版本/技术修订并不冲突，后者是历史引用和并发必需能力。
3. **核验来源**：打标源表“已核验”仅作为导入来源信息，不能替代绑定到实际清单与模型的审核记录。
4. **AIGC 映射口径**：部分汇总描述曾将清单映射作为四方向素材交付前提；平面素材详细设计明确，私有 AIGC 四方向完整即可按方向交付，映射未解决需提示。标准/SU 公共素材仍必须完成画面映射及尺寸核验；本资源模块不混用这两类规则。
5. **接口与代码状态**：接口总表属于拟开发设计；实际已有认证接入与较早文档表述存在差异。本次业务接入应复用实际会话，不根据路由规划重复开发登录。
