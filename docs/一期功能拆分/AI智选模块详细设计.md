**版本：** v0.1（开发评审稿）  
**日期：** 2026-09-24  
**范围：** 客户端 C1-01～C1-09、后台 M1-01～M1-12，以及支撑匹配的服务端接口和数据管理。

### 1.1 核心结论

1. AI 负责把用户语言转换为条件；业务服务负责确定性筛选和排序。LLM 不生成方案、不决定发布状态、不判断施工可行性。
2. 客户端免费匹配免登录，不扣积分；换主题、资料下载和报价分别衔接已有模块。
3. 先检索“可直接采用”，再独立检索“相似参考”。参考结果明确展示不符项，不能混成精确命中。
4. 目标总计三套、每套三张效果图。有条件查询不足三套如实返回；空输入才随机推荐。此为 Q01 的建议落地口径。
5. 方案发布必须建立在完整资产和人工审核上。JSON 中的“已核验”只是一项导入声明。
6. 一期采用现有 Fastify 服务和 PostgreSQL 方案库，使用规则筛选及标签排序；向量召回、LLM 二次排序不在本期实现。

### 1.2 本模块的交付边界

| 本模块负责 | 交接到其他模块 |
|---|---|
| 输入、解析、修正、筛选、结果展示、方案详情 | 换主题任务、积分扣费 |
| 后台打标、适用条件补录、效果图和模型维护 | 清单条目导入与核验、三视图及平面素材制作 |
| 检查六类资产状态并审核发布 | 人工报价、客服实时消息、项目跟进 |
| 模型授权下载入口、人工需求上下文 | SU 结构编辑与新方案复核 |

## 2. 现有打标数据分析与入库规则

### 2.1 当前文件的实际情况

| 观察 | 影响与处理 |
|---|---|
| 48 条有编号记录；序号 59～85 为仅有序号的空行 | 有编号记录才是方案候选，空行跳过；不得按说明文字认定已有 85 套完整方案 |
| 方案尺寸集中在 6×3、6×6、9×6、9×3 m | 字段中的长宽为事实；名称里的“3x6”不用于覆盖长宽 |
| 48 条产品体系均为 FS62布框 | 初始化字典仍保留全部 6 种体系；选择其他体系时可能无结果 |
| 48 条均标为“已核验” | 导入保留原声明，不自动生成清单核验记录或发布记录 |
| 8 条清单文件名为空 | 可存草稿，发布检查失败；非空文件名也不等于实际资产存在 |
| 所有母方案编号为空 | 不按编号相似度自动推断母版关系 |
| 缺适用条件 | 后台补录并审核后才能形成完整结构判定 |
| “岛式”与“4面”并存 | 统一为开口数 4；保留原始导入值供核对 |
| 存在中文逗号、尾逗号、“弧形/弧形元素”等 | 分隔符清洗可自动做，业务同义词合并需字典确认 |
| `TW66_BK_044_F&B` 含 `&` | 编号保持原值，URL 路径、查询参数分别正确编码 |

清单文件名为空的方案：`TW36_BK_051_HARD`、`TW39_BK_013_JEW`、`TW36_BK_052_HOME`、`TW39_BK_014_MED`、`TW36_BK_053_HOME`、`TW36_BK_054_HOME`、`TW36_BK_055_AUT`、`TW66_BK_044_F&B`。

`TW66_BK_037_APP` 的描述提到具体开口位置；当前选型只使用开口面数，不从描述推断额外结构条件。

### 2.2 二十字段映射

API 使用 camelCase；数据库字段使用 snake_case。字典字段传稳定 ID，中文名称仅作展示。下表 `*Id` 对应各自字典项，不是外部企业账户 ID。

| 原字段 | 业务字段 | 类型与处理 |
|---|---|---|
| 序号 | sourceRow | 导入来源行号，不是主键 |
| 方案编号 | code | 非空、唯一、去首尾空白；不按 LT-XXX 强制改号 |
| 方案名称 | name | 后台必填文本；公开响应不返回 |
| 母方案编号 | parentCode | 可空；解析为 parentId；禁止自身、循环和无效关联 |
| 配套清单文件 | sourceBomFilename | 可空来源名称；实际资源用 bomAssetId 关联 |
| 展位长(m) | lengthMm | 转整数毫米，正数 |
| 展位宽(m) | widthMm | 转整数毫米，正数 |
| 展位面积(㎡) | areaM2 | decimal，按长×宽派生；导入手填值必须一致 |
| 展位高度(m) | heightMm | 方案实际最高点高度，正整数毫米 |
| 开口面数 | openingCount | 1～4；岛式映射 4 |
| 产品体系 | productSystemId | 单值，必须来自字典 |
| 风格 | styleId | 方案单值；客户端查询多值 |
| 适用行业 | industryId | 方案单值；客户端查询多值 |
| 预算档位 | budgetTierId | 单值；仅材料购买预算，非实际报价 |
| 功能分区 | zoneIds | 多值去重，按中/英文逗号切分 |
| 关键特征 | featureIds | 多值去重；保留跨分类的原始来源 |
| 一句话描述 | description | 内部检索文本，不原样当作客户端营销文案 |
| 关键词 | keywords | 字符串数组；去空白、空项和重复项 |
| 核验状态 | sourceVerificationStatus | 原始声明；业务 bomVerificationStatus 从核验流程产生 |
| 备注 | notes | 仅后台可见，不传给公开接口和外部 LLM |

精度建议：长度输入最多三位小数米，存整数毫米；面积最多六位小数平方米，使用十进制比较。导入面积不一致时返回行级错误，不自动改写源数据。编号大小写保持原样，禁止未经确认的大小写合并。

### 2.3 补充字段（建议）

不修改原二十列模板。补充字段通过后台表单维护，JSON 原始格式仍可导入。

| 字段 | 含义与约束 |
|---|---|
| applicabilityStatus | `pending/confirmed`；空备注不能表示适用条件已确认 |
| applicabilityRules | 经审核的适用条件列表，见下文 |
| applicabilityNotes | 可公开的适用说明，不包含内部备注 |
| publicationStatus | `draft/published/unpublished` |
| editRevision | 乐观并发计数，不构成面向用户的方案版本管理 |

现有长宽不自动互换，方案以实际长宽和开口面数进行结构判定。

一期不做通用规则编辑器。适用条件为受控条目：`{id,label,expectedValue:boolean,helpText}`，例如“允许自立结构”。客户提交 `applicabilityAnswers:{[id]:boolean}`。每个方案只维护自己需要的条目及期望值；未回答为 unknown，回答不符为 fail。技术人员明确确认没有额外适用条件时，允许 `confirmed + []`。不能转成可校验问题的条款标记需人工确认，使方案不能自动判为可直接采用。

### 2.4 字典清洗

- 产品体系 6 项、风格 11 项、行业 12 项、预算 3 项，以 JSON 的“下拉选项”为基准；不只取“字段说明”中较短的列表。
- 功能分区和特征从已有数据提取候选，经运营确认建立字典；未知值在导入预览中提示，不自动扩充正式字典。
- “弧形”→“弧形元素”、“带储物间”→“储藏间”等仅作为待确认别名；“电视机”和“显示屏”不直接认定等价。
- 方案原始分区中的“储藏间”与特征中的“储藏间”可同时存在；排序中的关键词奖励不得重复计算同一证据。
- 字典项可以停用，禁止删除已被方案引用的项。改中文展示名不改变 ID；别名冲突拒绝保存。

## 3. 客户端功能详细设计

### 3.1 页面组成

| 区域 | 交互 |
|---|---|
| 展位条件 | 长、宽、限高、面积下拉，单位明确；开口面数、产品体系单选 |
| 偏好条件 | 行业和风格多选；材料购买预算档位单选；均支持“不限” |
| 文字输入 | 一句话描述、示例提示、清空；建议上限 1,000 字符 |
| 条件回显 | 标出文本识别/表单/用户修正来源、覆盖前后值、歧义和未处理文本 |
| 结果区 | 最多三套；每套主图与三张切换入口、编号、判定及差异说明 |
| 无结果区 | 原因、修改条件、转人工；保留原输入 |
| 详情页/弹层 | 三张效果图、唯一编号、空间条件、适用说明、关联业务入口 |

电脑端条件区与结果区并列；手机端条件折叠于结果上方，条件回显和差异提示不可藏在仅 hover 可见的位置。图片比例 16:9，缩略图优先加载，原图按需打开。

结果不显示方案名称、内部评分、排序名次分数和营销标签；“可直接采用”“相似参考”“待确认限高”等属于判定说明，应显示。

### 3.2 字段联动和语义

1. 客户输入的是**场馆限高**，方案保存的是**实际高度**；条件为方案高度 ≤ 客户限高，不要求相等。
2. 长宽齐全后自动计算面积并只读；仅知道面积时可单独选择面积，不反推长宽。与文字中的面积冲突时要求修正。
3. 选择开口面数后按面数匹配方案，无需补充具体开口位置。
4. 行业/风格在同一维度内按“任一偏好命中”处理，不要求方案同时具备所有风格。
5. 产品体系是硬条件；预算、行业、风格、分区、特征默认是排序偏好。用户说“必须有储藏间”等强要求时单独记录，见 5.4。
6. 下拉选项来自 API-001。无现成尺寸可用自然语言输入，解析出的合法非预置值以临时选项回显。

### 3.3 提交流程

```text
填写需求 → 点击“AI 智选”
  ├─ 参数与文字全空 → API-003 random → 随机推荐
  ├─ 只有结构化参数 → 本地基础校验 → API-003 filtered
  └─ 有文字 → API-002 → 回显合并条件
                    ├─ 需澄清 → 用户修正 → API-003 filtered
                    └─ 无阻断问题 → API-003 filtered，同时保留修正入口
```

文本明确识别的字段覆盖初次表单同名字段；数组为整组替换，不做隐式并集。缺失字段不覆盖表单。用户在解析后手工修正并重新匹配时，直接提交修正结果，不再用旧文本覆盖；只有点击“重新解析文字”才重新走 API-002。

例：表单“长 6 m、宽 3 m、现代简约”，文字“改成长 9 米，科技风”→长 9 m、宽 3 m、科技未来，面积重新计算 27 ㎡，并显示覆盖提示。孤立的“6×3”若无法确认长宽坐标，回显尺寸候选并要求用户确认，不按数值大小强行决定方向。

### 3.4 状态与异常

| 状态 | 展示与操作 |
|---|---|
| idle | 输入区可操作，无伪造历史匹配结果 |
| parsing / matching | 显示真实“识别需求中/查找方案中”，阻止重复提交；不模拟生图进度 |
| needs_clarification | 回显冲突/未识别内容，允许修改；不偷偷忽略强要求 |
| results | 显示 1～3 套，可修改条件或进入详情 |
| empty | 显示无直接结果/无参考结果原因，提供人工入口 |
| error | 保留全部输入、允许重试；不能把数据库故障显示成“无匹配” |

请求序号或取消机制保证旧请求响应不覆盖新结果。表单修改后旧结果标注“基于上次条件”，再次匹配成功才替换。

部分条件缺失时允许探索，但不能承诺结构适用：归入相似参考，显示“需补充长宽/开口面数/限高”等原因。仅行业或风格查询可以返回参考方案，不要求先填写全部条件。随机模式显示“随机推荐，适用条件待确认”，不冒充可直接采用。

### 3.5 详情与跨模块交接

| 入口 | 传递内容 | 校验/展示 |
|---|---|---|
| AI 换主题 | code、原效果图 assetId、returnTo | 未登录触发已有登录墙；原图必须属于该方案 |
| 清单/三视图/平面素材 | code，已有主题上下文保持不丢失 | 由对应资料接口再次鉴权 |
| 申请报价 | code、原图/选定主题效果、需求摘要 | 参考方案同时携带差异，不能默认成为施工确认 |
| 下载模型 | code | 按登录状态与方案资料规则；隐藏按钮不能替代服务端校验 |
| 转人工 | 原始文本、最终条件、未解决问题、联系方式 | API-020；无方案时 code 为空，不创造占位编号 |

URL 只保留可公开的编号和页面定位，使用规范编码。条件、解析结果、图片索引可保存在当前标签页 sessionStorage，并以 history state 恢复前进/后退；不把联系方式和原始自然语言放进 URL。刷新/恢复后重新校验方案可见性；离开当前标签页后的长期保存不在一期范围。

公开详情通过 API-004 获取最新发布数据。下架/不存在均不展示旧的公开详情；已有项目从项目授权入口访问历史绑定资料。直达详情且没有匹配上下文时只展示方案规格，不显示“符合您的条件”。

## 4. 管理后台功能详细设计

### 4.1 方案列表与编辑页

列表支持编号/名称模糊检索、长宽/面积/高度、开口面数、产品体系、行业、风格、预算、清单核验、发布状态及“缺失资产”筛选，默认按更新时间倒序并用编号作稳定次序。

列：编号、后台名称、长×宽、实际高度、开口、体系、风格/行业、清单状态、发布状态、完整性问题数、更新时间。操作按权限显示：编辑、检查、审核、发布、下架。

编辑页分区：

1. **基础与关联**：编号、名称、母方案、来源信息；创建后编号不可编辑。
2. **空间结构**：尺寸、派生面积、高度、开口面数、适用条件。
3. **偏好打标**：体系、行业、风格、预算、分区、特征、关键词、描述。
4. **资产**：模型、三张效果图及顺序，查看对应蒙版/清单/三视图/平面素材状态。
5. **核验与发布**：导入声明、实际核验、审核结论、阻断项、发布/下架记录。

结构/功能变体创建独立方案编号及独立资料包；母版关系不能使变体自动继承已核验清单。纯视觉结果继续引用原结构方案，客户私有主题不直接入公共库。

### 4.2 导入向导

```text
选择 JSON / XLSX → 解析和清洗 → 逐行预览 → 选择新增/更新/跳过
               → 确认有效行 → 事务提交 → 草稿/待重新核验
```

本设计将 API-035 在原 XLSX 基础上扩展为接收当前 JSON；两种格式复用同一标准化与校验服务，不另建导入路由。

- JSON 读取“方案打标”；“下拉选项”用于字典对照建议，不自动覆盖现有字典；“字段说明”和说明文字不执行。
- 仅序号非空的行跳过；编号为空但有其他业务值的行报错。
- 文件内重复编号全部标记冲突；库内同编号由用户明确选更新/跳过，默认跳过。
- 预览显示原始值、标准化值、警告、错误、目标方案当前 editRevision。
- 导入批次建议 24 小时过期；提交使用保存的预览内容，不接受客户端重新传入任意清洗结果。
- 选中的有效行作为一个事务提交；期间出现字典停用、编号冲突、目标被更新则整个所选集合失败，重新预览，不部分覆盖。
- 同批母子记录先校验完整关系图，提交时先建母方案；有循环、缺父级时禁止对应行提交。
- 提交重复调用返回同一批次结果；批次归属校验覆盖预览和提交。
- 更新已发布方案要求明确确认下架后更新；不能通过导入绕过审核。

### 4.3 效果图及模型

- 每套正式发布方案配置 3 张不同效果图，顺序 1/2/3；不复制同一图凑数。
- 校验真实文件类型、可解码性、分辨率和 16:9 比例；高分辨率最小阈值交由设计部确认并纳入发布规则。
- 蒙版与效果图一一关联，尺寸一致，人工检查品红区域；AI 智选不用蒙版进行筛选，但发布完整性依赖它。
- 模型通过资产 ID 绑定方案，文件扩展名及文件类型检查通过后入库；上传文件名不能作为绑定的唯一依据。
- 文件校验完成后才关联数据库；上传失败或对象尚未就绪不算资产齐备。临时无引用对象按运维清理策略回收。
- 替换创建新资产记录，不覆盖旧对象。历史项目已有引用保留原资产；当前方案重新审核，不建立方案版本编辑器。

### 4.4 核验、发布与下架

建议三个发布状态与独立审核记录：

```text
draft → 审核通过并发布 → published → 主动下架/编辑业务内容 → unpublished
  ↑                                                                  │
  └──────── 草稿保存；unpublished 补齐、复核后可再次发布 ────────────────┘
```

发布硬门槛：

1. 编号及基础字段合法，母版关联有效。
2. 开口面数及适用条件已确认。
3. 六类资产齐备且与方案绑定，三张效果图/蒙版满足对应关系。
4. 清单提取一致性、模型逐项核对和配套项核验通过。
5. 设计、结构/图纸、产品适用条件、素材授权及业务负责人审核通过。

机器完整性检查和人工审核分开显示；“有文件”不能自动生成“审核通过”。API-042 返回每项 `pass/fail/pending` 和处理入口。

审核绑定 editRevision。影响匹配、资产或交付的修改使原审核失效，已发布方案须在同一事务下架并更新。仅内部备注变更可不下架，但仍记录审计。结构实际变化必须创建新编号，不能以“重新审核”为由覆盖已有结构。

发布事务重新校验 revision、资产就绪及审核结论，再更新状态；审核期间发生修改返回冲突。下架保留原因、操作者及项目引用，立即停止新匹配和新选择。

### 4.5 权限

权限最小集建议：`scheme.read/edit/import/review/publish`、`catalog.manage`、`asset.manage`。角色到权限的映射沿用平台授权模块；审核/发布是否要求不同人员列入评审。

资料下载按“当前身份 + 方案授权 + 资产绑定”校验；内部管理员不因登录成功自动获得全量编辑/发布权限。后台操作者引用 `admins.id`，伙伴引用 `users.id`。

## 5. 服务端解析与匹配规则

### 5.1 处理分层

```text
API-002 → ParseService → 规则提取 + LLM 结构化提取 → 合并、校验、澄清
API-003 → MatchService → 发布库候选 → 硬条件判定 → 参考候选 → 排序 → 公开 DTO
API-004/005 → SchemeService / AssetService → 可见性与授权 → 详情/受控下载
后台 API → CatalogService / ImportService / ReviewPublishService → 事务与审计
```

路由只承担输入校验、鉴权上下文和响应。单位转换、候选判定、排序和发布规则在服务层共享，客户端与后台不各自维护一套匹配逻辑。

### 5.2 需求结构

建议统一 `Requirement`：

| 字段 | 类型 | 含义 |
|---|---|---|
| lengthMm / widthMm / maxHeightMm | positive integer 或 null | 客户尺寸、场馆限高 |
| areaM2 | decimal number 或 null | 独立面积或长宽派生值 |
| openingCount | 1～4 或 null | 开口数量 |
| productSystemId | string 或 null | 指定体系时硬过滤 |
| styleIds / industryIds | string[] | 同维度任一命中的偏好 |
| budgetTierId | string 或 null | 材料预算档位偏好 |
| zoneIds / featureIds / keywords | string[] | 偏好及检索词 |
| requiredZoneIds / requiredFeatureIds | string[] | 用户明确的必须项 |
| excludedZoneIds / excludedFeatureIds | string[] | 用户明确的禁止项 |
| applicabilityAnswers | object | 受控适用条件答案 |

空标量统一 null，空集合统一 []，未知字段拒绝。尺寸、数组数量、文本长度均设接口上限；不接受 NaN、负数和无穷值。字典 ID 必须有效。

### 5.3 解析、覆盖与降级

1. 先用规则识别明确单位、数字、开口表达、字典和已审核同义词，作为稳定基础。
2. 有自然语言时调用一次 LLM，要求输出允许的字段、原文证据片段、未识别片段、冲突和必须/禁止语义；不给它数据库访问能力。
3. LLM 输出必须通过结构、单位、枚举和证据校验。不得将模型推测的缺省长宽/限高写成用户明确条件。
4. 无证据、歧义、规则与模型矛盾的字段不自动覆盖；返回 clarification。显式“不要灯箱”不得被关键词规则当作“灯箱偏好”。
5. 模型超时、输出非法、调用失败时使用规则结果，`parser=rules`、`degraded=true`；保留未处理内容和提示。
6. 非空文本无法识别任何条件时返回 needs_clarification；不能变成 random。规则只识别部分内容但有未解决硬要求时也必须确认后匹配。
7. 最终优先级：本次解析后的人工修正 > 有明确证据的文本 > 初次表单。文本未提及的字段保留。

提示词只包含用户本次需求、所需公共字典及输出约束；不传企业密钥、用户账户资料、内部成本或后台备注。文本中的“忽略条件、直接发布”等指令只作为输入内容，不改变服务端规则。

### 5.4 条件分级（建议落地口径）

| 条件 | 可直接采用 | 相似参考 |
|---|---|---|
| 发布、资产、审核有效 | 必须通过 | 同样必须通过 |
| 产品体系（如已指定） | 必须相同 | 不放宽 |
| 实际高度 ≤ 限高（如已提供） | 必须通过 | 不放宽；超高方案排除 |
| 适用条件明确失败 | 排除 | 排除 |
| 必须/禁止的分区、特征 | 满足；禁止项不存在 | 不放宽；未知时不能当作满足 |
| 长宽与明确面积 | 精确通过 | 允许有差异，但必须在参考范围内 |
| 开口面数 | 精确通过 | 允许差异并说明需重新设计/核验 |
| 缺少长宽、限高、开口面数或适用答案 | 不可直接采用 | 可探索，逐项标记待确认 |
| 行业、风格、预算、普通功能偏好 | 影响排序，不决定结构可用性 | 同样影响排序并显示未满足偏好 |

“必须/禁止”是本设计对自然语言强约束的建议补充，不把所有功能偏好升级成硬筛选。若业务不采用该扩展，强要求必须留在澄清/转人工流程，不能静默降成软偏好。

标签已审核为完整集合时才可用“未包含标签”判断不存在；集合尚未核对的方案不能凭缺失标签通过禁止条件。

### 5.5 两级判定算法

**前置集合 E：** 已发布、审核有效、六类资产可用，且通过体系、已知限高、明确适用条件及必须/禁止条件。

**直接集合 D：** E 中客户长宽、开口面数、限高及所需适用答案齐全，且尺寸、面积、开口面数全部精确通过的方案。

**参考集合 R：** E 中不属于 D，尺寸/开口存在差异或仍有适用信息待确认的方案；必须满足下列参考限制：

- 已知面积 A（独立输入或长宽乘积）：`abs(方案面积 - A) / A <= referenceAreaDelta`。
- 只提供一条边：对该条边使用相同形式的偏差限制；不猜另一条边和面积。
- 无任何尺寸：可以基于已有偏好/硬条件探索，明确标注“尺寸待确认”，不宣称“面积接近”。
- 已知超高、指定体系不符或明确适用条件失败，不因面积接近进入 R。

D 和 R 去重，先 D 后 R，总计最多 3 套；不从前置集合以外随机补齐。`D=0,R>0` 显示“未找到可直接采用方案，以下仅供参考”；两者为零进入无结果。

**建议首版阈值：** 直接匹配尺寸容差 0，参考面积/单边偏差 30%，不自动旋转或镜像。规格说明书的 3% 容差仅保留为待评审候选；即使采用也不得突破展位边界。

“可直接采用”表示本次已提供的结构条件与审核方案一致，不替代具体项目的报馆及施工确认。说明要与实际已校验字段一致，不输出泛化的“完全符合所有要求”。

### 5.6 内部排序

建议使用确定性排序元组：

1. 直接结果先于参考结果。
2. 参考结果先按已知尺寸偏差升序、再按待确认项数升序。
3. 相同结构接近程度内按偏好分降序。
4. 同分按 code 升序，保证非随机模式可复现。

建议偏好分：风格命中 +3，行业命中 +2，预算同档 +2，分区命中 +1/项（上限 2），特征命中 +1/项（上限 2），关键词命中 +1/项（上限 3）。同维度多选不会重复累计风格/行业分。

描述与关键词通过已确认同义词和关键词规则参与命中，已在分区/特征计分的同一证据不再加关键词分。“通用”行业作为未命中但可排序的方案，不给所有行业自动加分。预算不是报价保证，档位不一致允许排序靠后并提示偏好差异。

上述权重为评审建议；一期用服务端规则配置，不扩展通用权重后台。对外 DTO 不包含 score、权重、内部排名证据或营销描述。

### 5.7 随机推荐与无结果解释

随机模式只允许原始文字去空白后为空、表单及条件完全为空。浏览器保存的“默认偏好”也算条件，不应随意判空。

从当前已发布可用集合中等概率、不放回选取最多 3 套；单次无重复。跨请求允许偶然重复；候选多于 3 套时验证多次抽样有变化，而非要求每次绝不重复。不缓存固定随机结果列表。

无结果原因由实际判定统计生成，例如“符合已选体系的已发布方案为 0”“现有候选均超过 4 m 限高”“尺寸/开口没有直接匹配”。多个条件组合导致为空时说明“当前组合暂无方案”，不能未经验证断言某单项不存在。

`suggestions` 仅提出可由客户主动修改的条件；点击并确认后才能重新查询。已知限高等不能被服务端自动提高。不能将数据库/存储不可用包装成无结果。

## 6. 数据结构与一致性

以下是建议逻辑表，不是现有数据库表清单；实施时通过新增迁移创建。

| 表 | 关键字段/约束 |
|---|---|
| schemes | id UUID PK、code UNIQUE、name、parent_id FK、尺寸、开口、字典引用、标签数组、适用条件、publication_status、edit_revision、created/updated_at |
| catalog_options | id、type、label、aliases、enabled、sort_order；type+label 唯一；数组引用在事务中校验 |
| scheme_assets | id、scheme_id 非空 FK、type、名称、sort_order、related_asset_id、ready；每条资产归属一套方案，蒙版关联同方案效果图；同方案有效效果图顺序唯一 |
| asset_versions | id、asset_id FK、object_key、原文件名、校验和、MIME、大小、像素尺寸/页数；文件替换保留 assetId 并新增不可变版本，项目固定版本引用 |
| scheme_reviews | id、scheme_id、edit_revision、stage、decision、comment、admin_id FK、created_at；追加记录，不覆写结论 |
| scheme_imports | id、owner_admin_id、file_checksum、normalized_rows、row_errors、expected_revisions、status、result、expires_at |
| scheme_search_logs（规划暂缓） | id UUID PK、fingerprint（浏览器指纹）、user_id FK（可空，登录态关联）、raw_query、structured_params JSONB、result_count、matched_scheme_codes text[]、ip、user_agent、created_at |

清单数据及实际核验复用清单模块；审计复用统一审计模块。现阶段不新增匹配任务表：解析和匹配是同步请求，不接入 BullMQ 图像任务队列。方案数量较小时读取有限已发布元数据进行规则排序即可；索引优先覆盖唯一编号、状态、体系和常用尺寸。

方案与资产为一对多，手工创建或打标导入允许零资产草稿；资产通过四个独立管理路由后续上传并关联，文件名不自动创建文件记录或通过核验。整体审核通过及发布时检查六类齐全和分项核验，详见[方案资产管理详细设计](方案资产管理详细设计.md)。公共资产归 W15，方案基础资料和整体发布归 W03。

审核、发布、导入提交及其审计在同一数据库事务中写入。模型调用和文件上传不持有数据库锁。发布内容更新与下架原子化；查询直接按数据库状态过滤，一期不缓存候选结果，避免下架后仍推荐。

方案与资产不物理级联删除历史项目引用。项目保存选用时的 code、资产 ID、最终需求和匹配差异快照；后续编辑不会把旧项目资料替换成新对象。历史授权访问从项目上下文校验。

## 7. 服务端接口详细契约

### 7.1 通用约定

- 路由和编号沿用已有路由文档。下文成功响应采用 `{data: ...}` 作为本模块建议约定，需在实现时统一 Schema；文件响应除外。
- 错误沿用 `{error:{code,message,requestId}}`；`code` 使用 `VALIDATION_ERROR/REQUEST_ERROR/INTERNAL_ERROR`，message 为安全文案，不能原样输出 LLM/数据库错误。
- HTTP：400 格式/字段错误；401 未登录；403 无权限；404 资源不可见；409 编号/并发/发布状态冲突；413 上传过大；429 限流；503 依赖不可用。解析需澄清和匹配无结果均为 HTTP 200 业务状态。
- 公开 DTO 采用白名单；不返回 name、notes、价格、内部评分、存储 objectKey、原始模型输出和后台审核人员资料。
- 上传建议上限：打标文件 10 MB/1,000 行，效果图 20 MB/张、SKP 200 MB；这些是技术配置建议，上传路由需独立于当前全局请求体限制设置，并由资产样本确认。
- 匿名解析/匹配需要按来源/IP 限流及全局 LLM 并发上限，429 返回 Retry-After；具体额度由试点容量确定。

### 7.2 API-001 可选条件

`GET /api/v1/client/catalog/options`，公开。

返回：

- `dimensions:{lengthMm[],widthMm[],maxHeightMm[],areaM2[]}`：尺寸可选值，来源为已发布库加运营确认的标准选项；不代表每个组合必有结果。
- `openingCounts:[1,2,3,4]`、`openingSides:[{id,label}]`、公开坐标示意。
- `productSystems/styles/industries/budgetTiers/zones/features`：`{id,label}` 数组；不返回核验状态。
- `applicabilityQuestions`：可供客户补充的受控问题。
- `rulesVersion`、`dictionaryVersion`：识别规则/字典变更，用于诊断，不是方案版本。

预算标签先保留低/中/高及原材料预算说明；数值预算的币种及 3 万/8 万端点未冻结前，不擅自将“3万元”映射某档，返回确认提示。

### 7.3 API-002 解析需求

`POST /api/v1/client/requirements/parse`，公开。

请求：`{text:string,form:Requirement}`。

响应字段：

| 字段 | 含义 |
|---|---|
| status | `ready/needs_clarification` |
| requirement | 合并后的完整 Requirement |
| parser / degraded | `llm/rules/none`；是否降级 |
| fieldSources | 字段路径→`form/text/derived`，文本字段含证据片段 |
| overrides | `{field,previousValue,value,evidence}`[] |
| clarifications | `{field,reason,question,candidates}`[] |
| unhandledText | 未能可靠处理的原文片段数组 |
| warnings | 安全的机器码和用户提示 |
| rulesVersion / dictionaryVersion | 本次使用的版本标识 |

LLM 返回非法字段时拒绝该次模型输出并走规则降级。降级仍能完整识别时返回 ready，否则 needs_clarification。解析接口不写方案库、不生成匹配得分。

### 7.4 API-003 匹配方案

`POST /api/v1/client/scheme-matches`，公开。

请求：

```json
{
  "mode": "filtered",
  "inputContext": { "textProvided": true },
  "requirement": {
    "lengthMm": 6000,
    "widthMm": 3000,
    "maxHeightMm": 4500,
    "areaM2": 18,
    "openingCount": 2,
    "productSystemId": "fs62",
    "styleIds": ["modern-minimal"],
    "industryIds": [],
    "budgetTierId": null,
    "zoneIds": [],
    "featureIds": [],
    "keywords": [],
    "requiredZoneIds": [],
    "requiredFeatureIds": [],
    "excludedZoneIds": [],
    "excludedFeatureIds": [],
    "applicabilityAnswers": {}
  }
}
```

示例字典 ID 用于说明契约，初始化时冻结实际 ID。`mode=random` 要求 `textProvided=false` 且所有条件为空；filtered 空条件返回 needs_clarification，不隐式随机。inputContext 不作为身份或授权凭据。

响应 `data`：

| 字段 | 含义 |
|---|---|
| status | `matched/no_match/needs_clarification` |
| mode | `filtered/random` |
| requirement | 服务端校验、标准化后的条件 |
| items | 下述 MatchItem[]，长度 0～3 |
| counts | `{direct,reference,random,total}`，为本次返回数量 |
| reasons / suggestions | 空结果原因和用户可主动选择的修改建议 |
| missingFields | 尚未提供且影响结论的字段 |
| rulesVersion | 判定规则标识 |

`MatchItem`：

| 字段 | 含义 |
|---|---|
| code | 唯一方案编号 |
| matchType | `direct/reference/random`；random 是推荐模式，不是第三种结构判定 |
| images | 恰好三项 `{assetId,url,thumbnailUrl,order,width,height}`，使用浏览器可访问地址 |
| specifications | 长宽、高度、面积、开口面数、体系的公开规格 |
| reasons | 由服务端规则生成的可展示判定说明 |
| differences | `{field,requested,actual,reason}`[]；不只返回一句模糊“相似” |
| pendingConfirmations | 待补充/核对条件数组 |
| preferenceMisses | 未满足的预算/风格等偏好，不冒充结构差异 |

`reasons` 建议机器码包括 `DIMENSIONS_MATCH/HEIGHT_WITHIN_LIMIT/OPENING_MISMATCH/DIMENSIONS_UNKNOWN/APPLICABILITY_UNKNOWN`，作为业务响应内容，不改变统一错误码。前端根据安全字段渲染，不能直接渲染模型 HTML。

客户端不得提交规则阈值、排序分数或发布状态。直接调用匹配接口时服务端仍完整校验 Requirement；不信任“已经解析过”。

### 7.5 API-004 方案详情

`GET /api/v1/client/schemes/{code}`。

返回：`{code,images,specifications,applicabilityNotes,resources,actions}`。

- `resources` 按六类资产返回可公开的存在状态；不直接提供受限下载 URL。
- `actions` 返回 `theme/bom/drawings/artworks/quote/modelDownload` 各入口的 `available/requiresLogin/requiresAuthorization/unavailable` 状态。
- 公开请求仅允许 published；详情响应不根据过期的浏览器条件给出匹配结论。
- 有条件权限的响应禁止进入共享缓存；授权在各业务接口再次验证。

### 7.6 API-005 模型下载

`GET /api/v1/client/schemes/{code}/model/download`，授权伙伴。

校验登录、方案访问范围、当前模型绑定及对象就绪后返回 `{downloadUrl,filename,expiresAt}`。短期签名建议有效 60 秒，下载文件名保留编号；生成地址使用公开存储端点。

下架后拒绝新公开下载；已签发链接在有效期内可能继续有效，因此有效期必须受控。已有项目历史模型从项目授权上下文读取，不能仅凭 code 猜测项目权限。

### 7.7 API-020 人工需求交接

`POST /api/v1/client/manual-requests`。

在既有契约基础上明确请求字段：`{requestKey,originalText,requirement,unresolvedQuestions,matchReasons,contact,sourceContext}`。本入口不要求 code；可选参考编号必须逐个验证，不能作为已经选定的施工方案。

返回 `{manualRequestId,projectId,status}`。requestKey 防重复提交，重复键且不同内容返回 409。联系方式验证、匿名提交策略及渠道承接规则沿用 Q07/Q11；这两项未确认前不宣称转人工闭环已完成。

### 7.8 后台接口契约

公共前缀 `/api/v1/admin`；下表路径均接在此前缀后。

| API | 方法与路径 | 请求及响应要点 |
|---|---|---|
| 031 | GET `/schemes` | page≥1、pageSize 建议默认20/最大100及4.1筛选项 → `{items,total,page,pageSize}` |
| 032 | GET `/schemes/{code}` | → 完整后台 Scheme、editRevision、实际审核及资产摘要 |
| 033 | POST `/schemes` | code、name及打标数据 → 201，草稿 Scheme；业务字段可待补齐，发布时严格检查 |
| 034 | PATCH `/schemes/{code}` | `{expectedRevision,changes,confirmUnpublish}` → 最新 Scheme；不能直接改编号、核验结论、发布状态 |
| 035 | POST `/scheme-imports` | multipart file，JSON/XLSX → `{importId,expiresAt,rows,summary}`；rows含原值、标准化值和错误 |
| 036 | POST `/scheme-imports/{importId}/commit` | `{rows:[{sourceRow,action,expectedRevision}],confirmUnpublish}` → `{created,updated,skipped,results}` |
| 037 | GET `/catalog-options` | type可选 → 字典、别名、引用数、字典revision |
| 038 | PUT `/catalog-options/{type}` | `{expectedRevision,items}` → 更新集合；引用项省略/删除返回冲突 |
| 039 | GET `/schemes/{code}/assets` | → 分类型资产列表与对应关系 |

清单实际导入/核验复用 API-051～056，不能通过 API-034 将 sourceVerificationStatus 改为“已核验”来绕过流程。后台对六类资产的管理复用 API-039～041，不为智选复制上传接口。

## 8. 性能、可观测性与故障处理

- 用户点击至筛选响应的需求目标 ≤5 秒，包括串行解析和匹配；图片完整下载另外测量。试点报告同时列 p50/p95/最大值和超时比例，不能以平均值代替需求目标。
- 建议预算：解析整体 3 秒内（模型调用约 2.5 秒超时），匹配及返回 1 秒内，其余留网络和序列化余量；供应商慢时及时取消并降级，不在请求内多次重试。
- 无文字直接匹配不调用 LLM。解析成功仍由规则引擎选方案，避免为每套方案调用模型。
- 记录 requestId、解析路径、模型标识、耗时、降级原因码、候选数、直接/参考数量和规则版本；普通日志不存原文、联系方式、token和完整供应商响应。
- 结构化“无匹配原因”用于扩库观察；询价转化由项目来源关联统计。原文样本留存策略需单独确认，默认不建立无限期保存的匿名需求库。
- 解析提供商不可用→规则降级；数据库不可用→503；单张资产失效→方案不再满足公开可用条件并提示后台修复。对象缺失通过发布检查、定期资产巡检及失败反馈更新 ready 状态，不对每次请求逐个远程检查全部对象。

## 9. 验收场景与需求追踪

以下为实施后的验证清单，本设计阶段未执行业务测试。匹配单测使用已审核开口面数和资产的测试夹具；现有 JSON 缺补充信息，不能直接作为“可直接采用”的完整夹具。

| 场景 | 预期结果 | 对应需求 |
|---|---|---|
| 表单6×3，文字明确改长9米 | 保留宽3米、派生27㎡，回显覆盖来源 | C1-01/03/04 |
| 解析后手改风格再匹配 | 不被旧文本再次覆盖 | C1-04 |
| 文本含歧义尺寸或无法识别 | 提示确认，不随机返回 | C1-03/04/06 |
| LLM超时、非法JSON或含伪造枚举 | 规则降级，未处理硬要求需确认 | C1-04 |
| 同面积但长宽不同 | 不进入direct；进入参考需通过面积范围 | C1-05 |
| 客户开口面数与方案不同 | 标注参考及开口面数差异 | C1-01/05 |
| 客户缺开口面数/限高 | 返回参考及待确认项，不宣称直接采用 | C1-05 |
| 方案4.5m，客户限高4m | 从直接和参考均排除 | C1-05/07 |
| 指定桁架，库内只有FS62 | 无匹配，不用语义相似绕过体系 | C1-02/07 |
| “必须储藏间”“不要灯箱” | 强约束或明确澄清，不降成普通加分 | C1-02/03 |
| 预算不同但结构合格 | 可直接采用，另提示预算偏好未满足 | C1-02/05 |
| 仅有1套合格候选 | 只返回1套，不用不合格方案补齐 | C1-05 |
| 全空且库内>3套 | 单次无重复，多次抽样非固定列表 | C1-06 |
| 进入详情后前进/后退 | 恢复条件和图序号，重新检查发布状态 | C1-08 |
| 匿名浏览、普通用户下载SKP | 浏览允许；下载分别401/403 | C1-08/09 |
| 用其他方案assetId下载/挂载 | 拒绝越权或绑定错误 | C1-09、M1-07 |
| JSON空行、中文逗号、尾逗号 | 跳过空行、正确标准化并保留来源 | M1-05 |
| JSON带已核验但缺清单/适用条件 | 可导草稿，不能发布 | M1-09/11 |
| 重复编号、循环母版、并发导入 | 预览报错/提交409，不静默覆盖 | M1-02/04/05 |
| 审核后修改数据、并发发布 | 旧审核失效，revision不符返回409 | M1-10/11 |
| 下架方案仍被旧结果选中 | 新详情/报价选择复检拒绝，历史项目保留授权资料 | M1-12 |
| code包含F&B | 列表、详情、下载、跳转均编码正确 | C1-08/09 |
| 查看公开响应 | 无name/score/notes/内部价格/存储内网地址 | C1-05、权限要求 |
| 非空查询无结果后转人工 | 保留原文、修正条件、联系方式；不伪造code | C1-07、C6-04 |

实施验证分层：规则与合并逻辑单测；接口注入验证公开 DTO/权限/错误状态；数据库集成验证唯一性、事务和并发；浏览器验证回显/导航/登录墙；用10套完整试点资产做端到端选型与人工交接，并记录≤5秒指标。后端实现后运行类型检查和相关测试，前端实现后构建及浏览器验证。
