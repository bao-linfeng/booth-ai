参展商客户端

02 / CLIENT

以 Vue 3 单页应用组织页面。路由与页面异步加载，组件由 Shadcn-Vue 风格组件和 Radix Vue 原语构成；Pinia 管理登录状态，composables 负责可复用交互。

Vue 3.5TypeScript 5.6Vite 6Tailwind CSS 3pnpm

应用分层

  • src/pages/：页面与业务流程，包括 AI 智选、方案详情和登录。
  • src/router/：Vue Router 4，HTML5 History，页面动态导入。
  • src/components/ui/：Shadcn-Vue 风格组件；Radix Vue 提供可访问性基础交互。
  • src/services/、src/lib/api-client.ts：业务 API 与 ofetch 请求封装。

状态与视觉系统

  • src/stores/auth.ts：Pinia 登录态；使用持久化插件存储 token 与用户信息。
  • src/composables/ 与 VueUse：复用交互逻辑。
  • src/plugins/i18n/：vue-i18n，中文/英文消息。
  • src/components/theming/：CSS 变量、主题切换与暗色模式。

接口路径：Vite 开发服务器将 /api 代理到 http://localhost:3000；VITE_API_BASE_URL 可覆盖本地 API 基地址，另有灵通外部 API 请求客户端。页面构建执行 vue-tsc --noEmit 后再运行 Vite 构建。

管理后台

03 / ADMIN

独立的 pnpm + Turborepo 工作区，业务应用位于 apps/web-antd。Vben 提供路由、权限、表单、表格和布局能力，Ant Design Vue 提供基础组件。

Vben Admin 5Vue 3.5Ant Design Vue 4Vite 8Tailwind CSS 4pnpm 11 + Turbo 2

工作区结构

  • apps/web-antd/src/views/：方案、资产、字典、用户等管理页面。
  • src/api/、src/adapter/：业务接口与 Vben 表单 / VXE 表格适配。
  • src/router/、src/store/：模块化路由、路由守卫、Pinia 登录态。
  • packages/：Vben 核心、布局、权限、请求、工具、国际化等共享包。

后台业务交互

  • 列表/检索使用 useVbenVxeGrid；表单使用 useVbenForm；弹窗使用 useVbenModal。
  • @vben/request 请求客户端注入 Bearer token 与语言头，按 { code: 0, data } 解包。
  • @vben/access 与路由守卫处理前端权限展示，API 端另做管理角色校验。
  • 开发环境可选 Nitro mock；实际业务 API 以 VITE_GLOB_API_URL 配置。

构建组织：后台包内使用 catalog 统一依赖版本，Turborepo 编排多包构建与检查。生产环境路由历史模式可由 VITE_ROUTER_HISTORY=hash 配置。

服务端

04 / SERVER

Node 24 + TypeScript ESM 的双进程服务。Fastify 负责同步请求；Worker 负责 BullMQ 任务消费和 Outbox 分发，两者共享基础设施代码但独立运行。

Node.js 24Fastify 5BullMQ 6PostgreSQL 17Redis 7.4Silo S3npm
HTTP PROCESS

API · src/api.ts

src/app.ts 装配 CORS、Helmet、multipart、Swagger、错误处理与健康检查；src/modules/client/、src/modules/admin/ 注册业务路由；服务层与仓储层处理业务和数据访问。

已接入的模块涵盖客户端登录与方案智选、管理端方案/导入/素材/清单/审核/字典等；部分其他业务目录尚未注册到应用入口。

BACKGROUND PROCESS

Worker · src/worker.ts

消费 booth-foundation 队列，并周期性分发事务性 Outbox；写入健康标记供容器检查。任务写库与 Outbox 入库同事务，分发采用数据库行锁与确定性 jobId。

当前 Worker 中明确注册的是基础 system.echo 任务；业务目录名不等于已具备对应异步处理能力。

数据访问

pg 连接池 + SQL 事务，迁移文件位于 migrations/。迁移执行器使用 advisory lock 和 SHA-256 校验，历史迁移只追加、不修改。

会话与异步

ioredis 接入 Redis；BullMQ 管理任务队列。API 请求侧快速失败，Worker 消费侧采用适合长期连接的重试策略。

对象存储

AWS SDK v3 通过 S3 协议连接 Silo；内部访问与给浏览器使用的签名 URL 分别配置不同端点。

接口与安全

外部 SSO 对接本地用户/管理员同步表，管理端路由校验会话及角色；Swagger UI 和 OpenAPI 文档在非生产环境开放。

现状口径：当前“AI 智选”的需求文本识别由服务端规则解析和方案匹配实现；不要把现有代码误写成已经接入第三方大模型推理。方案详情中的部分后续操作目前明确标记为 unavailable。

开发与部署边界

06 / OPERATIONS

客户端

在 apps/client/ 执行

pnpm dev
pnpm build

开发 API 使用 Vite /api 代理；History 路由部署时需静态服务回退到 index.html。

管理后台

在 apps/admin/ 执行

pnpm dev:antd
pnpm check:type
pnpm build:antd

业务应用默认开发端口 5666；后台是独立 monorepo。

服务端

在 apps/server/ 执行

npm run dev:api
npm run dev:worker
npm run check

本地 Docker Compose 在 infra/compose.dev.yaml，分别启动依赖、迁移、API 与 Worker。

本地依赖端口：API 3000 · PostgreSQL 55432 · Redis 56379 · Silo S3 19000 · Silo 控制台 19001。数据库和文件通过 Docker 命名卷保存；上述 Compose 配置面向本地开发。
