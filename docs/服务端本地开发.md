# 服务端本地开发

服务端采用独立的 `apps/server` TypeScript 项目，API 与 Worker 分进程运行。Fastify 5 提供 HTTP 接口，BullMQ 6 执行异步任务，PostgreSQL 17 保存业务数据，Redis 7.4 保存队列，Silo 通过 S3 接口保存对象。此阶段提供基础框架、Outbox 异步验证链路及核心模块服务，三端接口契约与数据模型以《服务端接口路由》为准逐步联调演进。

## 启动

需要 Docker Desktop（Linux containers）与 Docker Compose v2；无需宿主机安装 Node.js、PostgreSQL 或 Redis。以下命令在仓库根目录的 PowerShell 执行：

```powershell
./scripts/setup.ps1
```

脚本首次生成未跟踪的 `.env` 随机凭证，重复执行保留已有文件。先构建服务端镜像，再启动 PostgreSQL、Redis、Silo，完成数据库迁移与 bucket 初始化后启动 API 和 Worker。单独生成配置可用 `./scripts/setup.ps1 -SkipStart`。不要提交或分享 `.env`，不要输出包含解析后密码的完整 Compose 配置。

修改 `apps/server/src` 后开发进程自动重启；测试和迁移目录也挂载到容器。修改依赖或配置后重新执行启动命令以重建镜像。数据库迁移位于 `apps/server/migrations`。

## 地址与连接

| 服务 | 宿主机地址 | 说明 |
| --- | --- | --- |
| API | http://localhost:3000 | `/health/live` 为存活检查，`/health/ready` 为依赖就绪检查 |
| PostgreSQL | `127.0.0.1:55432` | database/user 均为 `booth`；密码在 `.env` |
| Redis | `127.0.0.1:56379` | 密码在 `.env`，AOF 持久化，`noeviction` |
| Silo S3 | http://localhost:19000 | bucket 为 `booth-assets`，region 为 `us-east-1` |
| Silo 控制台 | http://localhost:19001 | 账号与密码为 `.env` 的 `S3_ACCESS_KEY` / `S3_SECRET_KEY` |

所有端口只绑定本机 `127.0.0.1`。容器内部使用 `postgres:5432`、`redis:6379`、`silo:9000`；提供给浏览器的签名 URL 使用 `http://localhost:19000`。默认允许开发前端来源 `http://localhost:5173` 和 `http://localhost:5174`，来源变化时修改 Compose 中的 `CORS_ORIGINS`。

## 验证与排查

```powershell
docker compose --env-file .env -f infra/compose.dev.yaml ps -a
docker compose --env-file .env -f infra/compose.dev.yaml --profile tools run --rm check
docker compose --env-file .env -f infra/compose.dev.yaml --profile tools run --rm smoke
docker compose --env-file .env -f infra/compose.dev.yaml logs --tail 100 api worker migrate storage-init
```

`check` 执行 TypeScript 检查、测试与构建；`smoke` 在运行环境验证服务间集成。API 的就绪检查失败或 Worker 健康检查失败时，先检查依赖服务和对应进程日志。不要将可能含业务信息的完整日志公开发布。

手动运行迁移或重复初始化 bucket：

```powershell
docker compose --env-file .env -f infra/compose.dev.yaml run --rm migrate
docker compose --env-file .env -f infra/compose.dev.yaml run --rm storage-init
```

## 停止与数据保留

```powershell
docker compose --env-file .env -f infra/compose.dev.yaml down
```

此命令保留 PostgreSQL、Redis、Silo 的命名数据卷。正常停止不要加 `-v`；它会删除数据卷。已有数据库卷不会因修改 `.env` 自动修改密码，因此需保留原凭证。

## 部署边界

该 Compose 为本地开发环境。Node.js 固定 24.15.0，Silo 固定明确 release；PostgreSQL、Redis 镜像固定版本系列，重建可能拉到该系列的新维护版本。正式发布应验证后固定镜像 digest，并配置生产凭证、TLS、备份恢复、访问控制与独立环境。Dockerfile 提供 `runtime` target，默认启动编译后的 API；Worker 可覆盖为 `node dist/worker.js`。
