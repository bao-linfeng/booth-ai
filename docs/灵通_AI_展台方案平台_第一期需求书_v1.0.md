# 一、平台定位与目标

根据 2026-09-13「AI 设计平台优化与方案库扩充策略」会议指示及老板评审意见，灵通 AI 展台方案平台定位为：

> 围绕「描述需求 — 匹配方案 — 品牌调整 — 清单核对 — 询价交接」全链路的展台方案选型与成交平台。

核心价值：降低客户设计门槛（不懂设计也能描述需求、选择方案），并把方案转化为实际业务——通过完整方案库，把效果图与模型、材料清单、配套图纸联系起来，帮助客户更方便地选用灵通产品。

## 1.1 一期核心目标

| 目标维度 | 具体要求 |
|---|---|
| 产品形态 | 适配电脑 / 手机的 Web 平台 + 方案库 + AI 能力（小程序按试点结果分步推进） |
| 核心能力 | AI智选（智能选方案）（LLM 识别需求 → 方案库筛选）+ 品牌 / 主题调整（外部 API）+ 清单 + 配套图纸 + 平面素材 + 获取报价 |
| 服务对象 | 中小参展商（公开入口）+ 经销商 / 搭建商 / 设计师（合作伙伴入口） |
| 商业闭环 | 一期先形成「客户愿意用、渠道愿意接、内部能维护」的完整流程，再逐步扩大方案规模与自动化能力 |

## 1.2 设计原则

- **AI 开方，人在选：** AI 负责需求识别与方案筛选，人工做筛选把关、结构转化与业务承接。
- **方案库优先：** 方案库是平台核心基础，扩充「完整方案库」而非「配件库」。
- **输出可落地：** 效果图、模型、清单、图纸、素材对应同一唯一方案编号，可核对、可下载、可施工。
- **先试点再冻结：** 基于现有试点方案先跑通完整流程，用实际结果修订后再冻结开发范围与验收标准。

# 二、用户与双入口

## 2.1 用户分层（试点假设）

70% 参展商、30% 专业客户作为试点假设，后续依据实际使用与转化情况调整。

| 用户层级 | 预期占比 | 使用场景 | 平台形态 | 核心动作 |
|---|---:|---|---|---|
| 中小参展商（主力） | ~70% | 无 SketchUp、临时参展、效果为先 | Web 平台（公开入口） | 描述需求 → 选方案 → 调整品牌 → 申请报价 |
| 专业客户（保留能力） | ~30% | 自有材料、深度设计、结构定制 | SU 设计工具 | 调结构、换组件、深度编辑 |

## 2.2 双入口设计

一期只区分两类注册用户的主要使用入口，不建设复杂的伙伴权限、渠道归属或项目协作体系。中小参展商是客户端的主要用户；授权经销商、搭建商、设计师主要使用 SU。两类用户都来自统一注册账户，平台只需保存用户类型标记，并据此做入口识别和提示。

| 用户类型 | 主要入口 | 说明 |
|---|---|---|
| 中小参展商 | Web 客户端 | 描述需求、查看方案、调整品牌效果、申请报价；为客户端主力用户 |
| 授权经销商 / 搭建商 / 设计师 | SU | 使用统一注册账户进入 SU，进行结构编辑及相关专业操作 |

**身份标记规则：** 用户类型只用于识别主要入口、显示提示和判断是否需要引导至客户端或 SU，不自动产生额外的伙伴授权、渠道归属、跨客户项目访问或后台操作权限。

## 2.3 成交承接

报价申请、人工跟进和成交承接属于独立的后台业务流程，不由“中小参展商 / 合作伙伴”用户类型自动推导权限。具体承接规则另行确认，不纳入本节双入口设计。

# 三、第一期功能范围

一期范围收紧原则：

优先完成：

1. Web 平台
2. 智能方案匹配
3. 明确范围内的品牌 / 主题调整
4. 已核对清单和配套资料授权查看下载
5. 获取报价及销售交接

小程序、复杂功能修改、自由组件组合、大规模方案扩充，均按试点结果分步推进。

## 3.1 AI智选（智能选方案） P0

**定义：** 大语言模型（LLM）识别用户需求 → 从预置方案库中筛选匹配方案并展示效果图。

一期是「选」而非「生成」——不做从零生成新方案，而是从已有完整方案库中精准匹配。

**术语：** 对内技术本质为「文选图」（LLM + 方案库筛选）；对外名称采用「AI智选」——客户感知是「描述需求 → 出方案」，而非 AIGC 直接生图。

| 项 | 规格 |
|---|---|
| 输入形式 | ① 参数下拉：长宽高 / 面积 / 开口均采用下拉菜单选择模式，行业 / 风格多选；② 自然语言输入框；③ 预算档位（仅材料购买预算） |
| 筛选逻辑 | 两级判定：① 可直接采用——按实际长宽、开口面数、限高、模板适用条件匹配；② 相似参考——面积接近但长宽 / 开口面数不符时，仅作为参考并提示需调整 |
| 无匹配处理 | 说明原因，允许客户修改条件或提交人工处理，不默认放宽要求硬给结果 |
| 输出 | 3 套方案，每套 3 张效果图，可点开查看详情 + 配套清单 + 配套报馆图素材 |
| 加载体验 | 能快则快，不模拟「AI 生成」节奏（删除随机等待 2~5 秒） |

## 3.2 品牌 / 主题调整 P0

**定义：** 对候选方案进行明确范围内的品牌 / 主题调整（行业风格 + 客户品牌色），输出新效果图。

| 项 | 规格 |
|---|---|
| 登录墙 | 图生图产生费用，点「AI 换主题」前需登录 + 校验积分（衔接 3.7 账户登录与订阅） |
| 技术选型 | 外部 API：通义万相 `wanx-x-painting` / banana（Nano Banana Pro），公司内部不训练大模型 |
| 蒙版规范 | 每套方案制作 mask 蒙版层（品红 `#FF00FF` 标识可改区域） |
| 提示词 | 预置行业 × 风格模板 + 客户品牌关键词注入 |
| 输出 | 换肤后 1~4 张可选图，含前后对比 |
| 兜底 | API 失败时保留原图 + 提示稍后重试 |

## 3.3 简化清单导出 P1

| 项 | 规格 |
|---|---|
| 方案编号 | 所有方案（含变体）均有按特定规则制定的唯一编号，对应已核对清单和配套图纸，无需版本管理、无需让 AI 计算材料 |
| 申请报价 | 清单页面设置「申请报价」按钮，一键发起报价申请，由客服提供报价（衔接 3.6 获取报价）；前端不展示价格 |
| 字段 | 序号 / 产品名称 / 产品型号 / 尺寸规格(mm) / 数量 / 单价 / 总价 / ERP 编码（8 列） |
| 总价公式 | 数量 × 单价（自动计算，单价留空供手填，与 SU 保持一致，三种计算规则：个数、长度、面积） |
| 准确性（两层） | ① 从 xlsm 提取一致——证明导出正确；② 模型与清单逐项核对——证明源清单完整。必要连接件、支撑件及配套项应在发布前由相应技术人员确认（此步骤在制作方案库时由灵通完成） |
| 单位规则 | 明确计量单位、计价单位、换算规则；价格由客服报价，前端不展示价格 |

## 3.4 报馆图素材（三视图） P1

**定义：** 选定方案后提供报馆图素材（三视图），辅助施工，允许设计师后续微调。

详情页「报馆图素材」弹窗支持逐张下载 / 下载全部，供施工 / 报馆方取用高清素材。

注意区分：

- **报馆图素材（三视图）**：交付施工 / 报馆用的平面图。
- **mask 蒙版图**：给图生图用的可改区域标识图。

两者是不同产物。

方案库中的报馆图素材由灵通制作好入库；专业用户进 SU 定制需 SU 插件导出特定规则的报馆图素材。

配套三视图的用途与适用范围应写清楚；具体项目的报馆及施工资料仍需按实际要求确认。标准方案未发生变化时直接调取对应图纸；SU 修改结构后，重新导出并复核。

## 3.5 平面素材输出 P1

**定义：** 输出方案各墙面的平面素材，作为客户平面设计师自行裁剪、放大、编辑、添加文字的底图素材，最终由客户导出制作文件（喷绘 / 印刷），输出高清 PNG。

详情页「平面素材」弹窗支持逐张下载 / 下载全部，供平面设计师取用底图。

两个输出口：平面底图输出按「是否经过 AIGC 换主题」分为两个出口——SU 端与 AIGC 端各司其职、互不越界。

| 输出口 | 场景 | 方式 |
|---|---|---|
| SU 输出 | ① 未换主题（原方案） | 直接从方案库取底图资料（制作方案库时已由 SU 导出存库，名称与清单画面名称一一对应） |
| SU 输出 | ② 用户用 SU 改过方案 | SU 端实时导出（尺寸准确，名称对应清单） |
| AIGC 输出 | ③ AIGC 换过主题 | AIGC 根据提示词生成四面正交立面图（前 / 后 / 左 / 右），保持角色一致性——四立面主题、风格、品牌形象统一 |

**要点：**

1. AIGC 输出四面正交图的核心难点是角色一致性，需统一提示词模板 + 种子控制 + 参考图一致性技术保障。
2. 效果展示与墙面素材使用同一套内容。
3. 「自动生成可直接印刷文件」需在尺寸、分辨率、接缝、制作验证跑通后，再作为正式承诺。

## 3.6 获取报价 P0

**定义：** 客户选完方案后提交报价申请（可从清单页「申请报价」按钮发起），形成带唯一方案编号的项目，由后台管理人员接收、跟进并记录结果。

**后续端归属确认：** 项目由管理后台分配管理人员处理；已登录的提交人可在客户端查看本人项目列表与详情，不能在客户端跟进或处理项目。

一期通过人工报价完成验证，不必等待自动报价与自动下单。

| 项 | 规格 |
|---|---|
| 客户提交信息 | 展会名称、城市、日期、需求范围、预算（材料购买预算）等必要信息，并标注「申请报价」意向 |
| 形成对象 | 带唯一方案编号的项目记录 |
| 承接方式 | 由管理后台分配管理人员接收、跟进、记录结果（客户端仅提交人本人只读查看项目状态，API-024 客户端跟进已取消） |
| 在线客服 | 点「询价」进入在线实时客服对话，采用成熟第三方网页客服 SDK（优先推荐 Zoho SalesIQ / LiveHelperChat 或网易七鱼海外版，详见《LiveHelperChat、Zoho SalesIQ、网易七鱼海外版三方对比》）；一期演示版为本地模拟，正式版接入第三方客服 SDK |
| 一期实现 | 人工报价（含报价单导出 / 联系跟进），不做自动报价、自动下单 |

## 3.7 账户登录与订阅 P0

**定义：** 平台统一账户体系，支撑「AI 换主题（图生图）」的登录鉴权与积分扣费。

图生图产生费用，需在付费动作前完成登录与额度校验（登录墙）。

| 项 | 规格 |
|---|---|
| 登录方式 | 不自建本地密码库与注册表单，注册跳转至灵通官网完成；登录复用灵通已有的统一 SSO 账户体系（API-026 / API-028 / API-090），本地维护 users/admins 同步表 |
| 登录时机 | 免费浏览 / 匹配 / 看效果图免登录；点「AI 换主题」（图生图付费动作）时触发登录（登录墙），登录成功才进入生成流程 |
| 双入口鉴权 | ① 官网网页端：走到登录墙要求登录；② SU 插件端：插件内默认已登录，点按钮打开网页时 token 自动带入（静默登录，无需重复输入） |
| 统一账户 | 网页端与 SU 端共用同一账户与额度，扣费互通（同一后端鉴权 + 订阅接口） |
| 积分余额 | AI 换主题页右上角显示用户头像 + 积分余额；生成时校验并扣除对应积分 |
| 订阅方案 | 后置：一期先做账户登录与鉴权（演示账户），订阅套餐 / 定价后续单独设计 |

# 四、技术路线与架构

## 4.1 整体架构

> 此为 AI 构想，具体由开发者自行决定。

### ① 客户端（参展商端）

- **技术栈**：Vue 3.5 + Vite 6 + Tailwind CSS 3
- 参数面板、方案展示、品牌调整、清单/图纸/素材预览下载、报价申请；兼容电脑 / 手机。

### ② 管理后台（伙伴与管理端）

- **技术栈**：Vben Admin 5 + Ant Design Vue 4（Turborepo，通用工具优先使用 `@vben/utils`）
- 方案库与打标管理、四类独立资产路由（/assets/*）、计量规则、生成模型与任务运营、项目跟进与人工报价。

### ③ 服务端

- **技术栈**：Fastify 5 + BullMQ 6 + Node 24 (TypeScript ESM) + PostgreSQL 17 + Redis 7.4 + Silo S3（双端点）
- 业务模块（admin / client / su / tasks）、事务性 Outbox 分发器、Presigned URL 对象存储。

### ④ AI 对接

- LLM（通义千问 / banana / Nano Banana Pro）解析自然语言需求
- 图像 API（通义万相 `wanx-x-painting` / banana）换主题生图
### 前端页面结构（四页联动，已实测）

`方案匹配平台（选方案 / 看详情） → 登录（登录墙，AI 换主题前） → AI 换主题（图生图，含积分余额） → 申请报价（询价 + 在线客服）`

各页通过 URL 参数（方案编号 `?code` / `?open`）贯通，同窗口跳转、浏览器前进后退可用。

## 4.2 智能选方案技术路径（迭代）

| 阶段 | 方案 | 状态 |
|---|---|---|
| 1.0（当前） | 规则解析 + 关键词映射 + 方案库过滤（可直接采用 / 相似参考两级判定） | 已跑通试点方案测试，演示稳定 |
| 1.5 | 对接 LLM（通义千问 qwen-plus / banana）解析自然语言 | 一期内完成 |
| 2.0 | 向量召回 + LLM 排序 | 二期，方案库扩到数百套后启用 |

## 4.3 品牌 / 主题调整技术路径

| 环节 | 方案 |
|---|---|
| 蒙版制作 | 首批 PS 手工框出（精确）；后续自动化（材质通道 / Enscape） |
| 蒙版色 | 统一品红 `#FF00FF`，避开绿植 / 灵通绿 / 灵通红 |
| API 选型 | 通义万相 `wanx-x-painting` + `mask_color=[[255,0,255]]` / banana |
| 提示词模板 | 行业 × 风格组合预置库，支持品牌关键词注入 |

## 4.4 技术验证项

要求：技术团队将「需求理解、方案检索、图像处理、清单及规则管理」分开说明，明确各部分的输入、输出和责任，便于后续更换模型。

| 验证项 | 内容 |
|---|---|
| 模型名称 | LLM / 图像模型具体型号、版本 |
| 商用可用性 | 是否可商用、授权范围 |
| 付费方式 | 按量 / 包月、单价、并发限制 |
| 蒙版要求 | 蒙版格式、颜色、精度对换肤效果的影响 |
| 实际成本 | 单张 / 单次调用的真实成本 |
| 数据处理条件 | 数据存储、隐私、合规要求 |
| 双模型备用 | 通义万相 / banana 需用同一批样本验证，不能只写两个供应商名称 |

## 4.5 资产归属

- 代码、账号、数据资产的公司归属应明确（不依赖个人账号）。
- API 账号、模型调用权限、方案库数据统一归公司所有。

# 五、方案库建设要求

会议定性（核心基础）：方案库持续扩充完整方案库而非配件库，是支撑 AI 筛选效果的关键。

当前约 85 套，长期目标数百甚至上千套，但一期不设激进数量指标。

## 5.1 四层组织

不建议把大量仅行业、颜色或品牌不同的方案全部作为独立结构维护。

按四层组织，一期客户仍选择完整方案，后台保留关联即可，不必现在就实现自由拼装。

| 层次 | 主要内容 |
|---|---|
| 结构母版 | 已审核的尺寸、开口、模型、材料清单和配套图纸 |
| 功能变体 | 储藏间、展示柜、灯箱等经过审核的配置变化 |
| 视觉主题 | 科技、医疗、汽车等风格和画面素材 |
| 品牌资料 | 客户 LOGO、品牌色、产品图片和文字 |

### 方案编号规则

所有方案（含变体）均有按特定规则制定的唯一编号：

- 结构或功能变化（影响清单和图纸）→ 作为独立方案单独审核（独立唯一编号）。
- 纯视觉变化 → 尽量复用原有结构。

这样既能提供丰富展示效果，又控制数据维护成本。

100—200 个母版可作为后续规划参考，不马上变成一期数量指标。

## 5.2 方案来源优先级

1. 已成交、实际实施过且资料较完整的历史方案（首选）
2. 基于现有产品体系形成的标准组合
3. AI 辅助产生的新创意（补充）

历史方案上线前需重新确认产品型号、配件、适用条件和素材授权，不能认为「过去做过」就能直接上线。

「AI 批量生成—人工筛选—SU 转化」可保留，但应统计从创意到完整资产包发布的全部人工工时。

重点看每套合格方案用了多少时间、返工多少次，而不是一天生成了多少张图。

## 5.3 资产目录结构（每套方案一个文件夹）

```text
{方案编码}.skp
{方案编码}@简化清单.xlsx
效果图/
蒙版图/
报馆图素材/
素材图/
```

说明：

- `{方案编码}.skp` — SketchUp 模型源文件
- `{方案编码}@简化清单.xlsx` — 客户可用清单（自动从源 xlsm 提取，对应已核对清单）
- `效果图/` — 3 张高分辨率效果图（16:9 横图）
- `蒙版图/` — 3 张品红蒙版图（与效果图同分辨率，用于图生图）
- `报馆图素材/` — 报馆图素材（三视图，施工 / 报馆用）
- `素材图/` — 平面素材（画面素材，名称与清单画面名称一一对应）

**资产存储方式：**

- 方案与资产为一对多，每个资产独立记录并归属一套方案。允许先创建或导入无资产的方案草稿，随后单独上传并关联；资产齐全和核验通过是整体审核发布条件，不是创建或导入前置条件。
- 管理后台将效果图、蒙版图、报馆图素材、素材图拆为独立管理路由，方案详情保留统一汇总及跳转。数据模型、页面和报价边界见[方案资产管理详细设计](一期功能拆分/方案资产管理详细设计.md)。

- 所有方案资产统一存储于本地部署的 Silo 对象存储，使用 `booth-assets` Bucket，以 `schemes/{方案编码}/` 为对象前缀，保持上述逻辑目录结构。例如：`schemes/LT-001/效果图/01.jpg`。
- “每套方案一个文件夹”指逻辑目录，对应对象 Key 前缀；文件通过 S3 接口上传与读取，不直接写入 Silo 底层数据目录。方案编码作为存储前缀，创建后应保持稳定。
- Silo 保存文件内容，数据库记录方案与资产的关联、资产类型、对象 Key、原始文件名、排序及图片尺寸等元数据；不保存临时签名 URL。预览与下载由后端鉴权后提供临时访问链接。
- 效果图与蒙版图使用相同编号配对（如 `效果图/01.jpg` 与 `蒙版图/01.png`），入库时校验各 3 张、配对图片同分辨率、效果图为 16:9，并核对素材图名称与清单画面名称一一对应。
- 本机开发可使用本地访问地址；局域网或对外部署时，临时链接必须使用访问方可达的地址。调用第三方图生图服务时，由 Worker 读取 Silo 文件后上传；若服务仅接受图片 URL，则提供该服务可达的临时访问链接。
- Silo 数据需持久化到磁盘，并对资产文件及其关联数据库进行备份。

# 六、人机协同流程

确立「AI 批量开方、人工筛选把关」的协同机制，把设计师从重复工作中解放。

1. **方案收集：** 优先整理已成交历史方案，AI 辅助产生新创意。
2. **设计师快速筛选：** 人工审核，过滤质量不达标方案。
3. **SU 临摹转化：** 将 AI 灵感临摹为可施工的 SketchUp 模型。
4. **清单 / 图纸核对：** 模型与清单逐项核对，连接件、配套项由技术人员确认。
5. **审核发布：** 业务负责人签字后挂到平台（带唯一方案编号）。

**角色定位：**

- AI = 创意灵感生成器 + 重复劳动替代
- 人 = 方案筛选 + 结构转化 + 清单核对 + 业务把关

统计每套合格方案的全部人工工时与返工次数，作为产能与成本评估依据。

# 十一、二期内容规划

二期从「整方案匹配」升级到「组件化 + AI 自由修改」，此处单列规划，指导一期架构预留扩展性。

## 11.1 固定规格功能组件

制作标准尺寸的功能组件（储藏间、展示柜、灯箱墙等），每个组件含完整清单 + 连接规则，为二期 AI 自由修改提供可组合的组件单元。

## 11.2 配件配置强规则（核心）

**定义：** 用户通过 AI 修改组件后，系统需通过强规则自动明确清单配件，避免人工干预误差。

例如：直角必须配顶板加固件。

- **规则来源：** 需在「方案成本」与「配件数量」之间做权衡，具体规则待商讨确定后固化进清单生成逻辑。
- **落地方式：** AI 修改后自动触发规则校验，配件自动补配（而非人工判断），保证最终清单准确。
- **衔接一期：** 一期清单「三种计算规则（个数 / 长度 / 面积）」在二期扩展为「组件连接规则」。

## 11.3 AI 自由修改

用户通过 AI 对原方案做一定自由度的修改、替换、调整位置等操作，同时保持最终清单准确（核心难点）。

## 11.4 方案自动调整

考虑未来方案可自动调整，提升客户体验与订单转化率。

一期架构预留：

- 方案库数据结构需从「整方案」预留向「四层组织（结构母版 / 功能变体 / 视觉主题 / 品牌资料）」演进。
- 清单生成逻辑需支持「组件级」拆解，为二期 AI 自由修改后的清单准确打基础。
