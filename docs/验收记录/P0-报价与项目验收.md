- 标准方案须发布、整体审核有效、清单已核验且六类资料齐全；不可用方案不受理新申请。

- 公共申请由当前最早同步且有效的 `ROLE_ADMIN` 管理员默认承接；管理员全部不可用时事务回滚并返回 503。后台可改派有资格的管理员。
- 支持 CNY/USD/EUR/GBP/HKD（2 位）、JPY/KRW（0 位）、KWD（3 位），预算为正十进制字符串。币种之间不换汇。
- 未选主题时固定标准素材；选主题时冻结本人当前选定结果，主题平面素材明确为待补充。
- 回执为受理结果，保存/下载报价不代表已发送。客服属于独立 P2，通知渠道待接入；项目事件与通知待投递记录原子入库。

## P0-1 标准方案报价申请

已实现入口：客户端 `/schemes/:code/quote`，主题结果页选定效果后进入；API `GET /api/v1/client/schemes/:code/quote-context` 与 `POST /api/v1/client/quote-requests`。新增数据库迁移 `035_projects.sql`。

### 当前接口口径

- 报价上下文公开返回方案/清单/图纸/标准素材修订与资料状态，不返回文件位置或联系人。
- 创建请求沿用详细设计字段，额外支持可选 `schemeRevision`。暂未实现的四面任务不接受 `artworkJobId`，避免将占位任务冒充可交付资料。
- `requirementContext` 接受原文和确认条件，服务端用既有匹配规则重新计算并固定参考差异/待确认项，不信任浏览器的适用性结论。
- 资料锁沿用“方案 → 清单 → 主题任务”；方案采用 `FOR NO KEY UPDATE` 阻止并发修改，同时允许主题文件入库所需的外键 `KEY SHARE`，避免生成入库与报价形成反向锁依赖。项目事务不执行文件复制或第三方调用。
- 首次成功 `201`，同键回放 `200`，均沿用 `{code:0,data:回执}`。每用户每分钟最多 10 次提交；429 保留原键重试。
- 400 为输入不合格，401/403 为身份无效，409 为幂等/修订/方案/主题冲突，503 为暂无有效承接管理员。沿用标准错误响应，不返回凭据。
- 前端受理结果未知时保留原请求，允许在后续方案下架/资料读取失败情况下继续确认原回执；只有明确业务拒绝后才允许改写表单及使用新键。

### 验收范围

1. 详情与清单入口打开完整报价表单，主题结果页可带入选定效果；打开表单不创建项目。
2. 登录提交，展会日期、需求范围、材料预算、企业/个人和国际联系方式在服务端校验，未知字段拒绝。
3. 创建项目、申请快照、资料快照、承接事件与通知记录在同一事务完成。
4. 同人同键同内容并发重试只创建一次；同键异内容冲突，不同人互不占用幂等键。
5. 显式旧修订、不可用方案和错配/已改选主题拒绝；历史快照保持不变，同键重放不重新固定资料。
6. 前端失败保留填写内容；结果未知时冻结原请求并使用同键重试；登录后安全回到原表单。
7. 成功回执在当前浏览器标签页保留，刷新或返回同一申请入口继续显示原回执；另一份申请需明确选择重新填写。

### 实施与验收方案

- 报价申请与人工需求统一进入 `projects`；人工需求允许无方案，标准方案由后台凭客户确认说明补关联一次。

### 必测金标准

| 输入 | 预期 |
|---|---|
| 两条 `3 × 0.335`，CNY | 每行 `1.01`，合计 `2.02` |
| 单价 `null` | 行金额和总额为 null，草稿不完整，正式导出拒绝 |
| 单价 `0` | 合法零价，可参与完整报价 |
| `1 × 0.5`，JPY | HALF_UP 后 `1`，不强制两位小数 |
| `1 × 0.0005`，KWD | HALF_UP 后 `0.001` |
| 陈旧项目修订或报价修订 | 409，历史记录和当前报价不变 |
| 保存/导出后未新增发送跟进 | 项目状态不自动变为已报价 |
| 已发送旧修订，再保存新草稿 | 原发送依据仍指向原修订 |
| 客户文本以 `= + - @` 开头 | XLSX 保持文本，不能生成公式单元格 |
| 成交/未成交/关闭后编辑 | 拒绝，明确重开且填写原因后才允许 |

## 业务操作路径

1. 客户在方案详情/清单点击“申请报价”，或在主题任务选定结果后使用该效果申请；特殊需求从智选转入完整人工申请。
2. 登录并填写真实展会、日期、范围、材料预算及联系人，提交后以项目号/申请号确认受理；结果未知使用原请求重试。
3. 管理人员进入后台“项目承接”，打开项目工作区，核对申请及固定资料；人工需求尚未关联方案时凭客户确认依据关联一次。
4. 管理人员改派或追加跟进；在报价区域从项目清单快照复制材料行，补单价及运输/搭建等行，保存不可变修订。
5. 明确选择当前或历史完整修订导出 XLSX。真实发送后追加跟进，记录该修订、发送时间和渠道，才进入已报价状态。
6. 成交、未成交、关闭填写结果/原因；终态继续处理先明确原因重开。客户在“我的项目”仅看到公开进展和管理员明确发布的结果。
