# 业务测试数据清理手册

用于正式导入客户数据（方案 Excel、方案图片资源、物料清单 Excel）之前，清空数据库与 S3 中的业务测试数据，同时保留系统配置。

> 首次执行：2026-10-12，本地 dev 栈，schema 版本 `080_asset_upload_requests`。
> 后续新增迁移可能引入新表，执行前务必按「1. 执行前检查」重新核对表清单。

## 为什么不能只 `DELETE FROM schemes`

`schemes` 删除时会级联到 `scheme_assets → asset_versions`，但 `asset_versions` 被下游以 **RESTRICT / NO ACTION** 引用：

```
asset_versions ← project_asset_versions   (RESTRICT)
asset_versions ← theme_job_results        (NO ACTION)
asset_versions ← artwork_job_results      (RESTRICT)
asset_versions ← bom_verifications        (RESTRICT)
theme_job_results ← artwork_jobs          (RESTRICT)
artwork_jobs / theme_jobs ← credit_transactions、credit_reservations
```

只要客户端用测试方案生成过项目、主题图或画面图，单删方案就会报外键错误，所以必须连同下游一起清空。

## 字典项为什么可以清、清了之后会怎样

方案导入提交时会按写入的方案自动补齐 8 个字典的条目，清掉后按客户 Excel 重新生成：

- 开口面数、方案尺寸：按方案的开口面数与长宽高生成（`modules/dictionaries/sizes.ts`）。
- 产品体系、风格、适用行业、预算档位、功能分区、关键特征：先按名称、条目值或别名匹配已有条目；匹配不上时预览会标出“将新建”，确认导入时以该名称新建条目（`modules/schemes/imports/dictionary-items.ts`）。名称命中多个候选或只命中已停用条目时，该行仍报错。

清空的代价：

- 迁移预置条目上的英文、日文翻译和别名（迁移 `063`）会丢失，新建的条目只有中文名称。客户端切换到其他语言时这些选项显示中文，需要在字典管理里补翻译。
- 新建条目的条目值等于中文名称，不再是 `modern`、`fs62_fabric` 这类英文编码。

不清的字典：

- 计量类型 `measurementKind`：管理后台物料清单页面用它显示和选择计量类型，物料清单导入不会写入它。

清空前确认 `prompt_templates.style_id` / `industry_id` 都为空（外键引用风格和行业条目，有引用时 DELETE 会报错）：

```sql
SELECT count(*) FROM prompt_templates WHERE style_id IS NOT NULL OR industry_id IS NOT NULL;  -- 期望 0
```

## 其他注意事项



- `scheme_assets` 不只存放方案资产：`source = 'scheme'` 是方案自身资产，`theme_generation` / `artwork_generation` 是用户生成的私有图片。
- **S3 对象不会随数据库删除**，必须单独清理，否则会留下孤儿文件。

## 1. 执行前检查

以下命令都在仓库根目录执行。PowerShell 和 Git Bash 均可使用（Git Bash 下先 `export MSYS_NO_PATHCONV=1`，避免容器内路径被改写）。

下文用 `<C>` 代指 `docker compose --env-file .env -f infra/compose.dev.yaml`，执行时请替换为完整命令。

### 1.1 列出所有非空表的精确行数

> `pg_stat_user_tables.n_live_tup` 是统计估算值，不准，必须用 `count(*)`。

```sql
DO $$
DECLARE r record; n bigint;
BEGIN
  FOR r IN SELECT tablename FROM pg_tables WHERE schemaname = 'public' ORDER BY tablename LOOP
    EXECUTE format('SELECT count(*) FROM %I', r.tablename) INTO n;
    IF n > 0 THEN RAISE NOTICE '% = %', rpad(r.tablename, 40), n; END IF;
  END LOOP;
END $$;
```

对照第 0 节，确认没有出现不在任何清单里的**新表**；如有，先判断它属于清空还是保留。

### 1.2 检查外键（确认清单完整）

```sql
SELECT c.confrelid::regclass AS parent, c.conrelid::regclass AS child,
       CASE c.confdeltype WHEN 'c' THEN 'CASCADE' WHEN 'n' THEN 'SET NULL'
            WHEN 'r' THEN 'RESTRICT' WHEN 'a' THEN 'NO ACTION' END AS on_delete
FROM pg_constraint c
WHERE c.contype = 'f'
ORDER BY 1, 2;
```

### 1.3 确认队列空闲

```powershell
<C> exec -T redis sh -c 'REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli --scan --pattern "bull:*:wait*"'
<C> exec -T redis sh -c 'REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli --scan --pattern "bull:*:active*"'
```

没有输出即表示无等待或执行中的任务。

### 2.2 S3 文件

将下面的脚本保存为本地文件 `s3backup.mjs`：

```js
import { S3Client, ListObjectsV2Command, GetObjectCommand } from '@aws-sdk/client-s3';
import { mkdir, writeFile } from 'node:fs/promises';
import { dirname, join } from 'node:path';

const s3 = new S3Client({
  endpoint: process.env.S3_ENDPOINT,
  region: process.env.S3_REGION,
  forcePathStyle: true,
  credentials: { accessKeyId: process.env.S3_ACCESS_KEY, secretAccessKey: process.env.S3_SECRET_KEY },
});
const Bucket = process.env.S3_BUCKET;
let token;
let n = 0;
do {
  const r = await s3.send(new ListObjectsV2Command({ Bucket, ContinuationToken: token }));
  for (const o of r.Contents ?? []) {
    const res = await s3.send(new GetObjectCommand({ Bucket, Key: o.Key }));
    const out = join('/tmp/s3backup', o.Key);
    await mkdir(dirname(out), { recursive: true });
    await writeFile(out, await res.Body.transformToByteArray());
    n++;
  }
  token = r.IsTruncated ? r.NextContinuationToken : undefined;
} while (token);
console.log('downloaded', n);
```

```powershell
<C> cp ./s3backup.mjs api:/app/s3backup.mjs
<C> exec -T api node s3backup.mjs
<C> cp api:/tmp/s3backup D:/baolf/lingtong/booth-backups/s3-before-reset-YYYYMMDD
```

核对本地文件数与输出的 `downloaded N` 一致。

## 4. 清空数据库

保存为 `reset.sql`。**故意不加 `CASCADE`**：如果有保留的表引用了被清空的表，事务会报错并整体回滚，不会误删配置。

```sql
\set ON_ERROR_STOP on
BEGIN;
TRUNCATE
  -- 方案与资产、物料清单
  schemes, scheme_imports, scheme_assets, asset_versions, asset_upload_requests,
  scheme_boms, scheme_bom_items, bom_imports, bom_verifications, bom_change_logs, scheme_reviews,
  -- 项目
  projects, project_asset_versions, project_events, project_notification_outbox, project_notification_reads,
  project_operations, project_quotation_revisions, project_receipt_emails,
  -- 主题 / 画面生成
  theme_jobs, theme_job_results, theme_job_outbox, theme_job_generated_urls, theme_job_provider_attempts,
  artwork_jobs, artwork_job_results, artwork_job_outbox, artwork_job_directions,
  -- 积分、签到
  credit_transactions, credit_reservations, sign_in_records,
  -- 选型记录
  selection_attempts, selection_parses, selection_searches,
  -- 客服会话
  cs_visitors, cs_conversations, cs_conversation_contexts, cs_messages, cs_message_translations, cs_email_outbox,
  -- 审计与后台任务
  admin_audit_logs, foundation_outbox, foundation_tasks;
-- 导入时自动生成的字典项（字典本身保留，计量类型不动）
DELETE FROM dictionary_items
WHERE dictionary_id IN (
  SELECT id FROM dictionaries
  WHERE code IN ('booth_size', 'opening_count', 'product_system', 'style', 'industry', 'budget_tier', 'functional_zone', 'key_feature')
);
COMMIT;
```

```powershell
<C> cp ./reset.sql postgres:/tmp/reset.sql
<C> exec -T postgres psql -U booth -d booth -f /tmp/reset.sql
<C> exec -T postgres rm /tmp/reset.sql
```

完成后重新执行 1.1，应只剩第 0 节「保留」中的表，且行数与清理前一致。

## 5. 清空 S3

保存为 `s3purge.mjs`：

```js
import { S3Client, ListObjectsV2Command, DeleteObjectsCommand } from '@aws-sdk/client-s3';

const s3 = new S3Client({
  endpoint: process.env.S3_ENDPOINT,
  region: process.env.S3_REGION,
  forcePathStyle: true,
  credentials: { accessKeyId: process.env.S3_ACCESS_KEY, secretAccessKey: process.env.S3_SECRET_KEY },
});
const Bucket = process.env.S3_BUCKET;
let deleted = 0;
for (;;) {
  const r = await s3.send(new ListObjectsV2Command({ Bucket }));
  const keys = (r.Contents ?? []).map((o) => ({ Key: o.Key }));
  if (!keys.length) break;
  const d = await s3.send(new DeleteObjectsCommand({ Bucket, Delete: { Objects: keys } }));
  if (d.Errors?.length) throw new Error(JSON.stringify(d.Errors));
  deleted += keys.length;
}
console.log('deleted', deleted);
```

S3 脚本依赖 api 容器里的 SDK 与环境变量，所以先只启动 api：

```powershell
<C> start api
<C> cp ./s3purge.mjs api:/app/s3purge.mjs
<C> exec -T api node s3purge.mjs
<C> exec -T api sh -c 'rm -rf /app/s3backup.mjs /app/s3purge.mjs /tmp/s3backup'
```

> 这里清空的是**整个桶**。如果以后桶里有需要保留的对象（例如固定素材），改为按前缀 `schemes/`、`theme-results/`、`artwork-results/` 过滤（`ListObjectsV2Command` 传 `Prefix`）。

### 仅恢复字典项（含翻译与别名）

`dictionary_items-before-clear-YYYYMMDD.sql` 是 `pg_dump --data-only -t dictionary_items` 的输出。只能在还没有导入方案、对应字典项为空时恢复，否则同值条目会冲突：

```powershell
<C> cp D:/baolf/lingtong/booth-backups/dictionary_items-before-clear-YYYYMMDD.sql postgres:/tmp/items.sql
<C> exec -T postgres psql -U booth -d booth -c "DELETE FROM dictionary_items"
<C> exec -T postgres psql -U booth -d booth -v ON_ERROR_STOP=1 -f /tmp/items.sql
<C> exec -T postgres rm /tmp/items.sql
```
